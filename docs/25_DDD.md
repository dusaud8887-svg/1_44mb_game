# 25 — 도파민 드리븐 디벨롭먼트 운영 정본

이 문서에서 DDD는 신경전달물질을 직접 최적화한다는 뜻이 아니다. 에코/144의 DDD는 **기대 → 의미 있는 선택 → 즉시 읽히는 결과 → 학습 → 다음 선택**을 플레이어·개발·시장에 같은 구조로 적용하는 증거 중심 개발법이다. 기능 수나 체류시간이 아니라, 플레이어가 원인과 결과를 이해하고 다시 다른 선택을 하고 싶어지는지를 최적화한다. 이론 선택과 MDA 인과 지도는 [24_DESIGN_METHOD.md](24_DESIGN_METHOD.md)가 정본이다.

과학적 경계: 도파민은 단순한 쾌락 계량기가 아니라 예상과 실제 보상의 차이를 학습하는 신호에 가깝다([Schultz, 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC5549862/)). 장기 동기는 무작위 보상보다 유능감·자율성·관계성으로 설명하는 편이 안전하다([Przybylski·Rigby·Ryan, 2010](https://doi.org/10.1037/a0019440)). 따라서 본작은 유료 확률 보상·결석 처벌·허위 희소성을 사용하지 않는다.

## 1. 제품 가설

> 5장의 방송 큐에서 지금의 생존과 다음 방송의 힘을 편성하고, 내가 쌓은 약점과 습관이 마지막 60초에 화면을 지배한다.

플레이어가 기억해야 할 감정 곡선:

```text
호기심        첫 손패가 무슨 방송을 만들까
통제          송신/수신과 PROGRAM 순서를 내가 정한다
학습          결과를 보고 다음 구절의 배분을 바꾼다
회수          산 카드가 셔플 뒤 실제로 돌아온다
관계          노아가 내가 즐겨 쓴 기술을 학습한다
반전          부담이던 ARCHIVE가 OPEN CHANNEL의 힘이 된다
표현          64칸의 색이 내 덱·관계·엔딩을 말한다
```

## 2. 세 개의 증거 루프

| 층 | 루프 | 이 프로젝트의 증거 |
|---|---|---|
| 플레이어 | 예상 → 편성 → 송출 → 결과 → 재편성 | 의도별 PROGRAM·TX/RX 변경, 실패 후 재시도, 두 번째 런 전략 변경 |
| 개발 | 가설 → 최소 수정 → 빌드 → 관찰 → 유지/폐기 | selftest·SIM·Windows 실기·신규 5명 로그 |
| 시장 | 한 장면의 약속 → 노출 → 데모 → 행동 | 캡슐/영상 반응, 데모 실행, 의미 있는 플레이, 위시리스트 |

시장은 개발 뒤의 홍보 단계가 아니다. `노아가 내 기술을 복제`, `무음 ARCHIVE의 반전`, `64칸의 세 색`이 실제 플레이와 캡슐·GIF에서 같은 장면이어야 한다. Steam 위시리스트는 관심과 알림 채널이지 노출을 보장하는 점수가 아니다([Steam 가시성 문서](https://partner.steamgames.com/doc/marketing/visibility)).

## 3. 중첩 플레이 루프

| 시간 | 기대 | 행동 | 보상·학습 |
|---|---|---|---|
| 1~8초 | 준비한 PROGRAM이 어떤 형태로 나갈까 | 이동·Space 발동 | 즉시 형태 변화, 적 제거, 피격 원인 |
| 1구절 | 현재 생존과 구매력 중 무엇을 택할까 | TX/RX·CUE·순서 편성 | BAUD·SYNC·셔플·다음 의도 |
| 1런 | 약점이 마지막에 무엇으로 변할까 | 덱 구성·계약·보관·조기 개방 | 최종 형태·modifier·64색 엔딩 |
| 여러 런 | 다른 관계와 결말을 만들 수 있을까 | 다른 태그·색·TREND 유도 | 새 전략과 해석, 즉시 재접속 |

짧은 루프가 약하면 메타 진행이나 콘텐츠를 추가하지 않는다. 우선순위는 **입력 감각 → 결과 가독성 → 선택 → 조합 → 장기 진행**이다.

## 4. 증거 사다리와 중단 기준

1. **약속**: 5초 화면만 본 사람이 `방송/카드 편성/64` 중 둘 이상을 말한다.
2. **토이**: 60초 안에 EDIT에서 고른 카드만 Space로 나간다고 이해한다.
3. **반복**: 같은 손패라도 다음 의도에 따라 PROGRAM 또는 TX/RX를 바꾼다.
4. **회수**: 산 카드가 셔플 뒤 돌아온다는 사실을 예측한다.
5. **반전**: ARCHIVE 부담과 OPEN CHANNEL 상환을 자기 말로 설명한다.
6. **관계**: 노아가 자기 기술을 복제했다는 사실을 알아챈다.
7. **생산**: 새 콘텐츠 없이 기존 규칙 조합으로 두 번째 전략이 나온다.

1~3이 사람 5명 중 3명에게도 성립하지 않으면 카드·적·서사를 더 만들지 않는다. UI 한 번, 규칙 한 번을 수정해 재검증하고 그래도 실패하면 V2 코어를 기각한다. 상세 기준은 [50_PRODUCTION.md](50_PRODUCTION.md) G1′/G2′가 정본이다.

## 5. 2026-07-17 첫 DDD 패스

직접 플레이에서 첫 루프가 다음처럼 끊겼다.

```text
효과를 모르는 카드 선택
→ 추천과 다른 TX/RX 기본값
→ 이동 안내 없는 8초 전투
→ BAUD 0~1
→ 살 수 없는 상점
```

기능을 추가하지 않고 같은 루프를 다음처럼 고쳤다.

```text
MULTI 포커스 + 카드 효과 한 줄
→ 송신1/수신1 추천을 실제 기본값으로 적용
→ WASD·Space를 전투 화면에서 안내
→ 첫 응답 BAUD +1
→ 구매 가능한 CHAT에 포커스 + 실제 효과 표시
```

이는 첫 런만 정답을 강제하는 자동 플레이가 아니다. 기본값·포커스만 제공하며 플레이어는 즉시 모든 배정을 바꿀 수 있다. 첫 응답 보너스는 첫 8초 뒤 상점이 공회전하지 않게 하는 튜토리얼 보조금이며, 이후 경제에는 적용하지 않는다.

## 6. 반복 절차

각 패스는 한 가지 실패만 다룬다.

두 번째 패스(2026-07-17)는 **행동→결과 판독**만 수정했다. PROGRAM 발동 이름이 없고 이펙트가 0.4초뿐이던 문제는 하단 입력 안내를 1초간 `송출 / 카드명`으로 교체해 해결했다. 구매 카드 귀환 강조는 1.5초에서 3초로 늘렸다. 화력·적·카드 수는 바꾸지 않았다.

세 번째 패스(2026-07-17)는 **노아의 학습→복제 관계 판독**만 수정했다. 카드별 의미 반전은 이미 작동했지만 공통 복제 경로가 소유자와 카드명을 표시하지 않아 일반 적탄처럼 읽혔다. 복제 순간 1초간 `노아 복제 / 카드명`, 자홍 전장 테두리, 에코 모티프와 정확히 겹치는 짧은 화음을 같은 이벤트에 묶었다. 복제 규칙·주기·피해량은 바꾸지 않았다.

네 번째 패스(2026-07-17)는 **첫 선택→첫 수동 송출**만 수정했다. 추천된 MULTI는 CUE를 늘리지만 송출 큐에는 들어가지 않아, 확인 뒤 바로 Tab을 누른 신규 플레이어의 첫 Space가 무반응이었다. MULTI 확인 직후 FIREWALL로 포커스를 넘기고 두 번째 확인과 Space를 안내한다. 자동 편성이나 전투 수치는 추가하지 않았다.

다섯 번째 패스(2026-07-17)는 **적 의도→공간 변화**만 수정했다. 정본의 COMMENT WALL은 이동로를 막는 채팅창 지형이지만 구현은 정지형 POP.AD를 가장자리에 흩어 일반 원거리 적과 거의 같았다. 같은 적을 전장 내부의 가로/세로 한 줄로 배치해 우회·관통·방벽 방향 선택을 만들었다. 맵·적·수치·충돌 시스템은 추가하지 않았다.

여섯 번째 패스(2026-07-17)는 **덱 투자→최종 합성 기대**만 수정했다. OPEN CHANNEL의 형태·modifier·강도는 진입 뒤에만 보여, 8~12구절의 조기 개방이 결과를 모르는 버튼이었다. 기존 컴파일 계산을 BREAK 진입 때 재사용해 `지금 개방: 형태 / modifier / 강도`를 표시했다. 카드·진화표·보상·전투 수치는 추가하지 않았다.

일곱 번째 패스(2026-07-17)는 **실패→다음 선택**만 수정했다. 체력 0과 OPEN CHANNEL 시간 종료는 코드에서 구분되지만 결과 화면은 체력 0을 `미송출 편성 남음`으로 잘못 설명했다. 원인을 각각 `체력 0 / 송출 중단`, `64 미완성 / 채널 종료`로 표시하고, 다음에 바꿀 축과 도달 구절을 남겼다. 난도·보상·메타 진행은 변경하지 않았다.

```text
관찰  → 처음 막힌 지점과 실제 행동 기록
가설  → 원인을 한 문장으로 작성
수정  → 새 시스템보다 정보·기본값·수치 순서로 최소 변경
검증  → selftest + SIM + 같은 경로 Windows 실기
판정  → 유지 / 되돌림 / 다음 한 축 수정
기록  → 90_STATUS·91_COMPLETENESS_AUDIT·CHANGELOG 동기화
```

자동 SIM은 경제·덱·링의 도달 가능성을 거르고, 재미 PASS를 선언하지 않는다. 사람 테스트 전에는 CLEAN_SIGNAL의 생존 가치, Space+이동의 편안함, 노아 복제 자각, 3색 의미를 수치로 확정하지 않는다.

## 7. 측정 우선순위

### 첫 60초

- 첫 PROGRAM 편성까지 시간
- TX/RX 전환 여부와 설명 가능 여부
- 첫 ON AIR에서 이동·Space 사용 여부
- 첫 BREAK에서 구매 또는 의도적 넘김 여부
- 도움 없이 다음 구절 진입 여부

### 한 런

- 의도에 따라 편성을 바꾼 구절 비율
- 구매 카드 첫 귀환 인지
- ARCHIVE 0장 런 비율
- OPEN CHANNEL 도달·성공 시간
- 가장 기억나는 장면과 이유

### 다음 런

- 같은 시드/새 시드 재접속
- 다른 카드·색·계약을 고른 이유
- 실패 원인을 자기 행동과 연결하는지

허영 지표인 총 입력 수, 화면 이펙트 수, 평균 체류시간만으로 변경을 정당화하지 않는다.

## 8. 변경 우선순위

플레이테스트 실패 시 다음 순서로 고친다.

1. 정보 위치와 표현
2. 안전한 기본값과 포커스
3. 기존 수치
4. 기존 규칙의 상호작용
5. 마지막으로만 새 콘텐츠·새 버튼

한 패스에서 메커니즘·아트·밸런스를 동시에 크게 바꾸지 않는다. 무엇이 결과를 만들었는지 알 수 없기 때문이다. 아트 수정도 장식량이 아니라 실루엣, 위험/아군 판독, 카드 효과의 형태 차이로 판정한다.

## 9. 윤리선

- 유료 확률 보상, 다중 가상화폐, 허위 한정 판매를 두지 않는다.
- 휴식·미접속·종료에 손실을 부과하지 않는다.
- 재시작은 빠르게 하되 중단을 방해하지 않는다.
- 무작위 결과보다 플레이어 선택과 조합이 결과 분포를 바꾸게 한다.
- 플레이 시간을 늘리는 것보다 실패 원인이 읽히고 다음 시도가 달라지는 것을 우선한다.

DDD의 최종 성공은 “멈출 수 없었다”가 아니라 **“내 선택 때문에 이런 방송이 되었고, 다음에는 다르게 해 보고 싶다”**이다.
