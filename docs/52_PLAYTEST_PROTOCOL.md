# 52 — GV2 사람 플레이테스트 실행서

목표는 재미를 자동 점수로 대체하는 것이 아니라, 서로 다른 신규 테스터 **5명 × 2런**의 행동·발화·DEV 로그를 같은 기준으로 모아 [50_PRODUCTION.md](50_PRODUCTION.md) §4의 go/no-go를 판정하는 것이다.

## 1. 준비와 연구 근거

- `build.bat debug`로 `build/ECHO144_DEBUG.EXE`를 만든다. 테스터마다 별도 폴더에 복사해 로그가 섞이지 않게 한다.
- 첫 런은 도움 없이 관찰한다. 진행을 가르치면 학습성 측정이 사라진다. 막혀도 “지금 무엇이 보이나요?”만 묻는다.
- 플레이 중에는 보이는 것과 생각을 말하게 하되, 핵심 질문은 런 뒤에 묻는다. 동시 발화는 문제 지점을 드러내지만 행동 자체를 바꿀 수 있으므로 두 번째 런과 회고 답변으로 교차 확인한다([동시 발화 기반 게임 사용성 연구](https://eprints.whiterose.ac.uk/id/eprint/106935/)).
- Steam 배포가 필요하면 본편 리뷰·위시리스트와 분리되는 [Steam Playtest](https://partner.steamgames.com/doc/features/playtest)를 사용하고, 어떤 피드백을 어디에 남길지 초대문에 명시한다.

## 2. 한 사람당 절차 (약 30분)

1. 사전 질문 2분: 이 게임을 처음 하는지, 덱빌딩·생존 액션 경험을 `없음/가끔/자주`로 기록한다.
2. 첫 런 10분: 조작표만 제공하고 관찰한다. 첫 PROGRAM 편성, 첫 ON AIR, 첫 구매, 첫 막힘의 시각과 발화를 적는다. 치트키는 쓰지 않는다.
3. 회고 5분: 아래 7문항을 먼저 자유 답변으로 받고 나서 `예/아니오`를 기록한다.
4. 두 번째 런 10분: 새 시드로 다른 전략을 시도하게 한다. 구체적 카드나 정답은 제시하지 않는다.
5. 회수 3분: 게임 폴더의 `playtest_v2.csv`를 `P01.csv`처럼 익명 ID로 바꾸고 관찰표와 함께 보관한다. 이름·연락처는 로그와 분리한다.

런 뒤 7문항은 각각 `예/아니오 + 근거 한 문장`으로 기록한다.

1. 같은 손패라도 적 의도에 따라 PROGRAM 선택을 바꿀 이유가 있었나?
2. 이동하면서 Space로 발동하는 조작이 편했나?
3. 구매 카드가 덱으로 돌아온 순간을 알아차렸고 기뻤나?

6. 음소거에서도 카드 발동과 링 세 색의 차이를 구분했나?
7. 다른 전략이나 엔딩으로 다시 플레이하고 싶은가?

## 4. 로그 요약과 판정

```bat
build.bat report tests\P01.csv tests\P02.csv tests\P03.csv tests\P04.csv tests\P05.csv
```

`cheated=1`인 런은 자동 제외한다. `GV2 data volume: READY`는 표본량만 충족했다는 뜻이며 재미 PASS가 아니다. 최종 판정은 다음처럼 한다.

- **go:** 7문항 중 5개가 3/5 이상 긍정이고, 1번(손패 고민)과 4번(반전)이 모두 통과한다.
- **no-go:** 1번 또는 2번(수동 발동)이 2/5 이하이다.
- **보류:** 로그 누락, 신규 5명 미달, 유도·치트가 섞인 경우. 부족한 세션만 다시 모집한다.

수정은 정보 표현 → 기본 포커스 → 수치 → 기존 규칙 순서로 한 축만 바꾸고 같은 프로토콜로 재검증한다. 자동 추천률, 혼합 TX/RX, 승률은 원인 탐색용이지 단독 합격선이 아니다.
