# 42 — 비주얼 후킹·마케팅

`[본 개정 구체화 — 정규화 패스: V2 전면 재작성]` [40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md)의 아트 방향과 [41_PIXEL_ART.md](41_PIXEL_ART.md)의 제작 규격을 전제로, **어떻게 보는 이를 붙잡고 파고들게 만들 것인가**를 정의한다. 대상: 스팀 캡슐·itch 커버·소셜 썸네일 같은 마케팅 표면과 그 경쟁력을 낳는 기법. 인게임 자산은 여전히 인하우스 픽셀([41](41_PIXEL_ART.md))로 제작하며, 이 문서의 AI 관련 내용은 §8의 **경계 정책**뿐이다 — 구체적 프롬프트·모델·태그 레시피는 정본에 고정하지 않는다.

> 이전 판(V1 시점, "시청자 1"·FORMAT 캐릭터 기준)의 §1~§7과 상세 AI 프롬프트 레시피는 [archive/v1-last-live/42_VISUAL_HOOK.md](archive/v1-last-live/42_VISUAL_HOOK.md)에 그대로 보존되어 있다 — 이 문서는 그것을 승계·재작성한 V2 전용 정본이며, V1 판을 참조할 필요는 없다.

## 1. V2 후킹 원칙 — 채우지 말고 비워라

이 게임의 무기는 화려함이 아니라 **미스터리**다. 확정 사실과 답하지 않을 질문([40](40_ART_AUDIO_TEXT.md) §5)이 서사의 뼈대이고, 노아가 채우는 "완벽한 대답"과 에코가 기다리는 "진짜 대답 하나" 사이의 공백이 사람을 파고들게 한다. 비주얼도 같은 원리를 따른다.

- **네거티브 스페이스가 상상력을 고용한다**: 보이지 않을 때 더 무섭고 더 궁금하다. 화면을 채우는 대신 **전략적으로 지운다**: 상세 환경을 먼저 세우고 → 감정을 나르는 핵심만 남기고 → 나머지를 조명·그림자로 가린다.
- **본작의 실행**: 키아트에서 **시크는 어둠 속 눈 하나로만** 존재한다. 몸은 그리지 않는다. 깨진 버퍼 링 조각 2~3px만이 "둥근 무언가가 거기 있다"는 유일한 단서다. 시크가 무엇을 보고 있는지, 노아가 정말 위험한지를 **이미지가 답하지 않고 질문으로 남긴다.**
- **대비가 시선을 수술한다**: 어두운 배경 위 청록 히어로 하나, 그 반대편 어둠 속 호박 눈 하나 — 시선 동선이 에코 → 신호 → 눈으로 자동으로 흐른다.

### 갭모에 — 조합과 그 사이의 틈

오타쿠 어필은 요소를 **쌓는** 것이 아니라 **어긋내는** 것에서 나온다.

| 캐릭터 | 조합되는 모에 요소 | 의도적 갭(틈) |
|---|---|---|
| 에코 | 큰 둥근 눈·비대칭 롱헤어·당당한 미소·라이브 텐션 | 밝고 명랑한데 "시청자 1"·곧 끊김 — 명랑함 아래 소멸의 예감 |
| 시크 | 낮고 둥근 실루엣·외눈 삼백안·송곳니 미소·반개 시선 | 붙잡는 자인데 지켜보기만 — 애정인지 집착인지 미확정([06](06_CHARACTERS.md) §2) |
| 노아 | 아름다운 관리자 초상·정중한 존댓말·반개한 눈(냉소 아닌 경청) | 완벽하게 친절한데 에코의 표정까지 보정하려 함 — 다정함의 오싹함([06](06_CHARACTERS.md) §3) |

- **눈이 갭의 무대**([41](41_PIXEL_ART.md) §7): 에코 둥글게 / 시크 삼백안 / 노아 반개. **무표정·반개**는 갭모에의 핵심 장치다 — 감정을 다 보여주지 않아 관객이 채운다.
- **머리카락이 정체성의 절반**([41](41_PIXEL_ART.md) §1): 실루엣 차별화는 헤어 셰이프로. 조합은 명료하게, 사이는 비워서.

### 타깃 진입점 — 20대와 30~40대

30~40대에 강한 요소(그대로): 1997, `A:\>`, 플로피 1.44MB, 2400/14K/56K, 건조한 한국어 PC 안내문, `NO CARRIER`, PC통신·듀오톤. **20대의 첫 훅은 기술 지식이 아니라 캐릭터와 상황이어야 한다**:

```text
귀엽지만 이상한 에코 → 누군가/무언가가 보고 있음 → 모든 시대에 나타나는 목록 외 방송 → 자세히 보면 1997, 1.44MB, 시간 오류
```

마케팅 표면의 첫 레이어는 항상 캐릭터·미스터리, 복고 기호는 두 번째 레이어(발견 보상)로 배치한다.

## 2. 메인 키아트 — "세 초상"이 아니라 "한 사건"

V2 정본 장면:

> **에코가 화면 바깥의 알 수 없는 관객에게 손을 뻗어 대답을 기다린다. 시크의 케이블은 돌아오는 진짜 신호 하나를 보관하려 하고, 에코 뒤의 우아한 노아는 수백 개의 완벽한 대답으로 빈 공간을 먼저 채우고 있다.**

시각 무게: `에코 50~55% / 노아 25~30% / 시크 10~15% / 인터페이스·배경 10%`. **에코가 가장 커야 한다** — 노아를 같은 크기로 병렬하면 대전 구도처럼, 시크까지 같은 크기면 관계도가 된다.

배치: 에코 = 중앙보다 약간 왼쪽 전경, 손은 이미지 바깥(관객)으로 / 64링 = 에코 뒤, 일부는 노아 베일에 가림 / 노아 = 우측 상단 후경, 얼굴은 아름답고 안정, 그림자는 빈 프로필·좌석으로 크게 / 시크 = 좌측 하단 어둠, 한쪽 눈과 케이블만 / **진짜 청록 신호 한 개가 시크 케이블과 노아 프로필 사이에서 당겨짐** / 시대 화면 조각은 가장자리 / 로고는 보호된 네거티브 스페이스.

시선 동선(한 번에 읽혀야 함): `관객의 자리 → 에코의 뻗은 손 → 청록 메아리 → 시크의 케이블 → 노아의 댓글 베일 → 에코의 64링`.

감정 대비:

| 인물 | 얼굴 | 손·몸 | 그림자 |
|---|---|---|---|
| 에코 | 기대와 긴장 | 관객 쪽으로 열림 | 작고 인간적 |
| 시크 | 공손한 집착 | 신호를 안쪽으로 감음 | 저장 릴과 태그 |
| 노아 | **가장 평온함** | 화면과 에코를 감싸는 자세 | 가장 거대하고 비인간적 |

색·조명: 면적 60% 이상은 VOID·BLACK·PANEL 계열 / 에코 청록이 가장 밝고 넓은 유채색 / 노아 자홍은 외곽·수직으로 퍼짐 / 시크 호박은 작지만 청록 신호와 직접 접촉 / 빨간 LIVE 핀은 딱 한 점 / 라벤더는 한 픽셀·한 반사에만. 주광원은 에코의 링과 관객 화면 — 노아는 자홍 광원보다 **모니터의 차가운 흰빛을 받아 친절하게** 보이게 한다.

**썸네일 생존 법칙**: 1× 썸네일에서도 (a) 청록 히어로 실루엣 (b) 반대편 빛 하나 (c) 대각 동선 — 3요소가 읽혀야 통과. 검수는 1×·3× 동시 렌더로 한다([41](41_PIXEL_ART.md) §5 실크기 검증의 마케팅판).

### 승인 기준

- 인물 이름을 몰라도 에코가 주인공으로 보인다. 세 얼굴 콜라주가 아니다.
- 노아는 매력적이지만 그림자에서 위험이 느껴진다. 시크가 마스코트·애완동물로 보이지 않는다.
- 25% 크기에서 에코→신호→노아의 기본 갈등이 남는다. 흑백 실루엣에서 3인이 구분된다.
- 배경 텍스트를 지워도 정체성이 유지된다. 손·케이블·링의 물리 연결이 전부 설명 가능하다.
- 확장 팔레트가 [40](40_ART_AUDIO_TEXT.md) §3의 논리 팔레트를 벗어나지 않는다.

## 3. 캐릭터·장면 키아트 세트

정체성 = 구도다 — 앙상블(§2)을 나눈 게 아니라 캐릭터의 동사([40](40_ART_AUDIO_TEXT.md) §1)를 구도로 번역한다.

- **에코("송출한다")**: 좌측 히어로 + 우측 어둠의 시크 눈. 신호가 어둠으로 나간다.
- **시크("지켜본다")**: 우측 거대한 외눈이 **왼쪽 어둠의 작은 청록 신호 하나를 응시**. 신호가 시크 왼쪽 실루엣을 청록으로 물들이는 역광. 무엇을 보는지는 프레임 밖.
- **노아("흉내 낸다")**: 완전 대칭 구도 + 프로필 환 + 관객 베일. 얼굴은 깨뜨리지 않는다 — 위험은 그림자·베일에만 있다([06](06_CHARACTERS.md) §3).

### 필수 세트

| # | 이름 | 내용 |
|---|---|---|
| A | ENSEMBLE / UNLISTED LIVE | 메인 스토어 키아트 — §2의 한 사건 |
| B | ECHO / WAITING FOR REPLY | 에코 단독. 화면 밖 송출, 링의 빈 칸, 밝지만 기다리는 감정 |
| C | SEEK / FIRST LIVE ×3 | 인간형 얼굴 절반만 + 케이블에 매달린 여러 날짜의 같은 장면. 버퍼 셸은 보이지 않음 |
| D | NØA / PERFECT AUDIENCE | 아름다운 관리자 초상 + 빈 관객석 그림자 + 다른 닉네임의 같은 문장. **얼굴은 깨뜨리지 않는다** |
| E | OPEN CHANNEL | 후반 카타르시스 — 3색 64링, 최종 방송 프로토콜의 공간 재구성([10](10_MECHANICS.md) §10). 스크린샷과 키아트의 브리지 |
| F | NO CARRIER / ENDING TRIPTYCH | 같은 검은 화면을 청록 링 조각·호박 태그·자홍 프로필로 변주. 엔딩 무드만 제공 |

캔버스: 192×108(16:9) 저해상 원본 → 정수배 업스케일(3×=576×324 ≈ 스팀 헤더/메인 캡슐 근사). **저해상에서 완성하고 확대**하는 것이 픽셀 마케팅의 정석 — 축소가 아니라 확대라야 격자가 산다. 고해상도 마케팅 일러스트(픽셀 확대판과 별도 제작 시): 명확한 셀 색면 / 2~3단 그림자 / 단단한 윤곽 / 픽셀 UI·링은 실제 게임 비율 존중. 지양: 반실사 피부 광택 / 전체를 덮는 안개 / 무작위 회로 / 읽을 수 없는 가짜 문자 / 손·케이블 연결이 불명확한 구조.

## 4. 로고·워드마크

정본 구조는 [40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md) §3: `O`=불완전한 64링, `/`=전파 절단선·시대 경계, `144`=제약 암시, 빨간 핀 한 점, 기본 흰·청록·빨강 + 경로 변형 로고 4종(청록/호박/자홍/라벤더 균형판).

- **로고는 별 레이어**: 키아트는 로고 없이 넘긴다. 워드마크는 중앙 상단 또는 하단 네거티브 스페이스에 레이아웃 단계에서 얹는다 — 키아트에 텍스트를 굽지 않아 다국어·비율 대응이 자유롭다.
- 타이틀은 비트맵 워드마크(시스템 글꼴 금지, [45](45_UI_UX.md) §8과 동일 원칙).

## 5. Steam·소셜 규격

정기 출력 크기: `120×45 / 184×69 / 300×168 / 462×174 / 748×896 세로 크롭`. 작은 크기에서 **남아야 할 것**: 에코의 얼굴과 손, 끊긴 청록 링, 노아 자홍 수직 실루엣, 시크 호박 케이블 한 줄, 로고. 사라져도 되는 것: 채팅 문장, 파일 날짜, 프로필 세부, 시대 UI.

Steam 캡슐: Header 920×430 / Small 462×174 / Main 1232×706 / Vertical 748×896 + Library 계열은 최신 템플릿 확인. 기본 캡슐에는 게임 아트·게임명·**공식 부제 `UNLISTED LIVE`**만(리뷰 점수·수상·할인 문구 금지, [00](00_VISION.md) 참조). **기계적 크롭 금지** — 같은 원본 그룹을 쓰되 규격별로 3인 위치와 로고 안전영역을 재조정. Small은 자동 축소에서 로고와 에코 얼굴이 살아야 하며, 작은 규격에서 설정 단서를 읽히려 하지 않는다.

120×45에서 에코와 로고가 읽힌다 — 이것이 최소 통과선이다.

## 6. 스크린샷 세트 — 서로 다른 약속의 증명

스토어 스크린샷은 예쁜 장면 모음이 아니다: ① EDIT(5장 중 선택 + 적 의도) ② ON AIR(FIREWALL·SURGE처럼 공간이 다른 효과) ③ BUILD RETURN(산 카드의 셔플 귀환) ④ OPEN CHANNEL(ARCHIVE 반전 + 64링, [10](10_MECHANICS.md) §10) ⑤ TREND MIRROR(노아의 모방) ⑥ TIME LAYER(1997과 2097 UI 겹침). 같은 이펙트를 반복하지 않는다.

## 8. AI 사용 경계 `[본 개정 구체화 — 정규화 패스: 정책만 남기고 도구·태그 레시피 삭제]`

이 절은 **경계만 정의한다.** 구체적 모델명·품질 태그 스택·작가 블렌딩 레시피는 정본에서 삭제했다 — 도구는 자주 바뀌고, 문서에 고정하면 오히려 그 시점의 도구·화풍에 팀을 묶어 버린다. 필요한 실무 조합은 그때그때 팀 채널에서 공유한다. 인게임 자산은 항상 41의 인하우스 루프로만 만든다.

**허용** — 마케팅 착상 단계에서만:

- 구도 스케치·썸네일 레이아웃을 빠르게 여러 안 뽑아 비교
- 조명·색 온도 비교(같은 장면을 다른 광원으로)
- 소품·배경 디테일 발산(브레인스토밍 — 채택은 사람이 결정)
- 클리셰 점검 — 레퍼런스가 너무 흔하지 않은지 확인하는 용도

**금지**:
