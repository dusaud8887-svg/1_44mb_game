# 46 — UX 휴리스틱 평가·정보 설계 감사

게임이 **조작법·룰·플레이 방식·각 카드의 방법·카드 선택 이후의 변화(위상 변화)를 얼마나 잘 전달하는가**를 확립된 UX 법칙으로 평가하고, 정보 전달성·가시성·가독성·시각적 설득력을 높이기 위한 권고를 우선순위로 정리한다. 레이아웃 정본은 [45_UI_UX.md](45_UI_UX.md), 규칙 정본은 [10_MECHANICS.md](10_MECHANICS.md), 시각 방향은 [40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md). 이 문서는 **평가·권고**만 다룬다 — 무엇이 코드에 반영됐는지는 [90_STATUS.md](90_STATUS.md)·[CHANGELOG.md](CHANGELOG.md)가 정본이다.

## 1. 평가 기준 — 적용한 UX 법칙

작은 화면(400×240)·짧은 실시간 구절(8초)·정지형 편성이라는 이 게임의 제약에서, 정보 설계는 "읽는 것"이 아니라 "느끼는 것"이어야 한다. 다음 법칙을 감사 기준으로 삼는다.

| 법칙 | 의미 | 이 게임에서의 적용점 |
|---|---|---|
| **Miller (매직 넘버 7±2)** | 작업기억은 ~7 청크 | 손패 5 / 큐 5 / 상점 5쪽 / 헤더 계기 4 / CUE·HP 핍은 개수 세기로 즉독 — 모두 7 이하 유지 |
| **Hick의 법칙** | 선택지 수에 비례해 결정 시간 증가 | 기본 CUE 1로 "동시에 의미 있는 선택"을 제한, 상점 페이지네이션(5), 의도 예고로 손패 해석 축소 |
| **목표 구배(Goal-gradient)** | 목표에 가까울수록 동기 상승 | 64칸 링 레이스 + 16·32·48·64 위상 마일스톤 — **진행이 눈에 차야** 후반 몰입이 생김 |
| **Zeigarnik 효과** | 미완의 과업이 기억에 남음 | 미송출 큐(`STREAM LOST — UNSENT QUEUE`), ON AIR 편성 소진 표시 |
| **Von Restorff(고립 효과)** | 튀는 것이 기억됨 | 포커스 카드 강조, 구매 카드 귀환(`NEW`), 위상 팝업, 큐의 현재 발동 항목 |
| **직렬 위치 효과** | 처음·끝을 잘 기억 | 손패 첫/끝 카드, 실행 큐 순서 |
| **데이터-잉크 비율(Tufte)** | 픽셀은 장식이 아니라 데이터를 담아야 | HUD 막대는 **값을 인코딩**해야 한다 — 고정폭 장식 막대는 잉크 낭비 |
| **Doherty 임계(<400ms)** | 즉각 피드백이 몰입 유지 | 60fps 렌더 — 모든 입력 반응이 임계 이하 |
| **점진적 공개** | 상세는 필요할 때만 | 카드 상시 정보 4개 제한, 상점 포커스 상세 패널 |
| **Jakob의 법칙** | 사용자는 일관성을 기대 | 화면마다 하단 조작 힌트 한 줄, 색-의미 고정(청록=실제/호박=보관/자홍=모방) |
| **정점-종점 법칙** | 절정과 끝이 경험을 규정 | OPEN CHANNEL 64 카타르시스 시퀀스, 결과 화면 |
| **게슈탈트(근접·공동 영역)** | 가까운 것끼리 묶여 보임 | HUD 상단 바·하단 큐 패널·손패 영역의 영역 분리 |

## 2. 화면별 정보 설계 감사

각 화면이 **반드시 전달해야 하는 정보**([45](45_UI_UX.md) §1 HUD 불변 조건) 대비 실제 전달 여부를 감사한다.

### 2.1 EDIT — 편성

전달해야 할 것: 다음 적 의도(무엇이·어디서·몇), 남은 CUE, SEEK 잔여, 덱/뽑기/버림, 손패 5장의 타입·상태·TX/RX, 노아 학습 대상, 링 구성.

- **강점**: 손패 5장(Miller 준수), 타입별 프레임·모서리(색맹 대응, [45](45_UI_UX.md) §2), TX/RX 포트 방향, 계약 토큰, 카드 포커스 시 에코가 카드를 바라봄(인과 암시).
- **감사에서 드러난 공백**:
  - **의도 예고가 텍스트뿐** — "몇 명이 어디서"라는 레벨 디자인의 핵심([10](10_MECHANICS.md) §5)이 수치로 보이지 않았다. → *적 종류 아이콘 + 수량 텔레그래프 추가.*
  - **SEEK 잔여가 HUD 불변 조건인데 미표시** — 손패당 1회 능력의 가용 여부를 알 수 없었다. → *`탐색 가능/소진` 상태 표시 추가.*
  - **CUE가 숫자만** — 작은 수는 핍(개수 세기)이 즉독. → *● 핍 병기.*

### 2.2 ON AIR — 송출

전달해야 할 것: 다음에 Space가 발동할 프로그램, 큐 진행, 남은 시간, HP/SYNC, 위험 탄.

- **강점**: 번호·연결선 큐, 현재 발동 항목 흰 테두리 강조(Von Restorff), 위험 탄만 코어 강조([45](45_UI_UX.md) §5).
- **공백**:
  - **다음 발동 카드가 아이콘으로만** — "카드→효과 인과"([10](10_MECHANICS.md) §15)가 절반만 전달. → *다음 발동 프로그램 이름 + 소진 상태 문구 추가.*
  - **남은 시간이 숫자 하나** — 8초 구절의 압박이 "느껴지지" 않았다. → *하단 패널 상단에 카운트다운 슬라이버 막대 추가(목표 구배·시간 압박).*

### 2.3 BREAK — 구매·서비스

- **강점**: 5쪽 페이지네이션(Hick), 구매 가능 카드만 명도 상승(Von Restorff), 포커스 상세 패널(점진적 공개), **PROGRAM 포커스 시 `modifier 계열 → 구매 후 강도(→N)`** 표시 — 같은 계열을 모으면 최종 방송이 강해진다는 **스펙 변화를 구매 순간에** 읽게 함([45](45_UI_UX.md) §2). 이 게임 정보 설계의 모범 사례.
- **공백(경미)**: BAUD 병기 라벨(`전송량/다운로드 가능`)은 초보 보호 선택지로 남겨둠([45](45_UI_UX.md) §2 수치 표현).

### 2.4 OPEN CHANNEL — 최종 방송

- **강점**: 링이 화면 UI로 승격, 최종 방송 `형태/수정자/강도` 상단 상시, 원형 쿨다운 게이지 + 형태 아이콘 고정([45](45_UI_UX.md) §45), 노아 단계 진화. 정점-종점 법칙을 충실히 구현.

### 2.5 헤더(전 화면 공통)

- **감사에서 드러난 최대 공백 — 데이터-잉크 위반**: HP/SYNC/ECHO/TURN 막대가 **고정폭 장식**이었다. 값이 변해도 막대는 그대로여서, "상황·스펙 변화의 시각화"라는 요구의 정면 위반. → *네 계기 전부를 값 인코딩 계기로 교체(아래 §4).*

## 3. "위상 변화가 보이는가" — 상태·스펙 변화 가시화 감사

이 게임의 재미는 화력 숫자가 아니라 **덱·공간·관계의 변화**다([45](45_UI_UX.md) §2). 따라서 각 상태 전환이 화면에 드러나는지가 핵심 평가축이다.

| 상태·위상 전환 | 발생 시점 | 가시화 (감사 결과) |
|---|---|---|
| 카드 CUE(편성) | EDIT 선택 | CUE 핍 감소 + 카드 라벨 `편성` + 에코가 카드를 봄. **큐 형성**은 ON AIR에서 확인 |
| TX/RX 배정 | EDIT | 카드 하단 포트 방향(송신^/수신v) — 색이 아닌 방향 |
| SYNC 등급 변화 | ON AIR 종료 | **헤더 SYNC 핍**이 값 반영(개선 전: 항상 만충 막대 — 변화 안 보임) |
| 링 색 구성 변화(엔딩 결정축) | 상시 | **헤더 스택 구성 막대**로 청록/호박/자홍 비율 상시(개선 전: 장식 막대) |
| 16·32·48·64 위상 | 임계 도달 | 마일스톤 팝업(`첫 응답`·`교차 채팅`·`가면 균열`·`양방향 수신`) |
| 구매 후 최종 방송 강도 | BREAK 포커스 | `계열 → 구매 후 N` — 스펙 성장 예고(모범) |
| 다음 발동 프로그램 | ON AIR | **큐 강조 + 이름 문구**(개선 전: 아이콘만) |
| 다음 구절 위협 | EDIT | **적 아이콘 + 수량 텔레그래프**(개선 전: 텍스트만) |
| 남은 시간 | ON AIR / OPEN | **카운트다운 막대**(ON AIR) + 초 숫자 |

결론: 전환 이벤트 자체는 대부분 존재했으나, **상시 계기(헤더)가 값을 반영하지 않아** "지금 무엇이 어떻게 변하고 있는가"의 연속적 피드백이 끊겨 있었다. 이번 패스는 그 연속 피드백을 복원하는 데 집중했다.

## 4. 이번 패스에서 반영한 개선 (render 레이어)

세부 커밋 내용은 [CHANGELOG.md](CHANGELOG.md). 요지:

1. **헤더 계기 4종을 값 인코딩으로 교체**(데이터-잉크):
   - HP = 5개 생명 핍(작은 수는 개수로 즉독, Miller).
   - SYNC = 0~3 채워지는 3핍(편곡 게이지 — 값 변화가 보임).
   - ECHO = **64 기준 스택 구성 막대**(청록/호박/자홍 폭 = 엔딩 결정 색비를 매 프레임, 목표 구배).
   - TURN = 12구절 경과 비율 막대.
2. **EDIT**: 의도 위협 텔레그래프(적 아이콘 `×수량`), SEEK 가용 상태, CUE ● 핍.
3. **ON AIR**: 다음 발동 프로그램 이름 문구 + `편성 완료/없음`, 상단 카운트다운 슬라이버 막대.

모두 render 레이어 순수 드로잉으로, 규칙·밸런스 수치는 불변([90](90_STATUS.md) §5 원칙 준수) — 결정론 SIM 회귀 동일 통과.

## 5. 남은 권고 (우선순위)

Windows 빌드 검수([90](90_STATUS.md) §2 게이트)와 함께 다음을 권고한다.

1. **[상] 카드 선택 시 링 구획 변형** — [45](45_UI_UX.md) §1의 "에코 링의 한 구획이 카드 형태로 변형". 편성의 인과를 카드→링으로 직결. 16대구간 표현의 한계 안에서 시제품 필요.
2. **[상] 획득 연출 궤적** — [45](45_UI_UX.md) §3의 "신호 조각 → 케이블/곡선 → 빈 칸 삽입". 현재는 즉시 점등이라 "어디서 왜 왔는지"가 약함.
3. **[중] SYNC 변화 순간 펄스** — 값은 이제 핍으로 보이나, 상승·하락 *순간*의 강조(테두리 펄스)가 있으면 "왜 올랐/내렸는지" 인과 학습이 빨라짐.
4. **[중] TX/RX 위험도 추천**([10](10_MECHANICS.md) §3-1) — 첫 3턴 `위험 높음→TX / 낮음→RX` 힌트. 위협 텔레그래프가 들어왔으니 그 위에 얹기 자연스러움.
5. **[중] 자동 TX/RX 배정·접근성 옵션**([90](90_STATUS.md) §4 미착수) — 입문 보호 층.
6. **[하] BAUD 병기 라벨**, 셔플/CLEANUP `SENT` 스택 접힘 연출([45](45_UI_UX.md) §1·§40).

권고 1·2는 사람 대상 플레이테스트(GV2)로 체감 효과를 검증한 뒤 확정한다.
