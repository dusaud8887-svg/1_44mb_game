# ADR-0006 — 단일 파일 원칙·"파일 I/O 없음" 원칙 폐기

- 상태: 채택 (2026-07-16) / 원문 11부 §70, 15부 §86

## 결정

1. **"2,500줄 전까지 한 파일" 원칙 폐기.** 분리 기준은 줄 수가 아니라 **변경 이유**다: `core/ platform/ render/ audio/ generated/ tests/` + 릴리스 unity build([30](../30_TECH.md) §4).
2. **"파일 I/O 없음" 절대 원칙 폐기.** 64~256B 저장 파일 1개(`ECHO144.SAV`)로 엔딩·해금·기록을 지원한다([30](../30_TECH.md) §8).

## 맥락

- 단일 파일은 2,050줄에서 이미 전역 상태 결합·수치 3중 기재 드리프트를 만들고 있다(유지보수성 5~6/10). unity build를 쓰면 개발 분리와 크기 최적화(/GL·ICF)를 동시에 가진다 — "한 파일"의 실익은 빌드 형태로 보존된다.
- V2의 반복 플레이 설계(비수치 해금, 엔딩 기록, TODAY 최고 기록)는 저장 없이는 성립하지 않는다. "무저장"의 원래 동기(심사 PC 오염 방지·단순성)는 exe 옆 단일 소파일 + 읽기 전용 폴더에서 무저장 정상 동작 + checksum 불일치 시 조용한 초기화로 보존한다.

## 안전장치

- 저장 실패는 어떤 경우에도 크래시·경고 팝업을 만들지 않는다 (조용히 무저장 모드).
- 함께 폐기된 관련 원칙들 (원문 18부 §103): 시스템 글꼴을 최종 화면 규격으로 사용(→ 내장 비트맵 폰트), 모든 PROGRAM 자동 발동(ADR-0002), FORMAT을 게이지·초상만으로 처리(ADR-0003), 영구 능력치 메타 성장, 전 화면 글리치, 무기 슬롯·덱 이중 성장계.
- 계속 유지되는 원칙: 1.44MB 단일 EXE, 무패킹, 320×240 제한 팔레트, 절차적 오디오, 5장 손패, 구매 카드의 셔플 지연, 한 BREAK 한 구매, 64 목표, TODAY 시드.
