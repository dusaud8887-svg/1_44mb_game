# ADR-0001 — 공모전판은 C11+Win32 스택을 유지한다

- 상태: 채택 (2026-07-16) / 원문 13부

## 결정

공모전판은 엔진·프레임워크를 교체하지 않는다: C11 + Win32(USER32/GDI32/WINMM) + CPU 프레임버퍼 + `waveOut` + 60Hz 고정 틱 + MSVC 정적 CRT + 무패킹.

## 맥락

1.44MB 단일 EXE·무설치가 최상위 제약이다. 현 스택의 적합성 평가는 1.44MB 9.5/10, 결과물 통제력 9/10. 반면 약점(개발 반복 속도 6/10, 유지보수성 5~6/10)은 스택이 아니라 **코드 구조와 데이터화**의 문제다.

## 기각된 대안

- **Sokol**: 즉시 교체 실익 없음 → 확장판 1순위 프런트엔드로 지정.
- **raylib / SDL3 / RGFW / miniaudio**: 불필요 기능·통합 비용 또는 실익 부족 → 보류·확장판 후보.
- **Defold / Godot / LÖVE**: 1.44MB 위험 또는 런타임 불일치 → 대형판·프로토타입 전용.

핵심 논거: **엔진 교체는 V2의 진짜 문제(손패 의사결정·카드 개성)를 하나도 해결하지 않는다.**

## 결과

- 확장 대비는 스택 교체가 아니라 경계 분리로: 결정론 코어 ↔ Platform API ↔ Win32/Sokol 프런트엔드([30_TECH.md](../30_TECH.md) §2·§4).
- 개발 반복 속도는 빌드 타임 콘텐츠 컴파일러와 효과 레시피 데이터화로 해결([30](../30_TECH.md) §6~7).
