# 45 — UI/UX·화면 연출 정본

화면 레이아웃, HUD, 카드 정보 표시, 이펙트 우선순위, 피격·카메라·플래시 규칙, 접근성의 정본. 규칙 자체는 [10_MECHANICS.md](10_MECHANICS.md), 시각 방향은 [40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md), 제작 규격은 [41_PIXEL_ART.md](41_PIXEL_ART.md). UI의 대원칙: **UI는 세계관의 물건이다** — 시대별 인터페이스가 곧 무대이고, 카드 프레임이 곧 방송 장비다.

## 1. 320×240 기본 레이아웃

### ON AIR

```text
y   0..15     상단 상태 바
y  16..207    전투 공간
y 208..239    축소 큐·입력·현재 프로그램
```

- 상단 좌: HP / SYNC. 상단 중: `ECHO N/64` + 축소 링(8대구간). 상단 우: 페이즈·남은 시간·다음 의도.
- 하단: 현재 준비 프로그램(축소 큐), 남은 CUE(● 개수), 다음 카드/손패 예고, Space 입력 피드백.

### EDIT

```text
y   0..15     상태·적 의도 (NEXT 한 줄)
y  16..158    명도 40% 감소한 전장 + 에코 반응
y 159..239    5장 손패 + 선택 카드 설명 패널
```

- 손패 5장은 약 52×60~56×64. 선택 카드는 2px 상승 + PAPER 테두리, 나머지는 타입 모서리 기호만.
- 카드 선택 시 테두리 발광에 그치지 않는다 — **에코 링의 한 구획이 해당 카드 형태로 변형**되고, 에코가 카드 방향을 바라본다.
- CARRIER의 TX/RX 지정([10](10_MECHANICS.md) §3-1): 카드 하단의 열린 포트가 문법이다 — **TX = 포트에서 위로 송신 파형, RX = 포트 아래로 떨어지는 다운로드 점**. 색이 아니라 방향으로 읽힌다. `[본 개정 구체화]`

### BREAK

- 전장을 통째로 갈아치우지 않는다 — **방송이 잠시 멈춘 느낌**: 배경의 적은 희미한 정지 프레임으로 남는다.
- 최대 3개 큰 선택 또는 5개 작은 시장. 구매 가능 카드만 명도 상승. 비용은 숫자 하나 + BAUD 아이콘. 긴 설명 대신 `효과 아이콘 + 한 줄`, 포커스 시 상세 패널.
- 구매 카드가 버림더미로 들어가는 경로를 시각적으로 보여 준다.
- **NØA 제안 = 지나치게 매력적인 UI와 완벽한 정렬 / 시크 거래 = 손으로 붙인 호박 라벨과 불규칙한 케이블** — 두 세력의 성격이 상점 UI 그 자체에 드러난다.

### CLEANUP / 셔플

- 사용 카드가 우하단 `SENT` 스택으로 접힌다. 셔플은 카드 전체를 흔들지 않고 디스크 탐색음 + 줄 단위 재배열.
- 방금 산 카드의 첫 귀환은 2~3프레임 강조 — 엔진이 온라인 된 순간을 즉시 알게 한다.

### 타이틀 (CONNECT)

검은 화면에서 빨간 LIVE 핀 1픽셀이 먼저 켜진다 → 목록에 없는 방송 링크 → 에코 링 순차 점등. **NØA 프로필은 소개 전부터 관리자 목록에 1픽셀로 이미 존재**하고, 시크 케이블 끝이 화면 가장자리에 이름 없이 잠깐 보인다 — 첫 화면부터 반복 단서를 심는다.

## 2. 카드 정보 표시

한 카드에 상시 노출하는 정보는 **4가지를 넘기지 않는다**: 타입 / 비용·BAUD / 아이콘 / 핵심 효과 기호. 상세 문장은 선택 시 설명 패널로. 한글명·영문명·설명 3줄·태그·희귀도·풍미 문구를 한 장에 모두 넣지 않는다.

### 타입 프레임 — 색이 아니라 모서리 형태로

| 타입 | 프레임 형태 | 모서리 | 주색 | 인상 |
|---|---|---|---|---|
| CARRIER | 열린 하단 포트 | 둥근 한 곳 | 청록·청색 | 흐름·대역 |
| PROGRAM | 좌측 CUE 슬롯 | 사각 | 흰색+세력색 | 선택·실행 |
| ARCHIVE | 상단 날짜 탭 | 잘린 한 곳 | 회색→3색 반전 | 부담·반전 |
| NOISE | 깨진 테두리 | 불규칙 | 빨강·회색 | 오염 |
| SPONSOR | 완전 대칭 이중선 | 모두 동일 | 자홍 | 즉시 강함·의존 |
| CACHE | 묶는 태그 | 둥근 루프 | 호박 | 보관·지연 |
| REACTION | 우측 번개 탭 | 한쪽 돌출 | 흰색 | 조건 반응 |

전체 테두리를 타입색으로 칠하지 않는다 — 전투 화면에서 색 면적이 캐릭터 세력색과 경쟁한다.

### ON AIR 축소 큐

20×24~24×28, 아이콘 16×16, 발동 순서 숫자 또는 연결선, CUE 여부 = 흰 테두리+삼각 탭, 지연·봉인 = 아이콘 위 상태 기호. **카드명이 안 보여도 기능이 구분되어야 한다.** 실행 불가 PROGRAM은 어둡게 하지 않고 CUE 포트만 빈 상태로 — 그림 자체는 계속 읽힌다.

### 선택 모션

위로 2px 상승 / 흰 테두리 1px / 하단 CUE 포트 점등 / 아이콘 대표 부위 1프레임 동작 / 연결 가능한 다음 카드까지 얇은 선(`MULTI→MACRO` 청록 연결선).

### 수치 표현

큰 피해 숫자 금지 — 이 게임의 매력은 덱과 공간 변화다. 비용 = 우상단 고정폭 숫자 / BAUD = 파형 기호+숫자 / CUE = ● 개수 / 메아리 = 링 조각 기호 / 지연 = 점선 테두리 / 보관 = 호박 태그 / 모방 = 자홍 이중 윤곽.

### 희귀도 — P0에서 두지 않는다

도미니언형 공급에서 가치는 맥락과 조합이다. 프레임 색 희귀도는 타입·세력색과 혼동된다. 확장판에서 필요하면 `기본/세션/조건부/숨은 프로토콜` 모듈 구분을 하단 파일 탭으로만.

## 3. 64칸 링 표시 규칙

- **전투 중**: 8개 대구간 + `N/64` 숫자만. 64칸 세부는 OPEN CHANNEL·BREAK·엔딩에서만 정밀 표시 — 전투 캐릭터 뒤에 64칸을 전부 그리면 노이즈다.
- 각 칸은 색 + **형태**가 다르다 (색각 대응): 청록 = 둥근 단색 / 호박 = 점선·태그 / 자홍 = 이중선·완전 대칭 / 라벤더 = 중심이 빈 비정형.
- **획득 연출**: 화면 중앙 숫자 팝업 금지. 발생 위치에서 신호 조각 생성 → 곡선/케이블을 따라 에코에게 이동 → 정확한 빈 칸에 삽입 → 대구간 1프레임 점등. 세력별 이동 문법: 청록 = 약간 흔들리며 직선 / 호박 = 시크 케이블을 따라 감겨 들어옴 / 자홍 = **이미 정해진 위치에 갑자기 완성됨**.
- 금지: 64개 숫자 상시 표시 / 임계마다 동일한 전체 화면 폭발 / 링을 하단 경험치 바처럼 배치 / 64 도달 후 추가 체력전 요구.

## 4. 채팅·로그 노출 규칙

- 전투 핵심 UI와 분리된 가장자리 열, 최대 두 줄, 한 줄 1.2~2.0초. **적 밀도가 높으면 자동 지연.**
- 중요한 로그는 BREAK 직후 1초에 노출 — 전투 중 장문 금지. 전투 중에는 숫자 한 자리·잘못된 날짜·닉네임 하나·상태 한 줄·프로필 패턴·한 프레임의 반사만.
- NØA의 가짜 채팅은 자홍색만으로 구분하지 않는다 — **프로필 테두리 + 동일 오타 + 같은 문장 길이**로 암시([40](40_ART_AUDIO_TEXT.md) §7).
- 화면을 읽느라 피격되는 상황을 만들지 않는다. POP.AD 등 UI형 적이 핵심 상태 숫자·히트박스·현재 선택 카드를 가리지 않도록 HUD 마스크 영역을 둔다.

## 5. 이펙트 동시성·우선순위

렌더 우선순위 (읽기의 순서):

```text
1. 플레이어 피격·위험 판정   2. 현재 수동 PROGRAM   3. 보스 의도
4. ARCHIVE 대형 효과         5. 자동 CARRIER        6. 장식 파티클
```

동시 허용 상한 `[시드값]`: 대형 화면 효과 1 / 중형 지속 효과 3 / 연결선 12~16 / 일반 파티클 128~256 / 중요 글리프 ≤32. **사양이 아니라 가독성을 위한 제한이다.** 위험 탄환은 화려한 아군 효과에 묻히지 않아야 한다 — 중요 탄환만 외곽선·밝은 코어를 갖는다(전부 위에 그리면 공간감이 깨진다).

## 6. 피격·카메라·플래시 — 타격감은 타이밍이다

기본 타격 시퀀스: `예고 2~8틱 → 충돌 1틱 → 히트스톱 0~3틱 → 반응 2~6틱 → 잔향 4~20틱`.

히트스톱은 전부 주지 않는다: 2400 패킷 = 없음 / 14K 관통 = 첫 적 ≤1틱 / SURGE 연쇄 = 큰 노드만 1틱 / CLIP 닫힘 = 2~3틱 / TREND MIRROR 첫 공개 = 2틱 / 64 도달 = 정지 대신 **3틱 시간 팽창**.

카메라: 320×240에서 1픽셀이 이미 크다. 일반 피격 0~1px / 엘리트 처치 1px / CLIP 종료 1~2px / 최대 지속 6~8틱. 랜덤 흔들림 대신 `충격 방향 1px → 반대 1px → 복귀`. 64 도달은 흔들림이 아니라 1px 바깥 확장.

플래시: 전체 순백 금지. 주요 윤곽만 흰색 / 적탄만 1프레임 반전 / 테두리 펄스 / 팔레트 밝은 슬롯 1단계 이동 / 링 구획 순차 발광.

피해 표현: 플레이어 = 본체를 빨갛게 덮지 않고 **외곽과 LIVE 핀만 빨강** + 흰 피격 코어 노출 + 링 구획 2프레임 흔들림. 적 = 실루엣 1프레임 PAPER + 공격 방향 1px 눌림 + 종류별 고유 파편 1~3개. 피해 숫자는 치명타·보스에만. **처치는 기능이 보이는 해체**: BOT.CHAT = 말풍선 점 흩어짐 / POP.AD = 창이 안쪽으로 접힘 / MOD.MASK = 봉인 갈라짐 / SPON.GIFT = 리본 풀리고 빈 프로필 / BUF.WRM = 케이블 끝이 마지막까지 남음.

## 7. 히트박스와 피격 코어

```text
보이는 에코 몸            약 18×21 (24×24 캔버스)
실제 플레이어 히트박스     6×7
피격 중심 표시             가슴/발밑 1px 코어 — 평소 희미, 위험 탄 접근 시 PAPER 색
```

머리카락·링·재킷 끝은 시각 면적이지 판정이 아니다. 판정의 관대함이 픽셀 게임의 조작감을 만든다.

## 8. 폰트

시스템 GulimChe 의존 폐기 ([30](30_TECH.md) §9): ASCII 6×8(고정폭), 한글 본문 8×12~8×14, 숫자 6×8 고정폭, 제목은 전용 비트맵 워드마크. 사용 음절만 subset. 효과: 모든 PC 동일 출력 / 정수 배율 / 색·배경 문제 소멸 / 글자 폭 예측.

## 9. 접근성

- 저자극: 흔들림 0, 섬광 → 테두리 펄스, 규칙 불변. NØA 얼굴 분열 연출 완화 옵션.
- 색각: 세력별 패턴·선 모양 유지([40](40_ART_AUDIO_TEXT.md) §3 형태 문법) — 색을 빼도 관계가 남는다.
- EDIT 완전 정지(기본) / 카드 자동 추천 / 프로그램 자동 발동(Space 길게) / TX/RX 자동 배정 옵션(입문).
- 피격 코어 표시 강도·배경 오류 강도 설정. `M` 음소거, `ESC` 일시정지, Alt+F4 정상 종료.

## 10. UI 금지 목록

- 모든 패널에 이중 테두리 / 한 카드 안 문장 3줄 이상 / 아이콘·한글명·영문명·설명·태그 상시 병기.
- 색만으로 카드 타입 구분 (모서리 형태 병행 필수).
- 팝업 적이 설정 메뉴·HP를 가리는 연출. 전투 중 읽어야 하는 긴 미스터리 문장.
- 아레나 중앙의 고정 로고·텍스트. 충돌 오브젝트와 배경 장식의 명도·외곽선 동급 처리.

## 11. 결과 화면과 즉시 재시작

```text
ENTER   같은 신호 재접속 (시장·의도 덱·웨이브·셔플 동일, 첫 입력 전까지 즉시 시작)
RIGHT   새 신호 탐색 (새 시드)
TAB     방송 기록 (링 구성·덱·로그)
```

**실패 → 다시 조작 가능까지 1초 미만.** 이것은 편의가 아니라 반복 플레이 설계의 뼈대다([35](35_REFERENCES.md) §3 CLAWSTRIKE).
