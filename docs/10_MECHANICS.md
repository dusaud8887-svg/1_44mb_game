# 10 — 규칙 명세 (V2)

플레이 규칙의 정본. 모든 튜닝 수치는 [20_BALANCE.md](20_BALANCE.md)의 표 ID로 참조하고 여기 중복 기재하지 않는다. 구현 상태는 이 문서에 쓰지 않는다 — [90_STATUS.md](90_STATUS.md)가 정본. 카드 개별 설계는 [15_CARDS.md](15_CARDS.md). 자동 실행(V1) → 수동 편성(V2) 전환의 결정 이력은 [adr/0002-manual-cue-turn-structure.md](adr/0002-manual-cue-turn-structure.md).

**장르 정의**: 수동 편성형 실시간 솔로 덱빌더 서바이버 — 매 턴 5장을 편성(EDIT)하고, 실시간 전투(ON AIR)에서 직접 발동한다. 도미니언의 액션 경제(CUE)·경제(BAUD)·승점 오염(ARCHIVE)을 가져오고, 뱀서의 힘 곡선과 화면 장악을 후반에 배치한다.

## 1. 전체 흐름

```text
[타이틀] ENTER 일반 / F2 TODAY
   ↓
[오늘의 채널] 세션 킹덤 5종 + 감사 프로토콜 1종 + 시간층 확인. 시간 제한 없음
   ↓
[일반 방송 12턴]  ← 턴마다: EDIT → ON AIR → BREAK → CLEANUP
   ↓ 8턴 종료부터 BREAK에서 OPEN CHANNEL 선택 가능 / 12턴 종료 시 강제
[OPEN CHANNEL 최대 60초] 양방향 개방. ARCHIVE 반전, 64칸 링 레이스, NØA TREND MIRROR
   ↓
[결과] 링 색 구성 → 엔딩 분기 / 총 시간·턴·최종 덱·seed → 즉시 재시작
```

- **시간의 단위는 턴이다.** V1은 "몇 분 몇 초"의 연속 시간이었지만, V2는 초중반 진행을 턴으로 명확히 보여 준다 — HUD에 `TURN 7/12` 상시 표시. EDIT·BREAK에서 보낸 현실 시간은 전투와 무관하다.
- TODAY는 로컬 날짜 `YYYYMMDD` 고정 시드. 같은 날짜면 같은 킹덤·프로토콜·셔플·의도 덱. 서버 없음.
- 목표 런 길이: 5~7분 (B2-턴).

## 2. 한 턴의 네 단계

```text
[EDIT]      5장 드로우. 방송할 PROGRAM 선택(CUE). 순서·보관·SEEK 결정. 다음 적 의도 확인.
[ON AIR]    약 8초 실시간. 에코 이동, 선택한 PROGRAM 수동 발동, CARRIER 자동 공격.
[BREAK]     이번 턴 BAUD로 카드 1장 구매 또는 SERVICE 이용. (조건부: NØA 스폰서 / 시크 거래)
[CLEANUP]   사용·미사용 카드 버림. 캐시·격리 처리. 드로우 부족 시 셔플.
```

### 흐름을 덜 끊는 옵션 — 입문 보호와 숙련 가속

- EDIT 중 **완전 정지가 기본**(접근성 겸용). 숙련 모드: 25% 슬로모션 + 제한 시간(B2-턴) — 규칙은 불변, 생각 시간만 압박.
- EDIT에서 일정 시간 입력이 없으면 **추천 PROGRAM 자동 선택** — 입문자는 아무것도 몰라도 진행된다.
- ON AIR에서 Space를 길게 누르면 준비된 PROGRAM **자동 발동** — "이동만으로 플레이 가능"의 V2 버전.
- 이 옵션들은 난이도가 아니라 조작 밀도의 층 분리다. 난이도는 규칙 은닉이나 버튼 추가로 만들지 않는다.

## 3. EDIT — 편성

매 턴 드로우 더미에서 5장을 뽑아 공개한다. 화면 예:

```text
[2400] [MULTI] [MACRO] [CHAT] [14K]      CUE ●      SEEK 1      NEXT: BOT RAID →동쪽 다수
```

카드 타입별 취급 (타입 정의와 견제 구조는 [15_CARDS.md](15_CARDS.md) §1):

1. **CARRIER — TX/RX 양면 지정** (ADR-0007). 손패의 각 CARRIER를 둘 중 하나로 배정한다. CUE는 소비하지 않는다.
   - **TX(송신)**: 이번 ON AIR에서 자동 공격 스트림을 켠다. 구매 대역에는 기여하지 않는다.
   - **RX(수신)**: 이번 ON AIR에서 공격하지 않는다. BREAK에서 BAUD를 제공한다.
   - 이 한 규칙이 만드는 것: 현재 생존 vs 미래 경제의 **매 턴 직접 선택** / Treasure와 공격의 역할 혼합 해소(모뎀이 구조적으로 유리해지는 문제) / 적 의도에 따른 배분 변화(BOT RAID → 전부 TX / 약한 의도 → RX 투자) / 모뎀 중심 전략의 개성. "지금 싸울 것인가, 다음 카드를 살 것인가."
   - 입문 보호: 첫 구절은 `송신 1 / 수신 1`을 추천 기본값으로 적용하고 MULTI에 포커스를 둔다. 플레이어는 즉시 모두 변경할 수 있다. 2~3구절은 화면 문구로 TX/RX와 실시간 입력을 단계 공개한다.
2. **PROGRAM** — 보통 CUE 1을 소비해 선택한다. 모든 카드 효과는 **phase**를 가진다([15](15_CARDS.md) §2 정본): `EDIT_IMMEDIATE`(선택 즉시 EDIT 안에서 해소 — MULTI·CACHE·PREFETCH·MARKER의 드로우)와 `ON_AIR_ACTIVE`(Space 수동 발동 — FIREWALL·SURGE·MACRO 등). 선택하지 못한 PROGRAM은 `ON_AIR_PASSIVE` 약효과 또는 미사용(카드별). 기본 CUE는 1 — 이것이 **terminal collision**을 만든다: 강한 PROGRAM을 많이 사는 것만으로는 강한 덱이 되지 않는다.
   - **MULTI.FORK = Village**: `EDIT_IMMEDIATE`, CUE 1을 내고 **CUE +2를 받는다(순증 +1)** — EDIT 안에서 즉시 해소되므로 추가 PROGRAM을 계속 편성할 수 있다. "ON AIR에서 CUE를 받는" 구조는 선택이 이미 끝난 뒤라 Village가 될 수 없어 폐기했다.
3. **ARCHIVE** — 일반 방송에서는 발동 불가. 손패 슬롯만 차지한다(기본 공격 없음, BAUD 없음). 특정 PROGRAM(PREFETCH 등)으로 작은 예고 효과만. OPEN CHANNEL에서 반전된다(§10).
4. **NOISE** — 발동 불가. 슬롯 점유 + 카드별 방해. CHECKSUM·SERVICE의 제거 대상.

**SEEK (기본 능력)** — 손패당 1회: 사용하지 않을 카드 하나를 **덱 아래로 보내고 새 카드 1장을 뽑는다.** V1의 "첫 카드 순서 미루기"보다 선택성이 높다 — ARCHIVE 정체, 중복 PROGRAM, NOISE 대응, 셔플 타이밍 조절에 전부 쓰인다. 사용하지 않아도 정상 플레이가 가능해야 한다.

EDIT 종료 시 이번 턴의 **편성**이 확정된다: CARRIER의 TX/RX 배정 + 발동 순서가 있는 PROGRAM 실행 큐 (예: `MULTI → MARKER → SURGE`). CUE·TX/RX·SEEK의 해석 순서는 §14.

### CUE는 단일 핵심 동사다

CUE는 카드 선택 버튼이 아니라 게임 전체를 관통하는 동사다([35](35_REFERENCES.md) §3): 프로그램을 활성화하고 / 실행 순서를 정하고 / MULTI가 CUE를 늘리고 / **NØA가 CUE된 프로그램을 학습하고** / 적이 CUE 슬롯을 봉인하고 / 시크가 CUE된 아카이브를 보관하고 / MACRO가 직전 CUE를 재생하고 / CACHE가 CUE를 다음 구절로 넘기고 / 최종 방송이 최다 CUE 태그를 계승한다.

## 4. ON AIR — 송출

약 8초(B2-턴)의 실시간 전투.

```text
WASD / 방향키   이동 (8방향, 대각선 정규화)
Space           실행 큐의 다음 PROGRAM 발동
Space 길게      자동 발동 (준비되는 대로 순서대로)
Shift           [보류 P1+] REACTION — 긴급 방어·반응 카드
```

- **자동으로 유지되는 것**: CARRIER 기본 공격(최근접 조준, 대상 없으면 마지막 이동 방향), 단순 수치 효과, 일부 REACTION.
- **수동으로 가치가 생기는 것**: 범위 공격, 벽(FIREWALL), 연결망(SURGE), 화면 절단(CLIP), 복제(MACRO), 강한 방어 — **발동 타이밍과 위치가 플레이 실력이다.** 벽을 어디에 세우는가, 연쇄를 언제 터뜨리는가.
- Space를 누를 때마다 큐의 다음 PROGRAM이 실행된다. 큐가 비면 Space는 무동작(오발 없음).
- 필드: 내부 400×240(5:3 와이드) — 상단 상태 바 16px / 전투 영역 400×192 / 하단 큐 32px ([45](45_UI_UX.md) §1 정본). 카메라 없음, 경계 이탈 없음. 넓어진 가로가 홀로큐어식 회피·상황 파악 공간과 손패 가독을 확보한다.

### 덱 구성이 실시간 전투를 바꾼다 — 태그 스쿨 → 전투 정체성 `[본 개정 신설]`

[15](15_CARDS.md) §9의 "같은 계열 PROGRAM을 모으면 최종 방송이 강해진다"는 상환을 **일반 방송 ON AIR에도 상시 적용**한다. 최종 60초에서만이 아니라, 무엇을 사서 덱을 어떻게 구성하느냐가 런 내내 CARRIER 자동 전투의 형태·속도·위력을 바꾼다 — 도미니언식 덱빌딩이 뱀서식 전투 정체성으로 실시간 상환되는 축.

네 스쿨은 각각 **뚜렷한 무기 정체성**을 가진다 — 뱀서/홀로큐어식 "빌드마다 다른 전투"의 축. modifier의 서사 의미(§9)와 정합한다.

| 태그 스쿨(대표 카드) | 무기 정체성 | 전투 효과 | 시각 변화 |
|---|---|---|---|
| NETWORK (MARKER/SURGE) | **확산** (군중 제어) | CARRIER가 최근접 1체 대신 여러 적을 **동시 조준**(1+tier 타겟) | 탄이 여러 적에게 갈라짐 |
| REPEAT (MULTI/CACHE) | **다발** (집중 화력) | CARRIER가 **부채꼴 추가 탄** 발사(+1~2) | 볼리당 탄 수 증가 |
| REPLAY (MACRO/PREFETCH) | **연사** (지속 DPS) | CARRIER **재장전 단축** | 탄이 더 자주 나감 |
| SAFE (FIREWALL/CHECKSUM) | **내성** (탱킹) | 피격 후 무적 시간 연장 | 생존력(플레이어 전용) |

강도 규칙은 §9와 동일하게 **강도 1은 기본, 2부터 보상**한다(스쿨별 소유 장수 임계 = B2-전투: 2/4/6에서 tier 1/2/3). 수치는 `balance.def`가 정본. CARRIER 자체(재화 카드)의 수·타입(2400/14K)도 기본 화력을 정하고, ARCHIVE(승점)는 평시 무효·NOISE(저주)는 손패 정체 — 도미니언 삼각 경제([15](15_CARDS.md) §1)가 전투에 그대로 드러난다. HUD는 EDIT·BREAK에 현재 전투 정체성(`확산 II` 등)을 표시해 구매 결정과 전투를 잇는다([45](45_UI_UX.md) §2).

### 조우 텍스처 — 위협이 있어야 빌드가 의미를 갖는다 `[본 개정 신설]`

BOT.CHAT 군집은 HP 피해를 주지 않고 **큐를 지연**시킬 뿐이라(§9 — 적은 서로 다른 덱 층을 공격한다), 봇 습격 웨이브는 위협이 없어 전투 빌드가 물릴 대상이 없었다. 중반(4턴)부터 각 BOT.CHAT 웨이브에 **POP.AD 슈터를 소량 혼합**(`1+turn/6`)해 실제 HP 위협과 탄 회피를 만든다 — 확산·연사(처리 속도)와 내성(생존)이 이때 비로소 갈린다. 이른 구절은 여전히 완만하다.

### SYNC — 방송 동기화 등급 (Cave Story 번안, [35](35_REFERENCES.md) §3)

플레이 숙련이 방송의 질로 나타나는 교차 시스템. `SYNC 0~3` (수치·판정은 B2-SYNC):

- **상승**: 피격 없이 구절 종료 / 예고된 의도에 적합한 프로그램 사용 / 마킹 적의 회선 연쇄 제거 / 적절한 타이밍 창 발동.
- **하락**: 큰 피해 / CUE한 프로그램을 못 쓰고 구절 종료 / MUTE에 봉인 / 가짜 메아리 수용.
- **효과는 화력이 아니라 방송의 질이다**: 0 = 기본 / 1 = CARRIER 시각·사운드 강화 / 2 = 프로그램 범위·지속 소폭 증가 / 3 = 구절 종료 시 CUE 환급 확률·쿨다운 단축. **SYNC는 링을 올리지 않는다** — 플레이 실력이 '실제 관객의 대답'을 만들면 안 되기 때문이다(§8 메아리 출처 규칙). **SYNC = 편곡 게이지** — 오를수록 음악에 화음 레이어가 추가된다([40](40_ART_AUDIO_TEXT.md) §6).
- **악순환 방지 안전장치가 본체다**: 한 피격당 최대 1단계 감소 / SYNC 0에서 추가 감소 없음 / 피격 후 다음 구절 첫 성공으로 즉시 1 회복 / HP·구매력을 직접 깎지 않음 / 엔딩 조건에 필수 아님. 고수의 점수·화려함을 높이되 초보의 클리어를 막지 않는다.

## 5. 적 의도 예고 — 상대는 공개 오토마다

EDIT 단계에서 **다음 ON AIR의 적 의도 카드를 공개한다.**

```text
NEXT NOISE
BOT RAID    동쪽 다수 진입
MOD MASK    슬롯 1개 봉인
GIFT DROP   중앙 위험 보상
```

이 시스템이 수동 편성의 존재 이유다: **같은 손패라도 적 의도에 따라 선택이 달라져야 한다.** 한 화면 아레나에서 레벨 디자인 변주를 데이터로 만들고(맵 없이), 솔로 도미니언의 오토마처럼 상대 규칙을 명확하게 한다.

의도 목록과 대응 관계 (수치·가중치는 B2-의도):

| 의도 | 화면 변화 | 플레이어의 대응 |
|---|---|---|
| BOT RAID | 한 방향 다수 진입 | 14K·SURGE·FIREWALL, TX 확대 |
| MUTE | PROGRAM 슬롯 봉인 | MULTI, CHECKSUM |
| COMMENT WALL | 현재 위치 반대편 내부 축에 POP.AD 한 줄 배치 — 이동 경로 차단 | 14K 관통, SURGE, FIREWALL 방향 제어 |
| GIFT DROP | 위험 지역에 보상 | 방어, 기동 |
| CLIP THEFT | 직전 효과 탈취 | 약한 기술 미끼, 순서 조절 |
| SEEK HUNT | ARCHIVE 탈취 | 빠른 단일 피해 또는 보관 선택 |
| SPONSORED RAID | 강한 적 + 무료 카드 | 위험한 투자 판단 |
| MIRROR | 첫 발동 PROGRAM 반사 | 실행 순서 변경 |
| LATENCY | 발동 지연 | CACHE, PREFETCH |
| EMPTY CHAT | 적은 적, 메아리 감소 | RX 투자·ARCHIVE **구매**·PREFETCH 준비 |
| TREND | 최다 사용 카드 강화 복제 | 카드 다양화, 미끼 |

난도별 정보량: 입문 = 의도 전체 공개 / 일반 = 주요 의도와 방향 공개 / 고난도 = **주요 의도는 항상 참**, 방향·수량·보조 효과만 은닉. 거짓 예고를 쓸 경우 `SIGNAL CORRUPTED` 같은 **명시적 상태가 먼저 표시**되고 CHECKSUM으로 예고를 복구할 수 있다 — 덱 선택의 근거인 의도 UI가 이유 없이 거짓이면 [00](00_VISION.md) §5 '규칙 은닉으로 난이도를 만들지 않는다' 기둥과 충돌한다. 거짓말도 규칙으로 읽고 대응할 수 있어야 한다.

### 의도 덱의 절차 생성 — 완전 무작위로 섞지 않는다

```text
초반 3장   학습 가능한 단순 의도       중반 4장   덱과 카드 슬롯 공격
후반 3장   플레이어 전략 대응          종결 2장   NØA 시그니처
```

제약: 같은 의도 2연속 금지 / 해결 수단이 시장에 없는 의도 제한 / 초반 MUTE+MIRROR 동시 금지 / ARCHIVE 미보유 플레이어에게 SEEK HUNT 금지 / 가장 강한 의도 뒤에는 회복·투자 구절 1개. **이 문법이 한 화면 아레나의 레벨 디자인이다.** COMMENT WALL은 별도 맵 대신 정지형 POP.AD를 세로 또는 가로 한 줄로 내부 배치한다. 축은 현재 에코 반대편을 택해 즉시 겹침을 피하고, 개수에 따라 등간격으로 놓아 우회 틈을 남긴다.

한 런에는 기본 의도 덱 + **감사 프로토콜** 1종(런 전체 규칙 변형, B2-의도)이 붙는다:

- **RESPONSE RACE**: 두 BREAK 동안 어떤 색의 메아리도 늘지 않으면 NOISE 1장 삽입 — 생존 카드만 사는 지연 전략 견제 (Race Against Curses 변형).
- **ENGINE AUDIT**: 한 구절에 PROGRAM 3개 이상 발동 → 다음 의도 덱에 QUARANTINE 삽입 (오토마 반응 변형).
- **BANDWIDTH CAP**: BAUD에 하드 캡은 없다 — 7 이상을 전부 사용할 수 있되, **다음 의도 덱에 POP.AD 감사 카드가 삽입**된다. 큰 경제 턴을 허용하면서 노아의 관심을 끄는 소프트 페널티.
- **ARCHIVE HUNT**: 기본 SEEK HUNT 1회(7턴) + **ARCHIVE 4장 이상 보유 시 SEEK HUNT 의도 카드 1장 추가 삽입** — 확률이 아니라 의도 덱 삽입으로, 절차 생성의 가독성을 유지한다.
- **PERFECT RETENTION**: SPONSOR 등장률 2배·자홍 대가 +1.

**한 런에 프로토콜은 하나만** — 여러 개를 동시에 적용하면 특정 전략을 지나치게 처벌한다.

## 6. BREAK — 구매와 서비스

이번 턴 **RX로 지정한 CARRIER의 BAUD 합**으로 카드 **1장**을 산다(§3-1). **이월 없음** — 화력을 포기한 만큼만 이번 구매력이 된다. 구매 카드는 버림더미로 들어가 **다음 셔플 뒤에** 나타난다 — 즉시 강화는 없다. 산 카드가 처음 손패에 돌아오는 순간을 강하게 연출한다: `NEW` 점멸 + 귀환음 + 에코 주변 다운로드 선.

상점 구성 (가격·수치는 B2-카드):

```text
기본 CARRIER (14K/56K)
이번 세션 킹덤 PROGRAM 5종
ARCHIVE 3종 (CHAT/VOICE/CLIP)
SERVICE: DEFRAG (정리 타임)
조건부: NØA SPONSOR   조건부: SEEK 거래
```

- **DEFRAG는 SERVICE다** — 구매 1회를 소비해 카드 1장을 영구 삭제하고, 자신은 덱에 들어가지 않는다. 덱 압축의 기회비용(이번 턴 성장 포기)을 명확히 한다. NOISE를 삭제하면 보너스(B2-카드). Kingdom PROGRAM에서 제거된 이유: 덱 안에 들어가면 "뽑혀야 쓰는 압축"이 되어 압축 자체가 운이 된다.
- **NØA CONTRACT**(구 SPONSOR) — 조건 만족 시 노아가 무료·저가 계약을 제안한다. 구매 즉시 발동하지 않고 다음 EDIT·ON AIR 1회에 발동을 약속한다(`BREAK_CONTRACT`, §14). 확정된 강함이 즉시 화려하지만 자홍 모방 메아리를 만들고 TREND 학습을 가속한다([15](15_CARDS.md) §7). 유혹은 진짜여야 한다 — 초보에게는 구원, 고난도에서는 함정.
- **SEEK 거래** `[본 개정 구체화]` — 시크 등장(7턴) 이후 조건부로 열린다. 손패·버림의 카드 1장을 시크에게 **영구 보관**시킨다: 덱에서 제거(압축)되고 호박 메아리를 얻는다(B2-링). DEFRAG와의 차이 — DEFRAG는 흔적 없는 삭제, SEEK 보관은 **엔딩·로그에 흔적이 남는 압축**이며 호박 경로(LAST ARCHIVE)를 기울인다. "덱을 다듬는 두 가지 방법이 서로 다른 결말을 만든다."
- 8턴 종료 이후의 BREAK에서는 `F`로 구매를 포기하고 **OPEN CHANNEL**을 열 수 있다(§10). Y/N 확인 1회.
- 8턴 이후 BREAK에는 현재 덱을 같은 컴파일 규칙(§10)으로 읽은 `지금 개방: 형태 / modifier / 강도`를 표시한다. 구매 전 상태의 예고이므로 “이번에 더 투자할지, 지금 상환할지”를 결정하는 정보다.
- 덱 최소/최대(B2-시작) 위반 선택은 불가.

## 7. CLEANUP — 정리와 셔플

- 사용·미사용 카드를 버림더미로 보낸다. CACHE 보관 카드는 보관 영역으로. 격리 카드·NOISE 처리.
- 드로우 더미가 부족하면 버림더미를 셔플해 채운다. **셔플은 내부 처리로 끝내지 않는다**: 짧은 정지 + 되감기/재탐색 연출 + 새로 산 카드가 섞이는 표시 + **덱 크기와 다음 셔플 예상 턴 표시**. 도미니언의 "한 바퀴 뒤 돌아오는 투자"를 눈에 보이게 만드는 것이 목적이다.

## 8. 64칸 3색 링 — 목표이자 관계 게이지

```text
청록   실제 메아리 — 에코     호박   보관 메아리 — 시크     자홍   모방 메아리 — 노아
```

### 메아리 칸의 데이터 모델 `[본 개정 구체화 — 정규화 패스]`

64칸 각각은 **색 하나가 아니라 두 속성의 조합**이다. 색(청록/호박/자홍)은 `state`의 표현일 뿐이고, 그 칸이 "복구 가능한 진짜"인지는 `origin`이 따로 기억한다 — 이 구분이 없으면 SYNC·SPONSOR가 찍어낸 합성 메아리를 DEFRAG·CHECKSUM이 "진짜"로 되살리는 모순이 생긴다(원문 리뷰 3-3·3-4).

```text
EchoCell {
  origin: REAL      // 실제 플레이 사건에서 생성 — 언젠가 청록으로 복구될 자격이 있다
        | SYNTHETIC // 노아·스폰서가 처음부터 합성 — 되돌릴 "원본"이 없다
        | UNKNOWN    // 판정 보류(시드 예외 처리용, 기본 사용 안 함)
  state:  LIVE      // 청록으로 표현
        | ARCHIVED   // 호박으로 표현
        | MIMICKED   // 자홍으로 표현
}
```

### 수급 시점 `[본 개정 구체화 — 원문 부록 F-7의 답]`

링은 **1턴부터 항상 보인다.** 일반 방송에서 소량이 차고, OPEN CHANNEL에서 대부분이 찬다. 이렇게 하는 이유: 엔딩 색이 플레이 중에 예측 가능해야 하고(검증 질문 8·15), 노아·시크와의 상호작용이 "최종전에서 갑자기"가 아니라 런 내내 누적되어야 한다.

| 시점 | 사건 | EchoCell 변화 |
|---|---|---|
| 일반 방송 | NØA SPONSOR 구매·사용 | 빈 칸에 `{SYNTHETIC, MIMICKED}` 신규 점등(자홍 +) |
| 일반 방송 | SEEK 거래 / 시크 탈취 방치 | 빈 칸에 `{REAL, ARCHIVED}` 신규 점등(호박 +) — 방치된 것은 실제 흔적이므로 origin은 REAL |
| 일반 방송 | 시크 엘리트 격퇴(탈취 반환), 일부 이벤트 | 빈 칸에 `{REAL, LIVE}` 신규 점등(청록 +) |
| 일반 방송 | DEFRAG로 NOISE 삭제 | `origin=REAL`이며 `state≠LIVE`인 칸 중 1개를 `LIVE`로 복구(청록 +, 소량) — **가려진 실제 흔적만 복구**, 새 칸을 만들지 않는다 |
| OPEN CHANNEL | ARCHIVE 실물 발동 | 빈 칸에 `{REAL, LIVE}` 신규 점등(청록 +, ECHO값만큼) |
| OPEN CHANNEL | 노아 공격 적중 | 기존 `{*, LIVE}` 칸 1개의 `state`를 `MIMICKED`로 덮어씀(청록 → 자홍). **`origin`은 바뀌지 않는다** — 나중에 CHECKSUM이 복구할 근거가 남는다 |
| OPEN CHANNEL | 시크 케이블 개입 | 기존 `{*, LIVE}` 칸 1개의 `state`를 `ARCHIVED`로 덮어씀(청록 → 호박), origin 유지 |
| OPEN CHANNEL | CHECKSUM | `origin=REAL`이며 `state=MIMICKED`인 칸만 `LIVE`로 복구(자홍 → 청록). `origin=SYNTHETIC`인 자홍 칸(스폰서가 만든 순수 합성)은 되돌릴 원본이 없으므로 대상 아님 |
| OPEN CHANNEL | 재송출 PROGRAM (P1+) | `origin=REAL`이며 `state=ARCHIVED`인 칸만 `LIVE`로 복구(호박 → 청록). `origin`이 REAL이 아닌 호박 칸은 대상 아님 |

일반 방송의 수급 상한(B2-링)은 **16칸**(64칸의 1/4) — 본체는 어디까지나 최종 방송이다. 신규 점등 이벤트(빈 칸에 칸을 추가하는 행)는 점등된 칸 수가 16에 도달하면 **초과분을 소실**시킨다(칸을 만들지 못하고 조용히 버림, 오류 아님). 이미 점등된 칸의 `state` 전환(색 전환)은 칸 수를 늘리지 않으므로 이 상한과 무관하게 항상 적용된다 — 색 전환 이벤트는 OPEN CHANNEL에서만 발생하므로 일반 방송 16칸 상한과 실질적으로 충돌하지 않는다.

### HUD 표현 `[본 개정 구체화 — 검증 질문 12의 답]`

- HUD 하단에 **64칸 세그먼트 스트립**(64×3px, 3색+빈칸) — 정확한 개수와 색 구성은 여기서 읽는다.
- 에코 스프라이트의 머리 링은 **8대구간 요약**만 표시(16×16의 한계를 설정으로 승격 — "HUD가 정밀 계기, 캐릭터가 요약 계기").
- OPEN CHANNEL에서는 링이 화면 전체 UI로 확장된다(에코의 링 승격 연출, [40](40_ART_AUDIO_TEXT.md) §4).

### 메아리 = 채팅 라인 `[본 개정 구체화]`

메아리 1개가 점등할 때마다 HUD 채팅 영역에 **채팅 한 줄**이 흐른다: 청록 = 알아들을 수 없는 인간 흔적(각기 다른 시대 타임스탬프, 깨진 문장) / 호박 = 날짜 라벨이 붙은 보관본(`[1997-08-14 저장됨]`) / 자홍 = **완벽하게 동일한 문장의 반복**(닉네임만 다름). 링의 의미를 튜토리얼 없이 채팅의 질감으로 가르친다 — "실제·보관·모방의 윤리적 차이가 대사 없이 플레이에 드러나는가"(검증 질문 15)에 대한 1차 답.

## 9. 적 설계 — 적은 HP가 아니라 덱의 서로 다른 층을 공격한다

- 군중감: 적끼리 겹치지 않는 **간단한 분리 벡터** — 추가 스프라이트 없이 밀림·흐름·밀도를 만든다([30](30_TECH.md) §10).

### 노아의 시그니처 — TREND MIRROR

게임은 PROGRAM별로 `CUE 횟수 / 실제 발동 횟수 / 적중 수 / 총 피해 / 사용 구절 수 / 최근 사용`을 기록하고, **가장 반복적으로 의존한 패턴**을 TREND로 선택한다. 기본 집계는 실제 발동 횟수 + **최근 6구절 가중치**, 갱신은 48 메아리에서 1회, 고난도는 상위 2개 조합 `[시드값]` — 단순 총피해 1위가 아니라 "습관"을 잡고, TREND BAIT(미끼 전략)를 가능하되 너무 쉽지 않게 한다. HUD에 학습 현황을 **숨기지 않고 보여 준다**: `NØA is learning: SURGE ×8`. 복제는 처벌이 아니라 관계다 — "네가 좋아하는 걸 나도 할 수 있어."

**모방은 색상 변경이 아니라 의미 반전이다** — 같은 문법이 가치관에 따라 뒤집힌다:

| 플레이어 기술 | NØA 모방 |
|---|---|
| FIREWALL — 안전 공간 생성 | 닫히는 사각 감옥 |
| SURGE — 적끼리 연결 | 플레이어와 적을 연결 |
| MARKER — 적에게 번호 | 에코와 안전 지대에 추적 번호 |
| CACHE — 카드 보존 | 준비 카드 하나를 복제·격리 |
| PREFETCH — 다음 카드 미리 보기 | 다음 프로그램을 미리 봉인 |
| MACRO — 직전 공격 재생 | 이전 공격을 반대 방향으로 되돌림 |
| MULTI — CUE 증가 | 가짜 NØA 초상 동시 생성 |
| CHECKSUM — 오염 복구 | 청록 메아리를 자홍으로 재서명 |

기술적으로는 기존 이펙트 레시피에 `palette=MAGENTA, target_rule=INVERT, motion=REVERSE`를 적용한 재사용이다 — 콘텐츠 비용이 거의 0이면서 14점 후보 1번을 만든다. 시각 구분: 에코의 MACRO는 **불완전한 기록**(픽셀 일부 누락), NØA의 복제는 **지나치게 완전하고 대칭**.

## 10. OPEN CHANNEL — 최종 60초

V1의 `GO LIVE`는 폐기·개명. 게임은 처음부터 생방송이므로 최종 단계는 **양방향 개방**이다.

```text
채널을 열까요?
  이후 구매 불가 / ARCHIVE 활성화 / 관객의 대답 수신 / OFFLINE까지 60초
```

- **조기 개방**(8턴 이후 BREAK): 엔진은 약하지만 노아 학습·NOISE 누적이 적고 기록이 단축된다. **강제 개방**: 12턴 종료 시 자동. 종결 시점 선택은 플레이어의 전략이다 — 빠른 러시 빌드와 늦은 완성형 엔진이 서로 다른 답이 되게 한다.
- 진입 연출(한 호흡): 짧은 정지 → 링이 화면 UI로 확장 → 팔레트 전환 → 적·탄 넉백으로 읽기 공간 확보 → OFFLINE 타이머 시작.

### OPEN CHANNEL의 실행 규칙 — 덱 컴파일 모델 `[본 개정 구체화 — 정규화 패스]`

원문 리뷰가 지적한 문제: "PROGRAM을 개별 재선택"하는 구조는 EDIT가 사라진 연속 실시간에서 조작 대상이 없다(더 이상 손패 개념이 없다). OPEN CHANNEL은 **개별 카드 조작이 아니라 진입 시점의 덱 컴파일**로 재정의한다 — 카드를 편성하는 게임이 끝나고, 편성한 결과가 그대로 재생되는 것이 "마지막 방송"의 정서다.

**진입 순간(1회, 컴파일)**: 그 시점까지 획득한 덱 전체를 읽어 셋을 나눈다.

1. **CARRIER 전체** → 이후 자동 TX 목록에 등록(더 이상 RX 지정 개념 없음 — 존재 이유가 사라지는 것 자체가 연출).
2. **ARCHIVE 다수 타입** → 최종 방송의 **기본 형태**를 결정(CHATSTORM/RESONANCE/FRAMECUT/OPEN ECHO 중 하나, [15](15_CARDS.md) §9).
3. **PROGRAM 태그 다수** → 그 형태 위에 얹히는 **수정자**(REPEAT/NETWORK/SAFE/REPLAY)로 등록. 최다 태그 장수는 `컴파일 강도`가 된다. 같은 계열을 여러 장 산 엔진은 이름만 같은 수정자가 아니라 더 빠르고 강한 최종 방송으로 상환된다.
4. **64칸 링의 색 비율** → 소유권·관계·엔딩(§11)을 결정 — 컴파일 대상이 아니라 OPEN CHANNEL 내내 계속 갱신된다.

**컴파일 이후 실행(자동)**:

- **모든 CARRIER는 전자동 TX** — 플레이어 조작 없이 계속 송출된다.
- **ARCHIVE는 고정 박자로 자동 발동**(OPEN_AUTO, §14 phase 표)한다. 발동 시 효과가 반전된다(무음 → 화면 장악 공격 + 청록 메아리) + **비용 반전(CUE 0)** — 일반 방송 내내 "슬롯만 차지하던" 부담이 공짜 필살기가 되는 대칭.
- **PROGRAM 카드는 개별 재선택하지 않는다.** 컴파일 시 등록된 수정자로서 상시 패시브로만 작용한다. REPEAT 강도 2+는 ARCHIVE 메아리를 추가 재생하고, NETWORK 강도 2+는 ARCHIVE 순환 간격을 단축한다. 모든 수정자는 강도에 따라 최종 프로토콜 쿨다운이 짧아진다. CUE 소모·손패 선택 UI가 존재하지 않는다.
- **Space는 최종 방송 프로토콜(OPEN_ACTIVE, §14)을 직접 발동**한다 — 컴파일된 형태+수정자 조합의 실제 이펙트를 재생하는 유일한 수동 입력. 쿨다운은 B2-공식.
- 시크·노아의 개입, 색 전환은 §8 표(EchoCell 모델). 동일 틱에 64 도달과 OFFLINE·HP0이 겹치면 **64 우선**(V1 원칙 유지).

3축 요약(§11과 동일 문장, 정규화): **최종 방송은 3축으로 결정된다 — ARCHIVE 구성이 형태를(CHATSTORM/RESONANCE/FRAMECUT/OPEN ECHO), PROGRAM 태그가 수정자를(REPEAT/NETWORK/SAFE/REPLAY), 64칸 링의 색이 소유권·관계·엔딩을.**

### 16·32·48·64 위상 변화

임계마다 1회, 수치 이득 없이 위상만 바꾼다(예상 수식을 바꾸지 않는 V1 버스트 원칙 유지 + 연출 확장):

- **16 — FIRST REPLY**: 첫 관객 음성 조각(또는 키보드 입력음). 카드 발동음에 실제 음성 레이어. 적탄 일부가 메아리 패킷으로 변환(화면 정리 1회). 에코가 반대쪽 귀를 잠깐 기울인다. HUD 채팅에 서로 다른 연도의 첫 실제 메시지 — 카메라는 흔들지 않고 배경의 한 시대층이 잠시 겹친다.
- **32 — CROSS CHAT**: 서로 다른 연도의 채팅 동시 표시. 직전 5장 손패가 축소 잔상으로 한 번 재생. 배경 팔레트가 과거·미래 사이에서 흔들리고 음악에 두 번째 시대의 음색 레이어. **청록·호박·자홍 비율이 처음으로 대구간에 표시**되고, 노아가 카드 사용 통계를 명시적으로 관찰하기 시작한다.
- **48 — MASK BREAK**: 노아의 프로필 환이 64개 관객 아이콘으로 분열(그로테스크 최고조). **TREND 확정·복제 본격화.** 시크 케이블이 화면 외부에서 링 한 구획을 붙잡음. 에코 초상은 공포가 아니라 **방송용 웃음을 잠시 놓치는** 표정.
- **64 — TWO-WAY**: **승리 확정.** 이후 6~10초는 실패 없는 카타르시스 구간. 연출 시퀀스: ① 모든 탄·적이 3틱 시간 팽창 ② 링 8대구간이 채워진 순서대로 한 번씩 울림 ③ 색 비율로 최종 방송 프로토콜 생성 ④ 덱 대표 카드 효과가 화면 전체 스케일로 한 번씩 재생 ⑤ 에코가 처음으로 반대쪽 귀를 기울여 관객 소리를 들음 ⑥ 엔딩 이미지 전환.

### 최종 방송 프로토콜

덱의 ARCHIVE 다수 타입 × PROGRAM 태그가 최종 방송의 형태를 만든다. 조합표는 [15_CARDS.md](15_CARDS.md) §9. "내가 만든 덱이 마지막 방송의 모양"이라는 상환의 정점.

## 11. 승리·실패·엔딩

```text
승리: OFFLINE 전에 링 64칸 완성 (HP > 0)
실패 A: OFFLINE (60초 만료)      실패 B: HP = 0
동일 틱: 64 도달 우선
```

64 도달 시 **색 구성으로 엔딩 판정** (임계·우선순위는 B2-링, 서사는 [05](05_WORLD.md) §12):

1. **UNRESOLVED ECHO** — 세 색이 모두 일정 이상이고 편차가 임계 이내 (+숨은 조건: 세 경로 카드 각 1회 이상 사용) → 진엔딩 후보
2. **PERFECT AUDIENCE** — 자홍 임계 이상
3. **LAST ARCHIVE** — 호박 임계 이상
4. **OPEN CHANNEL** — 그 외 (청록 우세, 기본 승리)

실패 표기: HP0 `STREAM LOST — UNSENT QUEUE REMAINS` / OFFLINE `CHANNEL CLOSED — 64 INCOMPLETE` + 우세 색별 마지막 문장. 정답 빌드는 알려주지 않되 원인은 숨기지 않는다.

이 절이 다루는 것은 3축 중 **세 번째 축**(64칸 링의 색 → 소유권·관계·엔딩)뿐이다. 나머지 두 축(ARCHIVE 구성 → 형태, PROGRAM 태그 → 수정자)은 §10 "최종 방송 프로토콜"에서 결정되며, 문장은 §10과 동일하다.

### 결과 화면과 즉시 재시작

```text
ENTER  같은 신호 재접속 (시장·의도·웨이브·셔플 동일)   RIGHT  새 신호 탐색   TAB  방송 기록
```

**실패 → 다시 조작 가능까지 1초 미만.** 상세는 [45](45_UI_UX.md) §11.

결과 화면은 실패를 하나로 뭉개지 않는다. 체력 0은 `체력 0 / 송출 중단`과 `이동·송신·방벽 조정`, OPEN CHANNEL 시간 종료는 `64 미완성 / 채널 종료`와 `기록·같은 계열 투자`를 표시한다. 두 경우 모두 도달 구절을 남겨 같은 시드 재시도의 진전을 비교한다.

### 이전 방송 리플레이 — 기술이 세계관이 된다 (P2)

결정론 명령 로그([30](30_TECH.md) §5)로 이전 런의 이동·CUE를 저장할 수 있다(6분 틱당 1바이트 ≈ 21.6KB, 저장 파일 측). 기본 용도: 디버그 리플레이·TODAY 재현·버그 신고 입력 로그. **콘텐츠 용도**: 세 번째 런부터 호박색 "이전 방송 에코"가 잠깐 나타남 / 시크가 이전 런의 프로그램 타이밍을 재생 / NØA가 이전 성공 빌드를 학습 / 결과 화면에서 과거·현재 에코의 이동 경로 비교 / 특정 엔딩에서 **이전 실패 에코가 현재 방송에 한 번 응답**.

### 해금 원칙 — 숫자가 아니라 가능성이 넓어진다

- **해금한다**: PROGRAM, 시작 덱, 적 의도, 시간층, 감사 프로토콜, NØA SPONSOR, 시크 거래, 최종 프로토콜 수정자, 방송 로그, 키아트, 모델 시트, 팔레트, 엔딩, 도전 모드.
- **해금하지 않는다**: 영구 공격력·HP·시작 CUE·영구 BAUD·적 피해 감소 — **반복 횟수가 덱 판단을 대체해서는 안 된다.**
- 해금·기록은 저장 파일 1개(64~256B, [30](30_TECH.md) §8). V1의 "파일 I/O 없음" 원칙은 폐기(ADR-0006).

## 14. 카드 해석 순서와 상한 — 구현 분쟁 방지 규칙

V1 §4의 역할을 V2로 계승한다. 카드 목록·수치는 B2-카드, 개별 설계는 [15](15_CARDS.md).

### 카드 단계(phase) 정의 `[본 개정 구체화 — 정규화 패스]`

모든 카드는 정확히 하나의 phase를 가지며, 아래 발동 규칙은 **카드 이름이 아니라 phase에 귀속**된다 — "이 카드가 특별해서"가 아니라 "이 phase에 속해서" 이렇게 동작한다. 개별 카드의 phase 배정표는 [15](15_CARDS.md) §2.

| phase | 발동 시점 | 대표 예 |
|---|---|---|
| `EDIT_IMMEDIATE` | EDIT 중 선택 즉시 처리되고 손패에 남지 않음 | MULTI, CACHE, PREFETCH, MARKER(드로우 효과) |
| `EDIT_QUEUE` | EDIT에서 선택, ON AIR 진입 시 손패에 실려 대기 | 일반 CARRIER·PROGRAM 편성 |
| `ON_AIR_ACTIVE` | ON AIR 중 Space로 수동 발동 | PAYLOAD형 PROGRAM |
| `ON_AIR_PASSIVE` | ON AIR 내내 상시 적용, 별도 발동 없음 | FIREWALL 등 필드 효과 |
| `REACTION` | 특정 트리거(피격·근접 등)에서 자동 발동 | 일부 방어형 카드 |
| `BREAK_CONTRACT` | BREAK에서 구매, 명시된 미래 시점(주로 다음 EDIT·ON AIR 1회)에 발동 | NØA CONTRACT 계열(구 SPONSOR, [15](15_CARDS.md) §7) |
| `OPEN_AUTO` | OPEN CHANNEL 진입 시 컴파일되어 고정 박자로 자동 발동, 개별 재선택 불가 | ARCHIVE(§10) |
| `OPEN_ACTIVE` | OPEN CHANNEL에서 Space로 발동하는 최종 방송 프로토콜 1개 | 최종 방송 프로토콜(§10) |

0. **EDIT 확정 순서**: 드로우 → 의도 공개 → (SEEK, TX/RX 지정, PROGRAM 선택은 자유 순서로 반복 가능) → EDIT 종료 시점에 일괄 확정. SEEK로 CARRIER를 교체하면 그 카드의 TX/RX 지정은 소멸하고 새 카드는 재지정한다 — **지정은 카드가 아니라 슬롯이 아닌, "이번 턴의 그 카드"에 붙는다.** `[본 개정 구체화]`
1. **다음 발동 시점은 한 함수에서 명시적으로 계산한다.** 지연 = 손패 교체 지연 + 활성화 지연의 **합**이며 서로 대체하지 않는다. 타이머는 "N틱 후 발동"이 정확히 N틱이도록 구현·테스트한다(V1의 30→31틱 결함 재발 방지, [30](30_TECH.md) §3).
2. 손패 경계를 넘는 modifier는 **손패 재구성이 끝난 뒤의 실제 다음 카드**에 적용한다. 마지막 카드가 MULTI면 다음 손패의 첫 선택 PROGRAM이 가속된다.
3. MACRO는 직전 수동 PROGRAM/PAYLOAD의 **형태 전체**를 재생한다(수치만 복사 금지). 복사 강도의 반올림은 **최근접 반올림, 최소 1** — 작은 수치 게임에서 내림은 70%를 50%로 만든다.
4. **LINK!는 실제 효과가 적용됐을 때만** 표시한다. 카드 이름 순서만으로 판정하지 않는다 (복사할 payload가 없는 `MULTI→MACRO`는 LINK가 아니다).
5. PREFETCH·SEEK로 손패가 재배치되면, **다음 발동 대상을 먼저 확정한 뒤** 그 카드에 대한 지연·modifier를 계산한다.
6. 상태 전환(강제 OPEN CHANNEL 등)을 호출하면 **즉시 return** — 같은 틱에 이전 상태의 스폰·이동·발동·링 변경이 실행되지 않는다.
7. 한 카드 발동의 추가 피해 이벤트 상한 8. 초과는 버린다.
8. 메아리 색 전환은 틱당 소스별 1회로 제한(B2-링) — 전환 루프 방지.

## 15. UX·온보딩·접근성

### HUD 불변 조건 (레이아웃·상세 규칙은 [45_UI_UX.md](45_UI_UX.md))

- 상시: `TURN N/12` / HP / **SYNC** / CUE / SEEK 잔여 / 64칸 링(전투 중 8대구간+`N/64`) / NEXT 의도. BREAK: BAUD 합. OPEN CHANNEL: 링 확장 + OFFLINE 잔여의 반대 방향 막대.
- 카드는 한글 라벨 + 아이콘 + 상태(선택됨/TX/RX/OFF AIR/봉인/NOISE). 색만으로 구분하지 않는다 — 타입은 모서리 형태, TX/RX는 포트 방향([45](45_UI_UX.md) §1~2).
- 발동 카드에서 실제 효과가 출발하는 궤적 표시 — `카드→효과` 인과 연결. ARCHIVE는 일반 방송에서 공격처럼 보이거나 들리면 안 된다.
- 노아 학습 현황 `NØA is learning: ___`은 5턴부터 상시 노출.

### 온보딩 — 3구절 단계 공개 + 자동 추천 `[본 개정 구체화]`

1. (첫 EDIT) `방송할 카드를 고르세요. 지금은 시간이 멈춰 있습니다.`
2. (첫 ON AIR) `움직이며 버티세요. Space로 준비한 프로그램을 내보냅니다.`
3. (첫 BREAK) `BAUD로 1장 — 산 카드는 셔플 뒤에 돌아옵니다.`

첫 구절은 MULTI 포커스와 `송신 1 / 수신 1` 기본값으로 시작한다. MULTI 확인 뒤 FIREWALL로 포커스를 넘겨 두 번째 확인을 안내하고, **편성→Space 발동→구매**를 한 번 완주시킨다. 첫 ON AIR에는 `WASD 이동 / Space 송출`, 첫 BREAK에는 첫 응답 BAUD 보너스와 구매 가능한 CHAT 포커스를 제공한다. 2구절은 TX/RX, 3구절은 다음 의도와 실시간 입력을 한 줄로 다시 보여 준다. 세계관·시대 모순·메아리 색은 튜토리얼에서 설명하지 않는다 — 채팅의 질감(§8)과 로그가 가르친다.

### 접근성·안전

`M` 즉시 음소거 / `F1` 저자극(플래시·흔들림 0, 규칙 불변) / `ESC` 일시정지 / EDIT 완전 정지 기본 / Space 길게 자동 발동 / TX/RX 자동 배정 옵션. 백색 플래시 최대 2프레임, 흔들림 최대 2px, 오염 노이즈 고정 패턴·빠른 점멸 금지. 전체 목록은 [45](45_UI_UX.md) §9.
