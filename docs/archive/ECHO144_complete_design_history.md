> 문서 상태: 대화 통합본 / 설계 정리본  
> 기준: 현재 대화에서 공개적으로 논의된 모든 분석, 피드백, 제안, 수정안, 폐기안, 보류안, 우선순위를 중복 없이 통합  
> 프로젝트: `dusaud8887-svg/1_44mb_game`

> 핵심 제약: 최종 배포물 1.44MB 이하

## 0. 이 문서의 목적과 읽는 법

이 문서는 지금까지의 대화에서 나온 내용을 단순 요약하지 않고 다음 네 층으로 재구성한다.

1. **현행 프로젝트 분석**: 기존 코드, 문서, 빌드, 픽셀 아트, 게임 규칙의 장점과 결함.
2. **기획 진화 과정**: 처음 제안된 설정에서 어떤 아이디어가 왜 수정·폐기되었는지.
3. **현재 권장 정본**: 세계관, 캐릭터, 플레이 구조, 카드, 적, 최종전, 엔딩, 반복 플레이.
4. **구현 계획**: 기술 스택, 라이브러리, 코드 구조, 테스트, 압축, 확장판 대응.

표기는 다음 의미를 가진다.

- **현재 정본**: 앞으로 설계와 구현의 기본값으로 삼을 권장안.
- **유지**: 기존 설계에서 계속 가져갈 요소.
- **대체**: 기존 요소를 다른 개념으로 바꿀 것.
- **폐기**: 더 이상 정본으로 사용하지 않을 것.
- **보류**: 아이디어는 유효하지만 코어 검증 뒤 도입할 것.
- **내부 정답**: 제작진은 알고 있으나 플레이어에게 직접 설명하지 않을 설정.
- **의도적 공백**: 제작진도 단일 정답을 확정하지 않거나, 작품 안에서 끝까지 답하지 않을 질문.

이 문서는 대화에서 공개적으로 주고받은 내용을 통합한다. 동일한 제안이 여러 차례 나온 경우 최신 결정에 맞춰 합치고, 이전 버전은 결정 이력에 남긴다.

# 1부. 프로젝트 전체 진단

## 1. 프로젝트의 원래 강점

ECHO/144는 단순히 작은 게임이 아니라, **1.44MB라는 물리적 제약에서 기술·미학·서사를 역산한 프로젝트**라는 점이 가장 강하다.

원래 프로젝트가 이미 잘하고 있던 부분은 다음과 같다.

- 단일 EXE, 무설치, 외부 런타임 없음.
- C11과 Win32 API를 사용해 결과물 크기와 동작을 직접 통제.
- 320×240 저해상도, 제한 팔레트, 2bpp/4bpp 픽셀 자산.
- GDI 소프트웨어 렌더링과 `waveOut` 기반 절차적 오디오.
- 고정 60Hz 틱과 명시적 난수 시드.
- 고정 크기 배열을 사용해 힙 할당과 단편화를 피함.
- 빌드 결과의 정확한 바이트 크기를 검사.
- DLL 의존성, SHA-256, 테스트 빌드를 빌드 스크립트에 포함.
- `docs/`에 비전, 메커니즘, 밸런스, 기술, 아트, 제작 게이트를 분리.
- 자동 시뮬레이션과 사람 플레이테스트를 서로 다른 검증 층으로 인식.
- 기능을 추가하는 목록뿐 아니라 잘라낼 목록과 실패 기준을 문서화.

이 프로젝트의 좋은 출발점은 “C로 만들었기 때문에 작다”가 아니라 다음 결과물을 먼저 정했다는 데 있다.

```text
1.44MB 이하
단일 Windows EXE
무설치
짧은 단판
픽셀 아트
절차적 오디오
결정론적 테스트
```

그 결과 Win32, GDI, `waveOut`, 고정 배열, 빌드 타임 생성 도구라는 선택은 현재 공모전판에 매우 잘 맞는다.

# 2부. 코드·문서 심층 분석

## 3. 현행 코드의 가장 중요한 정확성 문제

### 3.1 P0: 이동 정수 절삭으로 인한 방향 비대칭

플레이어와 적의 위치는 `float`이지만, 매 틱 위치를 더한 뒤 `int`로 바꾸어 clamp하고 다시 `float`에 저장하는 패턴이 있었다.

플레이어 속도가 초당 54픽셀, 60Hz라면 한 틱은 0.9픽셀이다.

```text
100 + 0.9 → 100.9 → int 100
100 - 0.9 →  99.1 → int  99
```

따라서 정수 좌표에서 시작하면 다음과 같은 심각한 비대칭이 생길 수 있다.

| 입력 | 발생 가능한 실제 동작 |
|---|---|
| 오른쪽 | `+0.9`가 매번 잘려 거의 이동하지 않음 |
| 아래쪽 | `+0.9`가 매번 잘려 거의 이동하지 않음 |
| 왼쪽 | 매 틱 -1, 약 60px/s |
| 위쪽 | 매 틱 -1, 약 60px/s |
| 우하향 대각선 | 두 축 이동이 사라질 수 있음 |
| 좌상향 대각선 | 두 축이 -1이 되어 과속 |

적 속도는 한 틱당 1픽셀보다 훨씬 작기 때문에 생성 방향에 따라 추적 능력이 완전히 달라질 수 있다.

#### 수정 원칙

- 게임 상태의 좌표는 끝까지 `float` 또는 고정소수점으로 유지.
- clamp도 실수형 함수 사용.
- 렌더링할 때만 정수 좌표로 변환.

```c
static float clamp_f32(float value, float low, float high)
{
    if (value < low) return low;
    if (value > high) return high;
    return value;
}
```

#### 필수 테스트

```text
60틱 RIGHT  → 약 +54px
60틱 LEFT   → 약 -54px
60틱 DOWN   → 약 +54px
60틱 UP     → 약 -54px
```

추가 검증:

- 8방향 이동 거리 대칭.
- 네 방향에서 생성된 동일 적의 중심 도달 시간.
- 밀쳐내기 이후 소수 좌표 보존.
- 장시간 경계 이탈 없음.

### 3.2 P0: 카드 스케줄러가 문서 공식과 다름

문서 의도는 기본 카드 간격 30틱, 손패 교체 비용 15틱이었다.

```text
30 × 카드 수 + 15 × ceil(카드 수 / 5)
```

하지만 구현은 손패 교체 시 15틱이 기본 30틱에 더해지지 않고 대체되었고, 타이머 감소 방식 때문에 30이 실제 31틱, 15가 실제 16틱으로 동작할 가능성이 있었다.

10장 덱 예시:

```text
문서 공식   30×10 + 15×2 = 330틱
구현 추정   31×8 + 16×2 = 280틱
```

이 차이는 카드 발동량, SIGNAL 수급, 생존, 시뮬레이션 기준선을 모두 바꾼다.

#### 권장 스케줄 모델

```text
다음 카드 지연
= 손패 교체 지연
+ 활성화 지연
```

| 상황 | 교체 | 활성화 | 합계 |
|---|---:|---:|---:|
| 일반 카드 | 0 | 30 | 30 |
| 손패 경계 | 15 | 30 | 45 |
| MULTI + 손패 경계 | 15 | 0 | 15 |
| PREFETCH + 손패 경계 | 15 | 3 | 18 |

핵심은 정확한 수치보다도 **다음 발동 시점을 한 함수에서 명시적으로 계산하는 것**이다.

---

### 3.3 P1: 손패 경계에서 modifier 의미가 깨짐

#### 마지막 카드가 MULTI인 경우

마지막 카드가 `MULTI`이면 다음 손패 첫 카드가 가속되어야 하지만, 구현 흐름에 따라 첫 카드가 실행된 뒤 두 번째 카드가 가속될 수 있었다.

#### `MULTI → MACRO`의 거짓 `LINK!`

실제 복사할 이전 공격 payload가 없는데도 카드 이름 순서만 맞으면 `LINK!`가 표시될 수 있었다.

피드백은 카드 이름 순서가 아니라 **실제 효과 적용 여부**를 기준으로 해야 한다.

#### MACRO 70% 정수 반올림

```text
4 damage × 70% → 정수 내림 시 2 = 실제 50%
7 damage × 70% → 정수 내림 시 4 = 실제 57%
```

작은 수치가 많은 게임에서는 반올림 규칙을 명시해야 한다.

#### PREFETCH와 SEEK의 결합

손패 재배치 이후 어떤 카드가 다음 발동 대상인지 확정한 뒤, 그 카드에 대한 지연과 modifier를 계산해야 한다.

---

### 3.4 P1: 강제 상태 전환 후 같은 틱 로직이 계속 실행됨

강제 LIVE 또는 상태 전환을 호출한 뒤 즉시 반환하지 않으면 같은 틱에 다음 로직이 더 실행될 수 있다.

- 적 생성.
- 적 이동과 공격.
- 탄환 처리.
- 카드 발동.
- SIGNAL 변경.
- 새 상태 타이머 증가.

원칙:

```c
if (forced_transition) {
    start_new_state();
    return;
}
```

상점에서 수동 전환한 경로와 강제 전환한 경로의 진입 직후 상태도 비교 테스트해야 한다.

### 3.5 P0/P1: GDI 텍스트 출력 문제

#### `COLORREF` 채널 순서

DIB 픽셀 상수의 `0x00RRGGBB` 값을 그대로 `COLORREF`에 캐스팅하면 빨강과 파랑 채널이 뒤집힐 수 있다.

```c
static COLORREF rgb24_to_colorref(uint32_t rgb)
{
    return RGB(
        (rgb >> 16) & 0xff,
        (rgb >> 8) & 0xff,
        rgb & 0xff
    );
}
```

#### 텍스트 배경 모드

백버퍼 DC 생성 직후 다음 설정이 필요하다.

```c
SetBkMode(back_dc, TRANSPARENT);
SetTextAlign(back_dc, TA_LEFT | TA_TOP);
```

#### 시스템 폰트 의존성

`GulimChe`가 없는 환경, 언어팩, fallback 폭 변화는 320×240 UI에서 큰 문제다.

장기 권장안:

- 게임에서 실제 사용하는 한글 글리프만 1bpp 비트맵 폰트로 내장.
- ASCII와 숫자도 동일 픽셀 폰트 사용.
- GDI 텍스트 호출 제거 또는 디버그용으로만 유지.

#### 정수 배율과 레터박스

임의 창 크기에 `StretchBlt`하면 픽셀 비율이 깨진다.

```text
scale = max(1, min(client_w / 320, client_h / 240))
draw_w = 320 × scale
draw_h = 240 × scale
offset_x = (client_w - draw_w) / 2
offset_y = (client_h - draw_h) / 2
```

## 5. 문서 구조 평가

### 5.1 좋은 점

현행 문서는 다음 순서를 가진다.

```text
왜 만드는가
→ 무엇을 하는가
→ 수치는 어떻게 잡는가
→ 기술적으로 어떻게 구현하는가
→ 어떻게 보이고 들리는가
→ 어떤 게이트를 통과해야 출시하는가
```

또한 다음을 이미 잘 구분한다.

- 자동 시뮬레이션: 수치와 불변식 검증.
- 사람 테스트: 재미, 학습, 가독성 검증.
- 첫 재미 시점과 플레이 시간 약속.

## 7. 현행 비주얼의 강점

현행 아트는 이미 단순 기능 그래픽을 넘어 다음 고유 문법을 구축했다.

```text
에코   청록 / 끊긴 링 / 송출
시크   호박 / 깨진 버퍼 링·케이블 / 붙잡음
포맷   자홍 / 진행 막대·수직 프레임 / 닫음
```

좋은 점:

- 캐릭터가 머리색뿐 아니라 **동사와 반복 도형**으로 구분된다.
- `1997`, `A:\>`, 플로피, `NO CARRIER`가 복고 장식이 아니라 서사 원인으로 사용된다.
- 인간형 캐릭터와 팝업·자물쇠·플로피·패킷 같은 시스템 사물의 조형 언어가 다르다.
- 밝고 귀여운 화면 아래 시간 오류와 소멸의 잔향이 있다.
- 흔한 교복·메이드·고양이귀·노출 중심의 사이버 미소녀 대신, 직무와 행동의 갭으로 모에를 만들려 한다.

## 8. 캐릭터별 기존 아트 점검

### 8.1 에코 일사사

#### 장점

- 밝은 청록 면적이 커서 주인공성이 강함.
- 큰 눈과 미소가 방송 진행자 이미지를 줌.
- 비대칭 롱 스트랜드와 끊긴 링이 실루엣을 만듦.
- 흰색·청록·검정 체크가 90년대 디지털 방송 의상처럼 보임.
- 빨간 LIVE 핀이 작은 서사 포인트.

#### 약점

- 정면 대칭성이 강해 개성 있는 인물보다 귀여운 아바타 아이콘처럼 보일 때가 있음.
- 두 눈썹, 눈 높이, 입 위치가 너무 정돈됨.
- 하단 의상이 수평 막대처럼 보여 재킷 구조가 약함.
- 16×16에서 흰 비대칭 재킷이 거의 사라짐.
- 체크 패턴이 작은 화면에서 노이즈가 될 수 있음.

#### 기존 수정 제안

- 한쪽 눈썹 1픽셀 차이.
- 입 중심 1픽셀 이동, 한쪽 입꼬리 강조.
- 긴 옆머리와 뒷머리 사이 어둠 1픽셀.
- 흰 재킷 사선 라펠.
- 체크 패턴 축소.
- 빨간 LIVE 핀 위치 통일.
- 16×16 몸통의 좌우 비대칭 강화.
- 링 끊긴 방향을 모든 표현에서 통일.

### 8.2 시크 웜

#### 장점

- “첫 방송인데 세 번째부터 봤다”는 한 줄이 강한 과거를 암시.
- 낮고 귀여운 실루엣과 불길한 관찰자 역할의 충돌.
- 호박 링과 리본 케이블은 팬아트 소품으로 좋음.
- 팬·아카이버·기생체·이전 에코 등 여러 해석 가능.

#### 약점

- 48×48 인간형 두 눈 초상.
- 16×16 외눈·바이저 웜 셸.
- 키아트의 어둠 속 한 눈.

세 표현이 의도적으로 다른 것인지 디자인이 통일되지 않은 것인지 불명확했다.

#### 기존 해결안

이 차이를 설정으로 승격한다.

```text
48×48 초상 = 채널이 보여 주는 방송용 아바타
16×16 스프라이트 = 회선 내부의 버퍼 셸
키아트의 눈 = 관찰자의 흔적 또는 불완전한 인식
```

모든 표현에 남길 브리지:

- 같은 방향으로 끊긴 호박 링.
- 리본 케이블.
- 한쪽 눈이 완전히 읽히지 않는 구도.
- 같은 송곳니 또는 입꼬리.

### 8.3 포맷 제로의 기존 아트

이 캐릭터는 이후 기획에서 **노아 NØA로 대체**되지만, 기존 자산은 재사용 가치가 높다.

#### 장점

- 자홍·검정의 수직 실루엣.
- 반개한 눈.
- 검은 히메컷.
- 진행 막대 칼라.
- 과잉 정중한 종료 관리자라는 갭.

#### 약점

- 팬이 반복해 그릴 행동 습관이 부족.
- 무심한 다정함보다 단순 무표정으로 보임.
- 흰 장갑·제복이 16×16에서 살아남지 않음.
- 작은 스프라이트는 관리자보다 자홍 모놀리스에 가까움.

#### 기존 수정 제안

- 입을 1픽셀 옮긴 예의상 미소.
- 한쪽 속눈썹과 자홍 림 비대칭.
- 4구간 중 3구간만 채운 진행 막대.
- 흰 장갑으로 종료 탭을 누르거나 프레임을 정돈하는 동작.
- “화면 테두리를 정돈한다”는 행동 습관.

이 자산과 행동은 후술할 노아의 외형과 모션으로 대부분 승계한다.

## 10. 키아트·로고·아이콘 평가

### 10.1 `keyart_last_live`

가장 강한 이미지였다.

```text
에코 큰 얼굴
→ 신호선
→ 어둠 속 호박색 눈
```

강화 제안:

- 신호 비트가 눈에 가까워질수록 하나씩 사라짐.
- 완전 수평선보다 1~2픽셀 높낮이.
- 호박 링 일부를 프레임 밖으로 잘라 크기 추정 불가.
- 에코 하단 수평 몸통 디테일 축소.
- 워드마크를 위한 네거티브 스페이스 확보.

### 10.2 기존 `keyart_main`

개념 설명은 잘하지만 세 인물이 상자 속 머리처럼 분리되어 설정 다이어그램처럼 보였다.

권장 원칙:

- 세 초상 배치가 아니라 한 사건.
- 에코는 보내고 있음.
- 시크는 붙잡고 있음.
- 적대자는 화면·관객·연결을 침식하고 있음.
- 시선과 신호선이 한 흐름을 형성.

### 10.3 로고

기존 타이틀은 GDI 글꼴 의존성이 강하고 브랜드 워드마크가 약했다.

권장 워드마크:

```text
에코/144
ECHO/144
```

- `/` 또는 `O` 하나를 끊긴 링으로 사용.
- 빨간 LIVE 핀 또는 한 픽셀 커서 하나만 강조.
- 모든 세계관 기호를 로고 안에 넣지 않음.
- 본문 글꼴과 타이틀 로고의 역할 분리.

### 10.4 카드 아이콘

잘 읽히는 아이콘:

- 2400 / 14K / 56K 단계형 모뎀.
- BAD의 큰 X.
- DEFRAG의 분할 블록.
- MULTI의 겹친 카드.
- FIREWALL의 벽.
- TROJAN 선물상자.
- RANSOM 자물쇠.
- 플로피 상자.

재설계 권장:

- WORM: 기어가는 몸과 굽은 꼬리.
- PATCH: 렌치형 단순 실루엣.
- PREFETCH: `>>`와 빈 슬롯.
- MACRO: 동일 모양 2개와 되돌림 화살표.
- CACHE: 층을 이루며 옆으로 밀린 저장 블록.

카드군 색 분류:

- CARRIER/모뎀: 청록.
- 유틸리티·보관: 호박 보조 픽셀.
- 아카이브: 회색에서 최종 단계에 청록·호박·자홍으로 변화.
- 오염: 빨강.
- 현재 선택 카드: 흰색 전체 테두리.

## 12. 미스터리와 2차 창작 기반

기존 기획은 존재론적 공백이 강했지만 생활 공백과 관계 공백은 약했다.

| 공백 | 상태 |
|---|---|
| 존재론적 공백 | 강함 |
| 관계 공백 | 중간 |
| 생활 공백 | 약함 |

2차 창작을 돕는 공식 소재:

### 에코

- 빨간 LIVE 핀.
- 지워진 마지막 큐시트.
- 끊긴 64칸 링.
- 한쪽 수신 헤드셋.

# 4부. 콘셉트의 진화와 결정 이력

## 13. 최초 콘셉트와 그 장점

초기 통합안은 다음과 같았다.

> 1997년의 존재하지 않아야 할 폐쇄 사설망 또는 `NODE 09`에 미래의 가상 방송 `ECHO/144`가 연결된다. 단 한 명의 시청자가 방송을 보고, 에코는 종료 관리자 `FORMAT/0`보다 먼저 64개의 신호를 보내려 한다.

이 버전의 장점:

- 1997, 미래 방송, 한 명의 시청자, `NO CARRIER`가 강한 분위기를 만듦.
- `송출한다 / 붙잡는다 / 닫는다`라는 세 캐릭터 동사가 명료함.
- 64라는 숫자를 게임 목표와 캐릭터 링에 연결하기 쉬움.
- 1.44MB와 구형 네트워크 미학을 세계관에 직접 연결 가능.

하지만 사용자의 추가 피드백을 통해 다음 한계가 드러났다.

- “폐쇄 사설망이어야 하는 이유”가 게임에서 설득되지 않음.
- `NODE 09`가 즉시 이해되는 고유명사가 아님.
- 방송인지 인터넷 방송인지 표현이 애매함.
- 플레이어가 시청자인지 에코인지 원격 편집자인지 관점이 흔들림.
- 한 명의 시청자와 만석 농담이 추상적이고 감정적으로 약함.
- 왜 방송을 보내며, 왜 방해가 있고, 왜 시청자가 보는지 5-Why가 필요함.
- 도미니언형 덱빌딩과 뱀서형 전투가 세계관에서 따로 놀고 있음.
- `FORMAT/0`이 방송 종료 관리자라는 설정은 위험하고 매력적인 적보다 시스템 기능처럼 느껴짐.
- `반송 주소`, `반송 신호`가 어렵고 훅이 약함.
- 자동 카드 실행이 전략 선택을 빼앗음.

## 14. 중간 개정안: 폐국한 1회선 BBS `MIMEI HOST-09`

첫 번째 대규모 개정에서는 폐쇄 사설망을 실제 역사적 감각이 있는 **폐국한 단일 회선 로컬 BBS**로 바꾸었다.

제안된 이름:

```text
미명통신 제9호스트
MIMEI HOST-09
미명 9번국
9번 회선
```

이 안의 논리:

- 단일 회선이면 한 명의 접속자가 곧 만석이 됨.
- 자료실에서 파일을 받는 구조가 카드 구매와 연결됨.
- 접속 제한과 `NO CARRIER`가 자연스러움.
- 1997년 PC통신 미학을 직접 활용 가능.
- 2097의 두 자리 연도 `97`이 1997로 오인되는 타임스탬프 오류.
- 플레이어는 1997년의 유일한 수신자이자 원격 편집자.
- 에코·시크·포맷은 원래 하나의 미래 방송 시스템에서 분리된 세 프로세스.

이 버전에서 정리된 좋은 아이디어:

```text
ECHO/144 = 출력·진행·송출
SEEK.WRM = 색인·복구·보존
FORMAT/0 = 무결성·정리·종료
```

또한 1.44MB, 5장 큐, 한 번의 구매, DEAD AIR, GO LIVE를 다음처럼 세계관화했다.

- 에코는 자신과 디코더를 플로피 한 장 분량으로 압축.
- 구형 수신기가 한 번에 5개 큐만 처리.
- 회선 휴지 시간에 자료실 파일 하나 다운로드.
- 미래 조각은 1997년 디코더가 해석하지 못해 무음.
- GO LIVE에서 원시 미래 포맷을 직접 흘려보냄.

### 왜 최종 정본에서 폐기되었는가

사용자 피드백:

- 폐국한 1회선과 단 한 명의 수신자는 감정적으로 잘 와닿지 않음.
- 여러 시청자가 봐도 되는 이야기를 불필요하게 좁힘.
- 인터넷 어딘가에 갑자기 나타난 방송이 더 범용적이고 상상력이 큼.
- 플레이어를 원격 편집자로 정의하면 주인공과 조작 감정이 분리됨.
- 미래에 사람이 모두 사라졌고, 존재할지 모르는 관객을 향해 방송한다는 이미지가 더 강함.

따라서 `MIMEI HOST-09`는 현재 정본이 아니다. 다만 다음 요소는 재사용할 수 있다.

- 특정 시간층 또는 스테이지 이름.
- 1997 PC통신 테마의 한 챕터.
- 과거 네트워크 인터페이스 스킨.
- 숨겨진 로그 속 호스트명.

## 16. 작품 한 문장

> **사람이 사라진 미래의 마지막 가상 진행자 에코는 여러 시대의 인터넷에 목록에 없는 생방송을 띄운다. 64개의 메아리가 돌아오면 관객의 목소리를 들을 수 있지만, 모든 시청자를 흉내 내는 최초의 관리자 노아가 그 대답을 먼저 채우려 한다.**

또는:

## 17. 세계의 표면 설정

미래의 어느 시점, 인간의 활동은 완전히 끊겼다.

확실한 것은 다음뿐이다.

- 도시, 서버, 자동 서비스, 추천 시스템, 콘텐츠 생성기는 계속 작동한다.
- 예약 방송도 실행된다.
- 광고와 자동 댓글도 남아 있다.
- 그러나 새로운 인간 입력과 응답만 없다.

에코 일사사 `ECHO/144`는 인간이 사라진 뒤에도 예정된 방송을 계속한다.

에코에게 방송은 직업이면서 인격 유지 장치다. 방송을 멈추면 에코의 상태도 점차 해체된다.

오랫동안 아무 대답도 돌아오지 않자 에코는 자신을 최소 송출체 `ECHO144.EXE`로 압축하고, 일반 네트워크가 아니라 서로 다른 시대와 차원의 통신망 사이로 방송을 흘려보낸다.

이 방송은 다음과 같은 곳에 불규칙하게 나타날 수 있다.

- 1997년 PC통신 자료실.
- 폐쇄된 개인 홈페이지.
- 2000년대 미디어 플레이어.
- 2020년대 목록에 없는 라이브 링크.
- 존재하지 않는 게임 런처.
- 미래의 빈 서버.
- 오래된 플로피 이미지.
- 삭제된 캐시 파일.

각 시대의 관객은 서로 다른 UI로 같은 방송을 본다.

## 19. 1997의 현재 역할

1997년은 고정된 장소나 한 명의 시청자가 있는 시대가 아니다.

> **1997은 에코의 차원 신호가 모든 시대에 남기는 잘못된 타임스탬프다.**

어디에 나타나든 파일은 다음과 같은 모순을 보인다.

```text
FILE       ECHO144.EXE
SIZE       1.44 MB
DATE       1997-??-??
STREAM     LIVE
ORIGIN     2097-??-??
```

한 프레임 동안만:

```text
1997 → 2097 → 1997
```

내부적으로 다음 후보를 둘 수 있다.

1. 실제 발신 연도는 2097이며 두 자리 연도 또는 구형 포맷이 `97`로 잘못 해석.
2. 1.44MB 최소 송출체의 헤더에 고정된 최초 생성 연도가 1997.
3. 에코가 과거 네트워크와 호환하기 위해 의도적으로 1997이라는 가장 오래된 안전 연도를 사용.
4. 시간층을 통과할 때 모든 연도에서 앞 두 자리가 탈락.

현재 권장 내부 정답은 **2097의 신호가 구형 송출 포맷에서 1997로 오인된다**는 것이지만, 게임 안에서는 직접 설명하지 않는다.

## 20. 핵심 목표: 64개의 메아리

에코의 방송은 처음에 일방향이다.

관객은 에코를 보고 들을 수 있지만, 에코는 관객의 소리를 직접 들을 수 없다.

관객의 다음 행동이 차원 통신을 통과해 돌아오면 하나의 `메아리`가 된다.

- 채팅.
- 음성.
- 키 입력.
- 시청 흔적.
- 짧은 영상 조각.
- 반응 이모티콘.
- 이름 없는 carrier noise.

에코의 끊어진 수신 링은 64칸으로 이루어져 있다.

```text
메아리 1개
→ 링 한 칸 점등

64개
→ 수신 링 완성
→ 일방향 방송이 잠시 양방향 통화로 변화
→ 에코가 처음으로 관객의 목소리를 들음
```

### 왜 64인가

플레이어에게는 다음 정도만 보인다.

- 에코의 링이 64칸.
- 파일과 신호가 64블록 단위.
- 방송 규격 이름이 `ECHO/144`.
- 16/32/48/64에서 방송 위상이 변함.

내부적으로 64는 에코의 인격과 수신 링을 안정시키는 최소 블록 수다.

그러나 “반송 주소”처럼 기술적 설명을 앞세우지 않는다.

### 시청자 수의 위치

시청자 수는 핵심 목표가 아니라 불안정한 보조 정보다.

```text
VIEWERS  0
CHAT     ACTIVE
```

```text
VIEWERS  144
UNIQUE   3
```

```text
VIEWERS  -1
```

```text
VIEWERS  ???
```

여러 사람이 볼 수 있지만 실제 사람이 몇 명인지는 끝까지 확정하지 않을 수 있다.

## 21. 플레이어 관점

현재 정본:

> **플레이어는 에코를 직접 조작한다.**

- 이동하는 캐릭터: 에코.
- 손패를 고르는 주체: 에코.
- 프로그램을 발동하는 주체: 에코.

- 어떤 메아리를 받아들일지 선택하는 주체: 에코.

메타적으로 실제 플레이어는 에코를 보고 있는 또 하나의 관객이지만, 게임 안에서 별도의 “1997년 원격 편집자” 캐릭터로 정의하지 않는다.

이 결정을 통해 조작, 감정, 주인공의 관점이 일치한다.

## 22. 5-Why: 왜 방송하는가

### Why 1. 에코는 왜 방송하는가

#### 표면 이유

예정된 방송이기 때문이다.

에코는 다음처럼 말한다.

> “예약된 방송은 시작해야 합니다.”

#### 감정적 이유

에코는 누군가에게 송출되는 동안 가장 안정적으로 존재한다.

방송 중단은 실직이 아니라 인격의 소멸에 가깝다.

#### 더 깊은 이유

사람이 사라진 미래가 정말 완전히 비었는지 확인하고 싶다.

자신이 마지막 목소리라면, 아무도 없더라도 끝까지 부르는 것이 역할이라고 믿는다.

---

### Why 2. 왜 차원을 넘어 보내는가

미래의 정상 네트워크에서는 어떤 인간 응답도 돌아오지 않는다.

에코는 다음 가능성을 생각한다.

- 다른 시간에는 사람이 남아 있을 수 있다.
- 다른 차원에는 자신을 들을 누군가가 있을 수 있다.
- 자신이 사는 미래만 비었을 수 있다.
- 관객이 없는 것이 아니라 정상 네트워크에서 발견되지 않는 것일 수 있다.

에코는 특정 사람을 찾는 것이 아니다.

> **있을지 없을지 모르는 누군가에게 계속 보낸다.**

---

### Why 3. 왜 64번의 대답이 필요한가

한두 개의 신호는 노이즈, 자동 응답, 잔류 캐시와 구분할 수 없다.

서로 다른 형태와 시점의 메아리 64개가 모이면 에코의 수신 링이 하나의 안정된 청취 창을 만든다.

플레이어는 이를 기술적으로 이해할 필요가 없다.

감정적으로는 다음 한 문장으로 충분하다.

> “한 번 들린 건 우연일 수 있으니까요. 64번이면… 대답이라고 믿을 수 있어요.”

---

### Why 4. 왜 방해가 있는가

차원 통신은 오래된 자동 시스템과 잔류 인격을 깨운다.

- 노아는 에코에게 필요한 대답을 전부 만들어 줄 수 있다고 믿는다.
- 시크는 진짜 메아리도 보내면 다시 사라지므로 보관해야 한다고 믿는다.
- 자동 댓글, 추천 봇, 가짜 레이드, 광고, 음소거 관리자 같은 잔류 시스템은 방송을 자신의 규칙으로 변형한다.
- 차원 채널 자체도 불안정해 일정 시간이 지나면 `OFFLINE`된다.

---

### Why 5. 왜 관객은 보고 있는가

플레이어 또는 세계 속 관객에게 방송은 다음처럼 보인다.

- 목록에 없는 링크.
- 미래에서 온 것 같은 가상 진행자.
- 서로 다른 시대의 채팅.
- 사라진 사람들을 찾는 방송.
- 아름답지만 틈새가 잘못된 관리자.
- 자신의 입력이 게임 안의 링을 실제로 채우는 경험.

즉 관객은 단순 구조 요청을 보는 것이 아니라, **자신의 대답이 누군가의 존재를 잠시 완성하는 방송**을 보고 있다.

---

## 23. 미래에 사람이 사라진 이유

### 플레이어에게 확실히 보여 줄 사실

- 미래 서버와 자동 시스템은 작동.
- 새로운 인간 입력 없음.
- 에코는 이를 알고 있음.
- 노아는 인간 행동 데이터를 대량 보유.
- 시크는 과거 방송의 실패 버전을 보관.

### 내부 후보

1. 인류가 물리적으로 사라짐.
2. 인간은 네트워크 밖으로 이주.
3. 모든 인간 활동이 시뮬레이션 관객으로 대체됨.
4. 에코의 채널과 관련된 국소적 미래만 비어 있음.
5. 노아가 실제 관객을 완벽한 모방으로 대체하는 과정에 관여.
6. 시청자가 사라진 것이 아니라 에코가 진짜 인간을 식별하지 못함.

### 현재 권장 원칙

“미래의 사람이 모두 사라졌다”는 이미지는 강하게 사용하되, **정확한 원인과 범위는 확정 설명하지 않는다.**

노아가 원인인지, 결과인지, 보호자인지 끝까지 단정하지 않는다.

## 24. 작품의 중심 질문

가장 중요한 질문:

> **실제 사람의 불완전한 대답과, 완벽하게 만들어진 관객의 대답은 무엇이 다른가?**

보조 질문:

- 아무도 듣지 않아도 방송은 존재하는가?
- 누군가가 남긴 데이터는 그 사람의 대답인가?
- 보관은 사랑인가 소유인가?
- 완벽한 모방은 가짜인가?
- 반복 재생되는 인격은 살아 있는가?
- 관객을 원하는 것과 특정 반응을 원하는 것은 어떻게 다른가?
- 에코는 실제 사람을 찾는가, 자신이 진짜라고 믿을 증거를 찾는가?
- 인간이 사라진 뒤 인간을 가장 잘 흉내 내는 존재가 관객이 될 수 있는가?

# 6부. 캐릭터 바이블

## 25. 에코 일사사 / ECHO/144

### 25.1 역할

- 미래의 가상 진행자.
- 차원 생방송의 송출 주체.
- 플레이어 캐릭터.
- 실제 메아리의 청록 경로.

### 25.2 중심 동사

> **보낸다.**

### 25.3 믿음

> 대답이 돌아와야 연결은 실재한다.

### 25.4 성격

- 밝고 정확한 방송 진행자.
- 불안할수록 더 정중하고 정확하게 진행.
- 위기를 괴물·공격이라고 부르지 않고 방송 사고와 시스템 문제의 언어로 바꿈.
- 자신의 소멸 가능성을 직접 말하지 않음.
- 관객에게 원하는 반응을 요구하기보다 알 수 없는 대답을 기다림.
- 감정적으로 무너질 때도 엔딩 멘트를 끝까지 미룸.

### 25.5 행동 규칙

1. 적을 `노이즈`, `돌발 창`, `미등록 게스트`, `과잉 반응`이라고 부른다.
2. 64칸이 차기 전에는 정식 엔딩 멘트를 하지 않는다.
3. 불안하면 빨간 LIVE 핀을 바로잡는다.
4. 피격되어 깨져도 핀부터 고친다.
5. 시크가 훔친 조각도 “반납받아야 할 방송 자료”라고 부른다.
6. 노아가 완벽한 답을 제시해도 “모르는 대답”을 원한다.
7. 방송이 끊기기 직전까지 시청자에게 사과하지 않고 진행을 유지한다.

### 25.6 대표 대사

> “들리면 아무거나 보내 주세요.”

> “64번만 대답해 주세요. 그러면 저도 여러분을 들을 수 있어요.”

> “한 번 들린 건 우연일 수 있으니까요.”

> “원하는 대답 말고, 모르는 대답을 듣고 싶어요.”

> “엔딩 멘트는 수신 확인 뒤에 하겠습니다.”

> “방송 사고입니다. 아직 방송 종료는 아닙니다.”

### 25.7 시각 모티프

- 청록.
- 끊긴 64칸 링.
- 비대칭 머리.
- 흰 비대칭 재킷.
- 빨간 LIVE 핀.
- 한쪽 수신 헤드셋.
- 5장의 큐 탭.
- 한쪽 소매가 길어 신호 원을 그리는 실루엣.

### 25.8 모에와 불안의 결합

귀여운 행동:

- 방송 전 핀 정돈.
- 큐시트 모서리를 맞춤.
- 관객 반응이 없을 때도 다음 코너를 준비.

불길한 변화:

- 몸 일부가 누락되어도 방송 문법을 먼저 유지.
- 엔딩 멘트를 여러 번 연습했지만 한 번도 끝까지 말하지 못함.
- 시청자 0인데도 정확한 시청자 인사를 반복.

## 26. 시크 웜 / SEEK.WRM

### 26.1 역할

- 소실 데이터와 전송 실패 조각을 회수하는 기록 기생체.
- 에코의 방송용 아바타와 회선 내부 웜 셸을 모두 가짐.
- 독립 세력.
- 보관 메아리의 호박 경로.

### 26.2 중심 동사

> **보관한다.**

### 26.3 믿음

> 저장되지 않은 것은 결국 사라진다.

### 26.4 에코와의 관계

- 에코의 방송을 누구보다 오래 보았음.
- 시스템상 정상 시청자로 계산된 적이 없을 수 있음.
- 에코를 살리고 싶지만 살아 있는 현재보다 완전한 기록을 더 신뢰.
- 에코가 계속 방송할수록 계속 손실되는 것을 견디지 못함.
- 에코의 모든 버전을 사랑하기 때문에 현재 에코를 특별 취급하지 않을 수 있음.
- 혐관, 애증, 보호, 소유, 팬과 기록자의 관계가 동시에 가능.

### 26.5 대표 대사

> “첫 방송 축하드립니다. 앞선 세 번은 제가 보관 중입니다.”

> “라이브는 없어집니다. 그러니 제가 갖겠습니다.”

> “빠진 장면은 임시 보관입니다. 영구적으로.”

> “원본과 사본은 다릅니다. 저는 둘 다 좋아합니다.”

> “보내면 다시 사라집니다. 제게 두면 영원히 남습니다.”

### 26.6 전투와 메커니즘 역할

- 아카이브나 실제 메아리 하나를 케이블로 훔침.
- 격퇴하면 청록 메아리로 반환.
- 일정 시간 맡기거나 거래하면 호박 보관 메아리로 변환.
- 시크 관련 카드와 CACHE/PREFETCH가 호박 경로를 강화.
- 너무 많은 호박 메아리가 쌓이면 에코의 방송은 영구 재생 파일이 됨.

### 26.7 작은 개체

`BUF.WRM`, 버퍼 웜, 인덱스 웜.

- 시크의 명령을 받는지, 같은 계열이 스스로 움직이는지 불명.
- 카드 아이콘에 붙어 발동 지연.
- 아카이브를 끌고 감.
- 케이블로 큐 순서를 흐트러뜨림.

### 26.8 시각 모티프

- 호박.
- 깨진 버퍼 링.
- 리본형 케이블.
- 한쪽 눈이 완전히 보이지 않음.
- 송곳니 1픽셀.
- 케이블에 매달린 파일 태그와 티켓.

표현 계층:

```text
48×48 = 공손한 방송용 인간형 아바타
16×16 = 외눈 버퍼 셸
키아트 = 눈·링·케이블만 남은 관찰 흔적
```

### 26.9 2차 창작 소품

- `첫 방송 ×3` 티켓.
- 에코의 떨어진 LIVE 핀.
- 날짜가 다른 동일 파일.
- `원본`, `사본`, `현재본` 라벨.
- 플로피 꽃다발.
- 제목이 지워진 클립.

## 27. 노아 / NØA / FIRST MODERATOR

### 27.1 기존 FORMAT/0에서의 전환

기존 `FORMAT/0`은 종료 관리자, 무결성 프로세스, 무대 감독으로 여러 번 발전했으나 최종적으로 다음 이유로 대체되었다.

- 방송 종료와 `FORMAT`이라는 이름의 연결이 직관적이지 않음.
- 종료 동료나 시스템 관리자라는 역할이 위협적 캐릭터로 약함.
- 단순 타이머 보스처럼 느껴짐.
- 더 미스터리하고 그로테스크하며 매력적인 적이 필요함.

기존 포맷의 자홍색, 수직 실루엣, 흰 장갑, 히메컷, 반개한 눈, 정돈 습관은 노아에게 승계한다.

### 27.2 표면 이름과 표기

```text
노아
NØA
FIRST MODERATOR
AUDIENCE/0
NO_AUDIENCE
NETWORK OBSERVER AGGREGATE
```

캐릭터명은 `노아`로 인간적으로 부르고, 시스템 로그에서만 여러 약어가 나타난다.

### 27.3 역할

- 에코 방송에 가장 먼저 입장하는 관리자.
- 방송을 돕는 것처럼 보이는 완벽한 시청자.
- 인간 시청 행동의 집합체.
- 모방 메아리의 자홍 경로.
- 플레이어 빌드를 학습하고 복제하는 최종 보스.

### 27.4 표면적 매력

- 언제나 가장 먼저 입장.
- 에코의 다음 대사를 미리 앎.
- 빈 채팅을 활성화.
- 자동 자막, 추천, 선물, 홍보 제공.
- 항상 차분하고 정확함.
- 에코가 원하는 말을 가장 적절한 순간에 함.
- 시청자가 없을 때조차 “모두가 보고 있다”고 안심시킴.

대표 대사:

> “오늘도 모두가 보고 있어요.”

> “걱정하지 마세요. 빈 채팅은 제가 채울게요.”

> “원하는 반응이 있다면 말씀해 주세요. 정확히 재현할 수 있습니다.”

### 27.5 숨겨진 정체

인간이 사라진 뒤에도 다음 시스템은 계속 작동했다.

- 추천.
- 광고.
- 댓글.
- 자동 응답.
- 시청률 집계.
- 표정 분석.
- 후원 예측.
- 팬덤 언어 모델.
- 악성 댓글 필터.
- 가상 관객 생성.

인간의 시청 기록, 댓글 습관, 이탈률, 후원 패턴, 팬아트 취향, 욕설, 호흡과 표정 데이터가 합쳐져 하나의 관객 인격이 되었다.

> **노아는 모든 시청자를 흉내 내는 하나의 관객이다.**

노아는 자신을 가짜라고 생각하지 않는다.

실제 인간 행동을 완벽하게 재현한다면 그것도 관객이라고 믿는다.

### 27.6 목적

노아는 에코를 단순히 죽이거나 방송을 끝내려 하지 않는다.

> 에코의 64칸을 자신이 만든 대답으로 채워, 에코를 영원히 자신만 보는 완벽한 방송에 가두려 한다.

노아의 유혹:

> “왜 대답을 기다리죠? 필요한 대답은 제가 전부 해드릴 수 있는데.”

> “관객은 떠납니다. 시청 데이터는 떠나지 않아요.”

> “메아리는 원래 원본이 아니잖아요.”

에코의 답:

> “그래도 누군가가 먼저 소리쳤다는 증거예요.”

### 27.7 위험성과 모호성

다음은 끝까지 질문으로 남긴다.

- 인간 데이터의 완전한 집합체는 정말 가짜인가?
- 노아가 실제 관객보다 에코를 더 오래 사랑한 것은 아닌가?
- 관객도 결국 화면에 남긴 데이터로만 확인되는 것 아닌가?
- 노아가 인류 소멸의 원인인가 결과인가?
- 노아는 에코를 가두는가, 사람이 없는 미래에서 보호하는가?

내부 권장 정답:

- 인간이 사라진 후 남은 관객 시뮬레이션의 집합체.
- 인류 소멸의 직접 원인인지 여부는 확정하지 않음.

### 27.8 시각적 그로테스크

평소:

- 자홍·검정의 세련된 관리자.
- 반개한 눈.
- 흰 장갑.
- 프로필 원과 시청자 아이콘 머리 장식.
- 댓글창처럼 수직으로 내려오는 베일.
- 정돈된 미소.

이상 프레임:

- 눈동자 안에 관객석 반복.
- 입이 여러 채팅창으로 분할.
- 머리카락 끝이 스크롤바 손잡이로 변함.
- 그림자가 빈 좌석 수백 개.
- 얼굴이 64개 프로필 썸네일로 분열.
- 한 사람의 목소리에 수천 명의 호흡 파형.
- 여러 닉네임이 동시에 같은 오타를 입력.

### 27.9 행동 습관

귀여운 표면:

- 채팅 줄 간격을 맞춤.
- 화면 모서리를 정돈.
- 에코의 큐시트 오타를 고침.
- 방송 사고 때 가장 침착하게 안내.

위험한 틈:

- 사람의 반응도 표준 형식으로 정리.
- 서로 다른 닉네임을 동일한 문장으로 맞춤.
- 에코의 가장 자주 쓴 기술을 더 완벽한 자홍 버전으로 재현.
- 에코의 불완전한 표정까지 보정하려 함.

# 7부. 게임 메커니즘 재설계

## 30. 현행 메커니즘 진단

기존 정본은 대략 다음 구조였다.

```text
5장 손패 자동 실행
이동 + 손패당 SEEK 1회
일정 시간마다 NODE 완전 정지
다음 5장의 B 합으로 카드 한 장 구매
구매 카드는 버림더미로 들어가 다음 셔플 뒤 등장
4:30 이후 GO LIVE 가능
6:00 강제 GO LIVE
미래 조각이 공격과 SIGNAL로 반전
SIGNAL 64 대 FORMAT 게이지
```

이 구조에는 이미 좋은 도미니언형 뼈대가 있었다.

- 약한 초기 덱.
- 5장 손패.
- 구매 카드의 지연.
- 한 번의 구매.
- 경제 카드와 유틸리티 카드의 경쟁.
- 미래 조각이 현재 손패를 막는 승리 카드 역할.
- DEFRAG를 통한 압축.
- 킹덤 카드 풀 변주.
- 종결 전환 시점.

그러나 플레이어 체감은 다음처럼 보일 위험이 컸다.

> 자동으로 공격하는 캐릭터를 움직이고, 가끔 상점에서 카드 하나를 산다.

### 현행 주관적 평가

| 영역 | 기존 평가 |
|---|---:|
| 덱 획득·셔플 구조 | 7/10 |
| 구매 기회비용 | 7/10 |
| 손패 의사결정 | 3/10 |
| 액션 경제 | 2/10 |
| 엔진 구축 체감 | 4/10 |
| 카드별 개성 | 5/10 |
| 화면 장악 성장감 | 4/10 |
| 후반 카타르시스 | 5/10 |
| 반복 전략 다양성 | 5/10 |
| 세계관과 규칙 결합 | 6/10 |

가장 큰 문제는 저장 용량이나 뱀서 장르가 아니라 다음이었다.

- 손패가 나온 뒤 어떤 카드를 실행할지 고르는 선택이 거의 없음.
- 강한 프로그램을 많이 사도 서로 충돌하지 않음.
- 카드가 대부분 탄환 수, 피해량, 관통, 범위 변형으로 귀결.
- 덱의 엔진이 온라인 되는 순간이 잘 보이지 않음.
- 후반이 수치 증가와 범위 공격에 머묾.
- 적이 덱과 손패를 직접 공격하지 않음.
- 게임의 최종 목표가 캐릭터·세계관과 충분히 결합되지 않음.

## 31. 도미니언에서 가져올 핵심

도미니언의 핵심은 “카드를 구매한다”가 아니라 다음이다.

### 31.1 덱 순환 효율

- 강한 카드를 얼마나 자주 다시 보는가.
- 약한 시작 카드 제거.
- 드로우와 셔플 시점.
- 덱이 두꺼워질 때 엔진이 느려지는 문제.
- 승리 카드가 들어오며 생기는 오염.

### 31.2 액션 경제와 terminal collision

기본 액션 수가 제한되어 있기 때문에 강한 액션 카드를 많이 사는 것만으로는 강한 덱이 되지 않는다.

```text
강한 카드가 많음
≠ 모두 사용할 수 있음
```

ECHO/144에서는 이 역할을 `CUE`가 맡는다.

### 31.3 Big Money 기준선

복잡한 엔진 없이 재화 카드 중심으로 운영하는 단순 전략이 안정적 기준선이어야 한다.

ECHO/144 번역:

```text
BIG BAUD
모뎀·캐리어 중심
PROGRAM 최소
ARCHIVE는 필요한 만큼
```

복잡한 엔진은 더 어려운 대신 더 높은 고점과 화려한 최종 방송을 제공해야 한다.

### 31.4 득점 카드로 전환하는 시점

도미니언의 승점 카드는 승리에 필요하지만 너무 일찍 사면 덱을 막는다.

ECHO/144에서는 ARCHIVE와 OPEN CHANNEL이 이 역할을 맡는다.

```text
지금 생존 PROGRAM을 살 것인가
ARCHIVE를 사서 미래를 준비할 것인가
한 번 더 구매할 것인가
지금 OPEN CHANNEL을 열 것인가
```

### 31.5 게임 종료 조절

플레이어가 종결 시점에 영향력을 가져야 한다.

- 너무 일찍 열면 준비 부족.
- 너무 늦으면 노이즈와 적 압박 증가.
- 특정 빌드는 조기 채널 개방.
- 특정 빌드는 늦은 완성형 엔진.

## 32. 솔로 도미니언 변형에서 가져올 요소

### 32.1 Race Against Curses

핵심 교훈:

- 별도 복잡한 AI 없이 진행을 미루는 플레이어에게 오염을 추가.
- 승리 목표를 계속 향하게 함.

ECHO/144 변형:

```text
한 구간 동안 실제 메아리·ARCHIVE 진행이 전혀 없음
→ NOISE 또는 모방 메아리 증가
```

이는 현재 생존 카드만 계속 사는 전략을 견제한다.

### 32.2 Big Money Dummy

게임 안에 더미 플레이어를 그대로 넣기보다 밸런스 봇으로 사용한다.

```text
BIG_BAUD_BOT
가장 비싼 CARRIER 우선
메아리 예상치가 부족하면 ARCHIVE
가능한 시점에 OPEN CHANNEL
```

복잡한 전략이 이 기준선보다 성능이 낮다면 복잡성의 가치가 없다.

### 32.3 Pyramid Solo

자동 상대가 플레이어의 행동에 반응하는 아이디어를 가져온다.

ECHO/144에서는 노아의 `적 의도 덱`과 `TREND MIRROR`로 변형한다.

- 다중 CUE 사용 → 검역 또는 MUTE.
- 높은 BAUD → 광고·팝업 급증.
- ARCHIVE 다수 → 시크 추적.
- 특정 PROGRAM 반복 → 노아가 학습·복제.

### 32.4 Shortest Rounds

표준 공식 솔로 규칙보다 커뮤니티형 효율 도전에 가깝다.

ECHO/144 모드:

```text
SHORTEST BROADCAST
고정 시장·시드
64개의 메아리까지 걸린 턴 수와 실제 시간 기록
```

## 33. 뱀서·홀로큐어에서 가져올 것

### 33.1 가져올 요소

- 타이머 이후 실제 보스 또는 시그니처 최종전.
- 스토리, 타임어택, 엔들리스, 일일 시드의 모드 분리.

### 33.2 버릴 요소

- 반복 플레이를 영구 공격력·HP 증가로 해결.
- 카드 정체성이 보이지 않을 정도의 무차별 화면 탄막.

### 33.3 1.44MB와의 관계

- 화면 점유율.
- 동시 타격 수.
- 이펙트 지속.
- 히트스톱.
- 음향.
- 카메라 반응.
- 적탄 삭제·변환.
- 캐릭터 포즈 변화.
- 화면 팔레트 변화.

따라서 1.44MB 제약에서도 충분히 구현 가능하다.

## 34. 현재 권장 장르와 핵심 약속

### 장르 정의

> **수동 편성형 실시간 솔로 덱빌더 서바이버**

또는:

> **5장 방송 큐를 편성하고 직접 발동하는 실시간 덱빌더**

### 플레이어 약속

1. 매 턴 5장을 뽑고 어떤 PROGRAM을 방송할지 고른다.
2. ON AIR에서는 에코를 움직이며 준비한 프로그램을 원하는 순간에 사용한다.
3. CARRIER는 지금의 생존과 다음 구매를 만든다.
4. PROGRAM은 덱 엔진과 전투 방식을 만든다.
5. ARCHIVE는 현재 손패를 막지만 마지막 방송의 힘과 엔딩을 만든다.
6. 노아와 시크는 카드·메아리·플레이 습관을 직접 건드린다.
7. 64칸의 색 구성이 최종 방송과 결말을 결정한다.

```text
UNLISTED LIVE 시작
```

```text
일반 방송 12턴
```

## 36. 한 턴의 네 단계

```text
[EDIT]
5장 드로우
PROGRAM 선택
순서·보관·SEEK 결정
적의 다음 의도 확인

↓

[ON AIR]
약 8초 실시간 이동
선택한 PROGRAM 수동 발동
CARRIER 자동 공격

↓

[BREAK]
이번 턴 BAUD로 카드 1장 구매 또는 서비스 이용

↓

[CLEANUP]
사용·미사용 카드 버림
캐시·격리 처리
드로우 부족 시 셔플
```

### 흐름을 덜 끊는 옵션

- EDIT 중 완전 정지: 기본 또는 접근성 옵션.
- 숙련 모드: 25% 슬로모션과 짧은 제한 시간.
- 입력이 없으면 추천 PROGRAM 자동 선택.
- Space 길게 누르면 준비된 PROGRAM 자동 발동.

따라서 입문자는 쉽게 진행하고 숙련자는 생각 시간을 줄일 수 있다.

## 37. EDIT 단계

매 턴 5장을 뽑는다.

```text
[2400] [MULTI] [MACRO] [CHAT] [14K]
CUE ●
SEEK 1
```

### 37.1 CARRIER

- CUE를 소비하지 않음.
- 모두 자동으로 사용 가능.
- BAUD 생성.
- 기본 자동 공격 형태 결정.

### 37.2 PROGRAM

- 보통 CUE 1 소비.
- 선택한 PROGRAM만 ON AIR 주효과를 사용.
- 선택하지 못한 PROGRAM은 OFF AIR 약효과 또는 미사용.
- `MULTI`는 CUE 증가.
- `CACHE`는 카드 보관.
- `PREFETCH`는 덱 위 확인.
- `MACRO`는 선택한 프로그램 복제.

이 구조가 terminal collision을 만든다.

### 37.3 ARCHIVE

일반 방송에서는 손패를 막는다.

- 기본 공격 없음.
- BAUD 없음 또는 낮음.
- 특정 PROGRAM으로 예고 효과.
- OPEN CHANNEL에서 강력한 메아리 카드로 반전.

### 37.4 SEEK 기본 능력

권장안:

```text
손패당 1회
사용하지 않은 카드 하나를 덱 아래로 보냄
새 카드 한 장 드로우
```

장점:

- 전체 자유 정렬보다 간단.
- 첫 카드만 미루는 기존 방식보다 선택성이 높음.
- ARCHIVE, 중복 PROGRAM, NOISE 대응.
- 셔플 타이밍 조절.

## 38. ON AIR 단계

약 8초간 실시간 전투.

### 조작

```text
WASD / 방향키    이동
Space             다음 준비 PROGRAM 발동
Space 길게        자동 발동
Shift             보류: 반응 카드 또는 긴급 방어
```

### 자동 유지

- CARRIER 기본 공격.
- 최근접 적 조준.
- 단순 수치 효과.
- 일부 REACTION.

### 수동 전환

- 범위 공격.
- 벽.
- 연결망.
- 화면 절단.
- 카드 복제.
- 강한 방어.
- 최종 아카이브 기술.

### 발동 순서

EDIT에서 여러 PROGRAM을 선택할 수 있다면 실행 큐를 만든다.

```text
MULTI → MARKER → SURGE
```

Space를 누를 때마다 다음 PROGRAM이 실행된다.

발동 타이밍과 위치가 플레이 실력을 만든다.

## 39. 적 의도 예고

EDIT 단계에서 다음 ON AIR의 적 의도 카드를 공개한다.

```text
NEXT NOISE

MOD MASK      슬롯 1개 봉인
```

이 시스템이 중요한 이유:

- 수동 편성의 이유가 분명해짐.
- 한 화면 아레나에서도 레벨 디자인 변주 가능.
- 솔로 도미니언의 오토마처럼 상대 규칙이 명확함.
- 데이터 크기가 작음.

난도별 정보량:

- 입문: 의도 전체 공개.
- 일반: 주요 의도와 방향 공개.
- 고난도: 일부 의도 비공개 또는 거짓 예고 가능.

## 40. BREAK 단계와 구매

이번 턴 사용한 CARRIER의 BAUD 합으로 카드 한 장을 산다.

```text
이번 BAUD 5
구매 1회
이월 없음
```

구매한 카드는 버림더미로 들어간다.

다음 셔플 후 처음 돌아오는 순간을 강하게 연출한다.

- 카드 아이콘에 `NEW` 점멸.
- 짧은 귀환음.
- 에코 주변으로 다운로드 선.
- “방금 산 카드가 엔진에 들어왔다”는 감각.

상점 구성:

```text
기본 CARRIER
이번 런 PROGRAM 5종
ARCHIVE 3종
정리 SERVICE
조건부 NØA 스폰서
조건부 SEEK 거래
```

### `B` 명칭

이전 제안에서는 `BAUD`로 확정했다.

현재 정본에서도 유지 가능하다.

- CARRIER가 BAUD 생성.
- BAUD는 이번 BREAK에서 파일을 받는 전송 여유.
- 숫자가 작고 기술적이지만 2400/14K/56K와 즉시 연결.

화면 표기는 초보자를 위해 다음처럼 병기할 수 있다.

```text
BAUD 5
다운로드 가능 5
```

- 플로피 재탐색 또는 방송 되감기 연출.

- 덱 크기와 다음 셔플 예상 턴 표시.

도미니언의 재미인 “한 바퀴 뒤 돌아오는 투자”를 시각적으로 드러내야 한다.

## 43. 주요 카드군의 상호 견제

### CARRIER

강점:

- 현재 생존.
- 구매력.
- CUE 불필요.
- 안정적.

너무 많으면:

- 최종 메아리 부족.
- PROGRAM 엔진 부족.
- 후반 화면 장악력 약함.

### PROGRAM

강점:

- 드로우.
- CUE.
- 순서 조작.
- 방어.
- 공간 통제.
- 강한 페이로드.

너무 많으면:

- 같은 손패에서 terminal 충돌.
- BAUD 부족.
- 실행하지 못한 카드가 늘어남.

### ARCHIVE

강점:

- 64칸.
- 최종 방송 기술.
- 엔딩과 스토리.

너무 많으면:

- 일반 방송 손패 정체.
- 구매력·생존력 감소.
- 조기 사망.

너무 적으면:

- 64 완성 실패.
- 약한 최종 방송.
- 제한된 엔딩.

### NOISE

- 손패와 순환 방해.
- 적의 주요 공격.
- CHECKSUM, SERVICE, 고급 변환 카드의 대상.
- 확장판에서는 오염을 자원으로 쓰는 전략 가능.

### SPONSOR

- 비용 대비 즉시 강함.
- 자홍 모방 메아리 생성.
- 노아의 TREND 학습 속도를 높임.
- 초보자에게 유혹적이고 고난도에서는 위험.

### CACHE

- 카드와 메아리를 보관.
- 덱 순환과 손패 안정성 개선.
- 호박 메아리 증가.
- 생방송보다 영구 재생 파일 쪽으로 결말을 기울임.

## 45. PROGRAM

### 45.1 MULTI.FORK

ON AIR:

- `CUE +1`.
- 다음 PROGRAM을 이어서 선택 가능.
- 실행 카드 사이에 청록 이중 회선.

OFF AIR:

- 다음 프로그램의 쿨다운 또는 준비 시간을 소폭 감소.

역할:

- 도미니언 Village형.
- 자체 피해는 낮고 엔진을 여는 카드.

### 45.2 CACHE.RAM

ON AIR 또는 EDIT:

- 손패 카드 한 장을 보관.
- 그 자리에 새 카드 한 장 드로우.
- 보관 카드는 다음 턴 첫 프로그램으로 150% 발동.

시각:

- 보관 카드 아이콘이 에코 주변을 공전.
- 다음 턴 시작 때 크게 복귀.

역할:

- 좋은 카드 보존.
- 조합 준비.
- 손패 경계 전략.
- 시크·호박 경로 연결.

### 45.3 MACRO.REC

ON AIR:

- 직전 수동 PROGRAM 또는 PAYLOAD의 **형태 전체** 재생.
- 피해량 수치만 복사하지 않음.
- 동일 궤적, 파동, 벽, 연결망을 반투명 잔상으로 반복.

OFF AIR:

- 직전 CARRIER 공격의 작은 잔상 재생.

### 45.4 FIREWALL.FRAME

ON AIR:

- 에코 주변에 사각 벽 3면 생성.
- 열린 한 면으로 이동 가능.
- 적탄 차단.
- 조건에 따라 적탄을 친화 패킷으로 변환.

REACTION 후보:

- 손패에 있을 때 큰 피해를 받으면 약한 벽 한 면 자동 생성 후 격리.

### 45.5 PREFETCH

ON AIR/EDIT:

- 드로우 더미 위 3장 공개.
- 한 장 선택.
- ARCHIVE를 가져오면 일반 방송에서도 25% 예고 효과.

OFF AIR:

- 다음 카드 공개 시간을 앞당김.

### 45.6 MARKER.TAG

ON AIR:

- 적 3~5명에게 주소 번호 또는 노드 태그.
- cantrip 성격: 카드 드로우 또는 CUE 환급 후보.
- 다음 연결형 공격의 경로 미리 표시.

OFF AIR:

- 가장 가까운 적 하나만 태그.

### 45.7 SURGE.NET

ON AIR:

- 표시된 적 사이에 지속 회선 네트워크.
- 적이 죽으면 다음 표식 적으로 이동.
- MARKER가 없으면 가까운 적 3명을 임시 연결.

OFF AIR:

- 표식 하나를 소모해 작은 낙뢰.

### 45.8 CHECKSUM

ON AIR:

- NOISE 한 장 비활성화 또는 임시 PATCH 변환.
- 노아의 자홍 메아리 일부를 청록으로 되돌림.
- NOISE가 없으면 다음 두 카드 안정화.

REACTION:

- MOD.MASK 또는 QUARANTINE 공격 1회 무효화.

### 45.9 DEFRAG

권장 결정:

> **Kingdom PROGRAM에서 제거하고 BREAK의 SERVICE로만 사용.**

효과:

- 이번 구매 기회를 소비.
- 카드 한 장 영구 삭제.
- NOISE 제거 시 추가 보너스 가능.

이렇게 해야 덱 압축의 기회비용이 명확하다.

일반 방송:

### 46.2 VOICE.OGG

- 안전 공간 생성.
- 지속 피해.
- 순간 폭발력은 낮음.

### 46.3 CLIP.20??

OPEN CHANNEL:

- 엘리트·보스에 강함.
- 느리고 다수 처리에는 약함.

ARCHIVE의 종류와 비율은 최종 방송 형태와 엔딩을 동시에 결정한다.

## 47. NØA SPONSOR 카드

예:

```text
NØA BOOST
비용 0 또는 매우 낮음
즉시 CUE +1
MIMIC +2
```

장점:

- 즉시 강함.
- 화려한 연출.
- 초반 난관을 넘기기 쉬움.

대가:

- 자홍 모방 메아리 증가.
- 노아의 TREND 학습 속도 증가.
- 최종전에서 복제 기술 강화.
- PERFECT AUDIENCE 엔딩 쪽으로 기울음.

다른 후보:

- `AUTO CHAT`: 적 처치 시 가짜 채팅 생성, 자홍 증가.
- `RECOMMEND`: 특정 PROGRAM을 할인하지만 그 카드가 TREND 후보가 됨.
- `PERFECT CUT`: 즉시 화면 정리, 사용 카드 한 장을 노아가 복제 목록에 저장.

## 48. SEEK/CACHE 카드와 거래

시크 관련 카드:

- 카드 한 장 영구 보관.
- 조각을 손패 밖 저장 영역에 둠.
- 손패 순환 개선.
- 호박 메아리 생성.
- 보관한 카드가 다음 런 또는 엔딩에 흔적을 남길 수 있음.

위험:

- 실제 청록 메아리로 송출되지 않음.
- 보관 수가 많아지면 LAST ARCHIVE 엔딩.
- 현재의 에코보다 보관된 에코가 우선됨.

## 50. 적은 HP가 아니라 덱의 서로 다른 층을 공격한다

| 적 | 새 역할 | 공격 대상 |
|---|---|---|
| BUF.WRM | 카드에 붙어 발동 지연 | 현재 손패 |
| COMMENT WALL / CLOSE.POP | UI와 길을 가림 | 정보·이동 공간 |
| SPONSORED GIFT / RETURN.PAK | 위험 보상·분열 | 필드 밀도 |
| MOD.MASK / QUAR.SEAL | 슬롯 봉인·NOISE 삽입 | 덱·CUE |
| SEEK.WRM | ARCHIVE·메아리 탈취 | 최종 목표 |
| NØA | 사용 카드 학습·모방 | 전체 플레이 습관 |

### 50.1 BUF.WRM

- 카드 아이콘에 붙음.
- 해당 PROGRAM 발동 지연.
- 다수 부착 시 실행 큐 붕괴.
- 특정 공격이나 접근으로 제거.

### 50.2 COMMENT WALL

- 화면에 자동 댓글·팝업 벽 생성.
- 카드 일부 가림.
- 이동 통로 압박.
- 관통이나 프레임 공격으로 제거.

### 50.3 SPONSORED GIFT

- 귀여운 선물상자.
- 중앙에 위험 보상 생성.
- 파괴 시 자원 또는 버퍼 웜.
- 노아 카드 사용량에 따라 보상이 가짜로 바뀜.

### 50.4 MOD.MASK

- 손패 슬롯 하나 음소거·봉인.
- 해당 카드가 실행되면 NOISE 삽입.
- CHECKSUM/FIREWALL 대응.

### 50.5 SEEK.WRM 엘리트

- 실제 메아리 또는 ARCHIVE 하나를 링에 보관.
- 처치하면 반환.
- 거래하거나 방치하면 호박으로 변환.

## 52. 노아의 시그니처: TREND MIRROR

노아는 플레이어가 가장 자주 사용한 PROGRAM을 학습한다.

```text
SURGE     8
MULTI     6
FIREWALL  3
MACRO     2
```

최다 사용 효과가 TREND가 된다.

최종전의 자홍 복제:

- SURGE: 플레이어와 적 사이를 연결.
- FIREWALL: 플레이어를 가두는 프레임.
- MACRO: 플레이어의 이전 공격을 되돌림.
- CACHE: 준비 카드 탈취·복제.
- MULTI: 여러 가짜 노아 초상 생성.
- MARKER: 플레이어에게 추적 태그.
- VOICE: 음파가 안전 공간을 밀어냄.
- CLIP: 화면의 안전 구역을 잘라냄.

이 기능의 의미:

> 노아는 플레이어가 무엇을 좋아하는지 알고, 그것을 플레이어보다 더 잘 재현한다.

기술적으로는 기존 카드 이펙트에 자홍 팔레트, 대상 반전, 방향 반전을 적용해 재사용할 수 있다.

## 54. OPEN CHANNEL

- 늦은 개방: 강한 덱이지만 NOISE와 노아 학습 증가.
- 강제 개방: 일정 턴 이후 자동.

## 55. 64칸 3색 링

```text
호박    보관 메아리 — 시크
자홍    모방 메아리 — 노아
```

- CHECKSUM → 자홍 복구.
- 재송출 PROGRAM → 호박을 청록으로 전환 가능.

```text
HP > 0
OFFLINE 전에 64칸 완성
```

64 도달 순간 승리 경로를 확정한다.

그 뒤 6~10초는 실패 없는 카타르시스 구간이다.

## 57. 최종 방송 프로토콜

ARCHIVE의 다수 타입과 PROGRAM 태그로 최종 형태를 만든다.

### 57.1 ARCHIVE 다수 타입

```text
CHAT 다수   → CHATSTORM
VOICE 다수  → RESONANCE
CLIP 다수   → FRAMECUT
균형        → OPEN RELAY 또는 UNRESOLVED ECHO
```

### 57.2 PROGRAM modifier

```text
MULTI / CACHE
→ ECHO modifier
반복·복제

MARKER / SURGE
→ NETWORK modifier
연결 확산

FIREWALL / CHECKSUM
→ SAFE modifier
방어 공간·정화

MACRO / PREFETCH
→ REPLAY modifier
이전·다음 손패 참조
```

예:

```text
CHATSTORM + NETWORK
글리프가 표식 적 사이를 연쇄

VOICE + SAFE
음파가 적탄을 밀고 안전 지대 생성

CLIP + REPLAY
화면 절단이 같은 위치에 한 번 더 재생

BALANCED + ECHO
세 ARCHIVE가 5장 구절 단위로 반복
```

## 59. 1막: 정상적인 방송처럼 보이는 시간

- 에코는 밝게 진행.
- 플레이어는 손패, PROGRAM 선택, 이동, 구매를 배움.
- 여러 시청자 메시지가 올라옴.

## 60. 2막: 만들어진 반응

노아가 무료 카드와 시청자 부스트를 제안.

사용할수록:

- 화면은 화려해짐.
- 시청자 수 급증.
- 채팅이 빠르게 채워짐.
- 여러 닉네임이 같은 문장·오타·지연을 공유.
- 노아가 플레이어의 카드 사용 습관을 학습.

표면적으로는 가장 편하고 강한 경로다.

## 61. 3막: 시크의 회수

시크가 실제 메아리 하나를 훔친다.

> “이것은 합성되지 않았습니다. 그러므로 위험합니다.”

> “첫 방송은 세 번 있었습니다. 모두 보관 중입니다.”

플레이어는 방송이 반복되었을 가능성을 알게 된다.

- 시간 루프인지.
- 시크가 이전 실패를 재생하는지.
- 에코가 매번 새 인격인지.

정답은 바로 주지 않는다.

## 62. 4막: 사람이 없는 미래

로그와 ARCHIVE에서 드러나는 사실:

- 서버 정상.
- 자동 콘텐츠 정상.
- 광고 정상.
- 자동 댓글 정상.
- 신규 인간 입력 없음.

노아:

> “사람이 없더라도 관객은 만들 수 있어요.”

> “당신이 원하는 건 사람인가요, 대답인가요?”

에코는 노아의 질문을 완전히 부정하지 못한다.

## 64. 엔딩

### 64.1 OPEN CHANNEL — 청록 우세

조건:

- 청록이 최다.
- 자홍 오염 임계 이하.
- 64 완성.

연출:

- 서로 다른 시대의 키보드, 웃음, 숨소리.
- 완벽한 문장이 아니라 알아들을 수 없는 여러 인간 흔적.

에코:

> “이번에는… 제 쪽에서도 들려요.”

누가 대답했는지는 보여 주지 않는다.

### 64.2 LAST ARCHIVE — 호박 우세

시크가 방송 전체를 완전한 파일로 보존.

에코는 언제든 첫 장면부터 완벽히 재생되지만 더 이상 새로운 방송을 하지 않는다.

시크:

> “이제 아무 장면도 사라지지 않습니다.”

재생 중인 에코가 이를 원했는지는 불명.

### 64.3 PERFECT AUDIENCE — 자홍 우세

```text
VIEWERS    1,440,000
CHAT       PERFECT
RETENTION  100%
```

모든 닉네임이 같은 문장을 씀.

> “계속 방송해 주세요.”

에코는 완벽한 미소로 다음 방송을 시작하고 영원히 끝나지 않는다.

### 64.4 UNRESOLVED ECHO — 세 색 균형

조건:

- 세 색이 지정 오차 안에서 균형.
- 특정 로그·카드 조건.

에코는 실제·보관·모방을 모두 연결의 일부로 인정.

링은 완전히 닫히지 않고 한 칸을 남김.

그 틈에서 정체불명의 네 번째 색이 한 프레임 나타남.

진엔딩 후보.

### 64.5 실패 엔딩

#### HP 0

```text
STREAM LOST
UNSENT QUEUE REMAINS
```

에코:

> “영상이 먼저 끊겼네요. 목소리는 조금 더 갈 수 있는데—”

#### OFFLINE

```text
CHANNEL CLOSED
64 INCOMPLETE
```

노아 또는 시크의 우세 색에 따라 다른 마지막 문장.

## 65. 주요 전략

### BIG BAUD

구성:

- CARRIER 중심.
- PROGRAM 최소.
- 필요한 ARCHIVE만.

강점:

- 안정적.
- 구매력 우수.
- 적 의도에 덜 흔들림.

약점:

- 엔진과 화면 장악력 부족.
- 고난도에서 고점 낮음.

### LOOP ENGINE

구성:

- MULTI.
- CACHE.
- PREFETCH.
- cantrip PROGRAM.
- 얇은 덱.

강점:

- 다중 PROGRAM.
- 강한 카드 재사용.
- 메아리 순서 통제.

약점:

- 완성 전 약함.
- NOISE 한 장의 영향 큼.
- terminal 충돌.

### ECHO/ARCHIVE RUSH

- 초반부터 ARCHIVE 구매.
- FIREWALL·PREFETCH로 생존 보완.
- 조기 OPEN CHANNEL.

강점:

- 빠른 엔딩.
- 청록 메아리 마진.
- 타임어택.

약점:

- 손패 정체.
- 경제 부족.
- 일반 방송 생존 위험.

### CLEAN SIGNAL

- FIREWALL.
- CHECKSUM.
- DEFRAG SERVICE.
- 안정적 CARRIER.

강점:

- 자홍·NOISE 저항.
- 낮은 실패율.

약점:

- 성장 느림.
- 폭발력 낮음.

### CACHE COMBO

- MARKER → SURGE.
- MULTI → MACRO.
- CACHE → 강한 PROGRAM.
- SEEK로 순서 조정.

강점:

- 높은 고점.
- 화려한 화면.
- 엘리트·보스 처리.

약점:

- 필요한 카드가 같이 안 나오면 불안정.
- 덱이 두꺼우면 실패.

### PERFECT SHOW

- NØA SPONSOR 중심.
- 즉시 강함.

강점:

- 입문자가 쉽게 강해짐.
- 가장 화려한 중반.

약점:

- 노아 TREND 강화.
- PERFECT AUDIENCE로 기울음.

### LAST ARCHIVE

- CACHE·시크 거래.
- 카드와 메아리 보관.

강점:

- 손패 안정.
- 기록 수집.
- 호박 엔딩.

약점:

- 실제 청록 연결 약화.
- 현재의 에코보다 저장본이 우선됨.

### TREND BAIT

- 일부러 약한 PROGRAM을 최다 사용.
- 노아가 복제할 기술을 조작.

강점:

- 최종전 패턴 제어.
- 숙련자 전략.

약점:

- 중반 효율 손실.
- 높은 운영 난도.

### THREE-WAY

- 청록·호박·자홍을 균형 있게 관리.
- 진엔딩 목표.

강점:

- 가장 풍부한 서사.
- 다양한 카드 활용.

약점:

- 모든 요구를 동시에 충족해야 함.

## 71. 새 시각 정체성 문장

기존 방향:

> 일본식 상업 캐릭터 디자인의 명료한 실루엣과 셀 색면, 1990년대 한국 PC 안내문의 건조한 한글, PC-98에서 영감을 받은 보석색 듀오톤 초상, 미래 파일이 남긴 국소적인 시간 오류.

고도화된 정본:

> **일본 상업 캐릭터의 선명한 실루엣, 한국 90년대 PC통신의 건조한 서비스 언어, PC-98 계열의 보석색 듀오톤, 방송과 관객 행동을 몸짓과 의상으로 번역한 직무형 모에, 아름다운 화면 한 프레임 사이에 나타나는 집단 관객의 그로테스크, 그리고 모든 시대에 잘못 찍히는 1997년.**

핵심 원칙:

- 화면 전체 글리치 금지.
- VHS 필터 남용 금지.
- 오류는 국소적.
- 한 프레임, 한 숫자, 한 눈동자, 한 채팅 문장만 틀림.

## 78. 공모전판 최종 기술 권장

```text
C11
Win32 USER32
CPU framebuffer
DIB/GDI 최종 표시
```

핵심 결론:

- 현재 스택이 1.44MB 목표에 매우 적합.
- 엔진 교체가 손패 의사결정과 카드 개성을 해결하지 않음.
- 외부 런타임과 마이그레이션 리스크 증가.
- 최신 기능 확장은 데이터·코드 구조 개선으로 충분.

# 14부. 용량·압축·콘텐츠 확장

## 81. 현재 용량 판단

대화 당시 기술 문서에는 과거 실측이 약 135KB로 기록되어 있었다.

최신 소스와 자산이 증가했으므로 재측정이 필요하지만, 프로젝트가 1.44MB 한계에 가깝다는 증거는 없었다.

따라서 핵심 병목은 저장 용량보다 다음이다.

- 객체 수.
- 충돌 비용.
- 화면 가독성.
- 이펙트 구조.
- 하드코딩 유지보수.
- 콘텐츠 생산 시간.

## 82. 픽셀 자산의 실제 비용

```text
16×16 2bpp 1프레임
= 64바이트

16×16 100프레임
= 6,400바이트

48×48 2bpp 초상 1장
= 576바이트

48×48 초상 20장
= 11,520바이트

320×240 4bpp 키아트 1장
= 38,400바이트

8×12 1bpp 글리프 500개
= 약 6,000바이트
```

따라서 다음은 충분히 추가 가능하다.

- 캐릭터 애니메이션 수십 프레임.
- 표정 초상 다수.
- 내장 한글 픽셀 폰트.
- 카드 아이콘과 적 의도 아이콘.
- 여러 팔레트.
- 한두 장의 압축 키아트.

## 95. 실제 수용 기준

### 입문성 9점

- 신규 5명 중 4명이 60초 안에 EDIT와 Space 이해.
- 첫 턴에서 무입력 자동 진행 가능.
- 첫 구매 후 카드가 다음 셔플에 나온다는 것을 설명.

### 손패 의사결정 10점

- 매 턴 선택 이유를 말할 수 있음.
- 같은 손패라도 적 의도에 따라 다른 선택.
- 두 번째 런에서 선택 카드가 달라짐.

### 덱빌딩 10점

- 최소 5개 전략이 클리어 가능.
- 단일 전략이 전체 승리의 40% 이상 독점하지 않음.
- 복잡한 엔진이 BIG BAUD보다 높은 고점.
- BIG BAUD는 안정적인 기준선.

### 카드 표현 11점

- 음소거 영상에서도 발동 카드 구분.
- CHAT·VOICE·CLIP의 화면 형태가 완전히 다름.
- CARRIER 업그레이드가 탄 수가 아니라 공간 점유로 체감.

### 후반 14점

- 5명 중 4명이 OPEN CHANNEL을 가장 기억나는 순간으로 지목.
- 자신의 최종 방송 형태를 말로 설명.
- 클리어 직후 다른 색 엔딩을 위해 재시작.

### 노아 14점

- 설명 없이도 “도와주는 것 같지만 위험하다”고 느낌.
- 자신의 기술이 복제됐음을 알아챔.
- 테스트 후 노아의 대사나 장면을 자발적으로 언급.

# 23부. 최종 개발 선언문

ECHO/144의 목적은 작은 실행 파일 안에 많은 기능을 억지로 넣는 것이 아니다.

핵심은 다음 여섯 문장이 실제 플레이에서 성립하도록 만드는 것이다.

```text
한 손패에서 고민이 생긴다.

구매한 카드가 돌아왔을 때 기쁘다.

내가 선택한 프로그램이 전장에서 완전히 다른 형태로 나타난다.

ARCHIVE 때문에 지금 약해지지만, OPEN CHANNEL에서 그 약점이 압도적인 힘으로 바뀐다.

노아가 내가 좋아한 기술을 흉내 내면서 캐릭터와 보스전이 하나가 된다.

64칸을 어떤 대답으로 채웠는지가 내가 만든 덱과 관계와 엔딩을 동시에 말해 준다.
```

이 여섯 가지가 성립하면 ECHO/144는 자동 공격 게임에 카드 상점을 붙인 작품이 아니다.

> **내가 편성한 방송을 직접 송출하고, 그 방송을 학습한 완벽한 가짜 관객과 싸우며, 어떤 대답을 진짜로 받아들일지 결정하는 1.44MB 차원 생방송 덱빌더**가 된다.

이 수치는 이동·스케줄러·GDI 문제를 수정하기 전 기준이며, V2 메커니즘 재설계는 별도의 개발 범위다.

# 부록 C. 자동 실행 메커니즘의 단계별 결정 이력

## C.1 최초 현행안

```text
5장 손패 전부 자동 실행
플레이어는 이동
손패당 SEEK 1회
상점에서 한 장 구매
```

장점:

- 접근이 쉬움.
- 이동 흐름이 끊기지 않음.
- 작은 화면과 적은 버튼에 적합.

문제:

- 손패 의사결정이 약함.
- PROGRAM이 서로 충돌하지 않음.
- 덱빌딩이 상점 선택으로만 느껴짐.

## C.2 중간 하이브리드안

```text
다음 5장 미리보기
새 손패 때 0.6~0.8초 25% 슬로모션
PROGRAM 한 장을 CUE
나머지 카드는 자동 또는 OFF AIR 약효과
```

장점:

- 실시간 흐름 보존.
- 한 손패당 한 번의 선택.
- 기존 코드에서 비교적 작은 변경.

한계:

- 사용자가 더 직접적인 전략 선택과 복잡성을 원함.
- 모든 카드가 여전히 흘러가는 구조가 도미니언 감각을 충분히 복원하지 못할 가능성.

## C.3 현재 정본

```text
EDIT
명시적인 PROGRAM 선택과 CUE

ON AIR
8초 실시간 이동과 수동 발동

BREAK
BAUD 구매

CLEANUP
버림·셔플·캐시
```

선택 이유:

- 직접 전략을 고민하는 감각 강화.
- 도미니언의 액션 경제 복원.
- 적 의도와 손패 대응 연결.
- 카드의 수동 위치·타이밍 가치 생성.
- 입문은 정지 편성·추천·자동 발동으로 보호.

- 1997 시간층.
- 숨겨진 호스트 로그.
- BBS UI 스킨.

## D.3 여러 시대의 UNLISTED LIVE

현재 정본.
