# 41 — 픽셀 아트 제작 규격

[40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md) §1의 아트 방향(금지 목록 포함)을 전제로, 실제 픽셀 제작의 기법·포맷·공정·수용 기준을 정의한다. 제작자는 Claude — `.px` 그리드로 그리고, PNG로 렌더해 직접 눈으로 검수하고, 통과분만 C 배열로 변환한다.

## 1. 조사 요약 — 무엇을 훔치고 무엇을 버리는가

**PC-98 문법** (1997 설정·오타쿠 취향과 정확히 일치):
- 16색 제약 아래 디더링으로 그라데이션·질감을 만든 애니메 초상 중심의 화면. 어두운 배경 위 보석색 포인트.
- 본작 번역: 초상(48×48)에만 2×1 체커 디더 허용. **디더는 "면"에만, 얼굴 윤곽·눈에는 금지**(뭉개짐). 16×16 스프라이트는 디더 전면 금지 — 클러스터를 크게 유지.
- 참고: [What's unique about PC98 art? — Pixel Glade](https://pixelglade.net.au/blog/posts/2025-08-31-Whats-unique-about-PC98-art.html), [PC-98 — Aesthetics Wiki](https://aesthetics.fandom.com/wiki/PC-98), [PC-98 팔레트 모음 — Lospec](https://lospec.com/palette-list/tag/pc98), [Dithering for Pixel Artists — Pixel Parmesan](https://pixelparmesan.com/blog/dithering-for-pixel-artists)

**16×16 실루엣 원칙**:
- 실루엣을 단색으로 채워도 누구인지 읽혀야 하며, 부위당 색 2~3개, 디테일은 픽셀 1~2개로 끝낸다. 가장 좋은 16×16은 가장 정밀한 것이 아니라 가장 잘 읽히는 것.
- 참고: [Draw 16×16 Character — Lospec 튜토리얼](https://lospec.com/pixel-art-tutorials/how-to-pixel-art-tutorials-6-draw-16x16-character-by-dual-core-studio), [16×16 Pixel Art Tutorial — Photon Storm](https://photonstorm.com/art/tutorials-art/16x16-pixel-art-tutorial)

**오타쿠 어필의 실행 수단** (40 §1 금지 목록 — 교복·메이드·고양이귀·노출 — 을 지키면서):
- **머리카락이 정체성의 절반**: 실루엣 차별화는 헤어 셰이프로 만든다. 에코 = 비대칭 롱 스트랜드 + 끊긴 링 헤어 액세서리, 시크 = 둥근 몸 + 리본 케이블, 포맷 = 수직 베일.
- **눈이 나머지 절반**: 16×16은 세로 1×2 다크 픽셀(애니메 눈 비율), 48×48은 큰 눈 + 하이라이트 1px + 캐릭터별 눈매(에코 둥글게 / 시크 ∧ 곡선 / 포맷 반개).
- 3등신 치비(머리:몸 ≈ 9:7px), 포즈는 당당하게 — 귀여움은 반응 속도와 자세에서, 무력함이 아니라.
- **CRT 듀오톤 초상**: 3색 제약을 약점이 아니라 스타일로 — "채널 불빛에 물든 얼굴". 피부색이 없는 것이 아니라 모니터 광이 도는 것.

## 2. 기술 포맷

- **2bpp, 인덱스 0=투명(초상은 0=배경)**, 4px/바이트 MSB-first, 행 우선. 런타임에 32비트 캐시로 언팩(기존 계획 유지, 30 §2).
- 소스는 `assets/px/*.px` 텍스트 그리드(문자 `.123`), 변환·검수는 `tools/px_render.ps1`(Windows) 또는 `tools/px_render.py`(크로스플랫폼, 의존성 없음):

```text
powershell -File tools\px_render.ps1 -Path assets\px\echo_16_a.px           # PNG 렌더(검수)
python3 tools/px_render.py assets/px/echo_16_a.px --scale 3 --bg 100d18     # 실크기·게임 배경 시뮬레이션
python3 tools/px_render.py assets/px/*.px --sheet out.png --bg 100d18       # 여러 장 나란히 비교
python3 tools/px_render.py assets/px/echo_16_a.px --emit-c                  # C 배열 출력
```

- 초상 3장은 `tools/px_portraits.py`가 베이스 지오메트리(타원·디더·눈꺼풀 곡선)를 생성한다. **`.px` 파일이 정본**이며 재생성은 손 튜닝을 덮어쓰므로 주의.
- `assets/`와 `tools/`는 제출물에 포함되지 않는다. 게임에는 emit된 배열만 들어간다(`src/echo144.c`의 W5 픽셀 아트 구획).

## 3. 캐릭터 램프 — 3색의 배분

공용 어둠·공용 백색 + 캐릭터 강조색 1개. 명도차가 커서 색약·저자극에서도 자동으로 구분된다.

| 캐릭터 | 1 어둠 | 2 강조 | 3 광 | 코드 오버레이 |
|---|---|---|---|---|
| 에코 일사사 | `1a1626` | 청록 `4ddbc8` | `f2f0e6` | 빨간 LIVE 핀 1px (`e55b57`) |
| 시크 웜 | `1a1626` | 호박 `e5a84b` | `f2f0e6` | — |
| 포맷 제로 | `1a1626` | 자홍 `ed4f9a` | `f2f0e6` | 베일 진행 막대(게이지 연동) |

- 외곽선: 전면 윤곽선 금지. **배경과 닿는 밝은 면에만 선택적 어둠 1px**(셀렉티브 아웃라인). 어두운 배경(`100d18`) 위이므로 어둠(1)이 실루엣 역할을 겸한다.
- 16×16에서 강조색은 면적의 30~60%를 가져야 한다 — 멀리서 색만으로 캐릭터가 구분되게.

**적·탄·보물상자는 도형 → 시스템 글리프로 승격**(2026-07-15). 원래 "도형=시스템, 스프라이트=인물" 대비를 이유로 도형 유지였으나, **인간화하지 않는 아이콘**으로 만들면 그 대비를 지키면서 가독·완성도를 함께 올릴 수 있다. 웜=무채색 벌레 블롭, 팝업="주문하지 않은 창"(닫기 표식), 트로이=청색 선물상자("선물 아닌 것"), 랜섬=빨간 자물쇠, 적 탄=빨간 다이아 패킷, 플레이어 탄=청록 신호 비트. **보물상자 = 3.5인치 플로피 디스크** — 1.44MB 세계관에 정확히 맞는 루트 컨테이너. 엘리트는 여전히 seek_16(인물). 즉 시스템 객체는 사물 아이콘, 인물은 캐릭터 스프라이트라는 서사 규칙은 강화된다.

애니메이션은 40 §1 모션 문법(각 4프레임 상한, 반전·1px 오프셋·팔레트 교환)을 따른다. 에코 대기 2프레임 = 링이 반 박자 늦게 따라오는 2픽셀 차이.

## 5. 제작 공정 — 5단계 루프

1. **실루엣**: 단색(어둠)만으로 블랙필 형태를 잡는다. 렌더 → 검정 채움 상태로 캐릭터가 구분되면 통과.
2. **램프 배분**: 강조/광을 클러스터 단위로 채운다. 픽셀 1개짜리 고아 픽셀 금지(눈·하이라이트 제외).
3. **렌더 검수**: 14× 렌더를 Claude가 Read로 직접 보고 형태·가독성·매력을 판정. 불통과면 그리드 수정 후 반복.
4. **실크기 검증**: 3× 렌더(게임 창 배율)와 1×로 뭉개짐 확인. 게임 배경색 위 시뮬레이션.
5. **emit-c**: 통과분만 C 배열로 변환해 `src/echo144.c` 데이터 구획에 삽입, `draw_sprite_2bpp()` 경로로 교체.

## 6. 수용 기준

- 블랙필 실루엣만으로 3캐릭터 구분(자기 판정 + G2 테스터 3/5 확인 문항 재사용).
- 16×16을 1×로 봐도 머리/몸/눈 위치가 읽힌다.
- 저자극·게임 배경 위에서 캐릭터 강조색 구분 유지.
- 각 스프라이트에 `비대칭 1곳 + 강조색 1개 + 반복 도형 1개`(40 §1)가 실제로 존재 — 16×16에서 사라졌으면 실패.
- 프레임 4개 이내, 자산 합계 4KB 이내.

## 7. 캐릭터별 디자인 결정 기록

검수 루프에서 확정된, 그리드만 봐서는 이유가 안 보이는 결정들:

- **에코**: 끊긴 링은 스프라이트에서도 우상단 4×4 오픈 링(상단 1px 끊김)으로 항상 떠 있다. 대기 B는 링 1px 하강 + 스트랜드 끝 1px — "링이 반 박자 늦게"의 최소 구현. 발끝 흰 부츠 1행이 다크 다리를 배경에서 건져낸다.
- **시크**: 다크 몸이 게임 배경에 녹는 문제를 "깨진 버퍼 링"을 몸 둘레 아웃라인으로 승격해 해결 — 끊김 2곳(우상단·좌하단)이 로딩 중 아이콘처럼 읽힌다. 링 정점 1px는 아호게로 읽혀 유지. 초상의 우상단 사선 스텁은 끊긴 링의 단면이다.
- **포맷**: 검정 제복이 배경에 녹으므로 왼쪽에만 자홍 세로 엣지(비대칭 겸용). 눈은 규격의 다크 1×2 대신 **자홍 발광 반개 1px** — 비인간 데몬 캐릭터성이 우선하는 유일한 예외. 초상의 진행 막대는 베일이 아니라 칼라(가슴)에 있고 75% 채움 — FORMAT 경고 임계와 같은 숫자.

## 8. 진행 상태 (2026-07-15)

- **자산 11종 전부 완성·수용 기준 통과**: 16×16 8프레임 + 초상 3장. 블랙필 실루엣 3종 구분, 1× 가독, 게임 배경(`100d18`)·다이얼로그 배경(`201c2b`) 위 검수 완료.
- **인게임 반영 완료**: `src/echo144.c`에 2bpp 데이터(2,240B) + `draw_sprite_2bpp()` 탑재, `draw_echo/seek/format` 교체. gcc 하니스로 11종 디코드가 `.px` 원본과 일치함을 검증.
  - 프레임 배선: 에코 대기 A/B(16틱 플립)·피격(무적 중)·LIVE / 시크 피격 = SEEK 카드 사용 순간(`seek_fx_ticks`, "붙잡기"와 동기) / 포맷 B = 전환 중 8틱 맥동.
  - 타이틀 재배치: 좌 에코 초상(+빨간 핀 2×2) — DIM 회선 — 우 포맷 초상, **시크 16×16이 회선 위에 앉아 있다**(시청자 1의 시각화). GO LIVE 전환 박스는 포맷 초상 48×48.
- **시스템 글리프 7종 제작·배선 완료(2026-07-15)**: 적 4종·탄 2종·플로피 보물상자를 `draw_world()`에 배선. gcc 하니스로 전체 18종(인물 11 + 글리프 7) 디코드가 `.px` 원본과 일치함을 검증. 아레나 합성 장면으로 실전 가독 확인.
  - **잠복 버그 수정**: `draw_sprite_2bpp()`가 데이터를 행 패딩 없이 연속으로 인덱싱했다(`(y*size+x)/4`). emit는 행마다 `ceil(w/4)` 바이트로 패딩하므로, **폭이 4의 배수가 아닌 스프라이트**(예: shot_6)가 깨진다. 기존 11종은 전부 4의 배수라 우연히 맞았다. stride 기반(`y*stride+(x>>2)`)으로 수정 — 4의 배수일 때 수학적으로 동일, 임의 폭에 안전.
- **결과·엔딩 화면 초상 연출 완료(2026-07-15)**: `draw_result()` 우측 여백에 승리=에코 / 패배=포맷 초상(48×48). `draw_ending()`(64/64 성공)은 검은 화면에 에코 LIVE 스프라이트를 홀로 띄워 "시청자 1"의 고독을 시각화. 실좌표 목업 렌더로 배치 확인.
- 남은 것(W5 후속): 엘리트 피격 프레임의 전용 트리거(현재는 SEEK 카드 연동), **Windows 실빌드 스크린샷 검수**(MSVC 필요 — 리눅스 세션에서는 렌더러 시뮬 목업으로 대체, 실캡처는 G-게이트 수동 항목으로 유지), G2 테스터 실루엣 확인 문항.
