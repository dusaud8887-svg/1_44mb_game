# 41 — 픽셀 아트 제작 규격

[40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md) §1의 아트 방향(금지 목록 포함)을 전제로, 실제 픽셀 제작의 기법·포맷·공정·수용 기준을 정의한다. 제작자는 Claude — `.px` 그리드로 그리고, PNG로 렌더해 직접 눈으로 검수하고, 통과분만 C 배열로 변환한다.

## 1. 조사 요약 — 무엇을 훔치고 무엇을 버리는가

**PC-98 문법** (1997 설정·오타쿠 취향과 정확히 일치):
- 16색 제약 아래 디더링으로 그라데이션·질감을 만든 애니메 초상 중심의 화면. 어두운 배경 위 보석색 포인트.
- 본작 번역: 초상(48×48)에만 2×1 체커 디더 허용. **디더는 "면"에만, 얼굴 윤곽·눈에는 금지**(뭉개짐). 16×16 스프라이트는 디더 전면 금지 — 클러스터를 크게 유지.
- 참고: [What's unique about PC98 art? — Pixel Glade](https://pixelglade.net.au/blog/posts/2025-08-31-Whats-unique-about-PC98-art.html), [PC-98 — Aesthetics Wiki](https://aesthetics.fandom.com/wiki/PC-98), [PC-98 팔레트 모음 — Lospec](https://lospec.com/palette-list/tag/pc98), [Dithering for Pixel Artists — Pixel Parmesan](https://pixelparmesan.com/blog/dithering-for-pixel-artists)

**16×16 실루엣 원칙**:
- 실루엣을 단색으로 채워도 누구인지 읽혀야 하며, 부위당 색 2~3개, 디테일은 픽셀 1~2개로 끝낸다. 가장 좋은 16×16은 가장 정밀한 것이 아니라 가장 잘 읽히는 것.
- 참고: [Draw 16×16 Character — Lospec 튜토리얼](https://lospec.com/pixel-art-tutorials/how-to-pixel-art-tutorials-6-draw-16x16-character-by-dual-core-studio), [16×16 Pixel Art Tutorial — Photon Storm](https://photonstorm.com/art/tutorials-art/16x16-pixel-art-tutorial)

**오타쿠 어필의 실행 수단** (40 §1 금지 목록 — 교복·메이드·고양이귀·노출 — 을 지키면서):
- **머리카락이 정체성의 절반**: 실루엣 차별화는 헤어 셰이프로 만든다. 에코 = 비대칭 롱 스트랜드 + 끊긴 링 헤어 액세서리, 시크 = 둥근 몸 + 리본 케이블, 포맷 = 수직 베일.
- **눈이 나머지 절반**: 16×16은 세로 1×2 다크 픽셀(애니메 눈 비율), 48×48은 큰 눈 + 하이라이트 1px + 캐릭터별 눈매(에코 둥글게 / 시크 ∧ 곡선 / 포맷 반개).
- 3등신 치비(머리:몸 ≈ 9:7px), 포즈는 당당하게 — 귀여움은 반응 속도와 자세에서, 무력함이 아니라.
- **CRT 듀오톤 초상**: 3색 제약을 약점이 아니라 스타일로 — "채널 불빛에 물든 얼굴". 피부색이 없는 것이 아니라 모니터 광이 도는 것.

## 2. 기술 포맷

- **2bpp, 인덱스 0=투명(초상은 0=배경)**, 4px/바이트 MSB-first, 행 우선. 런타임에 32비트 캐시로 언팩(기존 계획 유지, 30 §2).
- 소스는 `assets/px/*.px` 텍스트 그리드(문자 `.123`), 변환·검수는 `tools/px_render.ps1`:

```text
powershell -File tools\px_render.ps1 -Path assets\px\echo_16.px            # PNG 렌더(검수)
powershell -File tools\px_render.ps1 -Path assets\px\echo_16.px -Scale 3   # 실크기 감각 확인
powershell -File tools\px_render.ps1 -Path assets\px\echo_16.px -EmitC     # C 배열 출력
```

- `assets/`와 `tools/`는 제출물에 포함되지 않는다. 게임에는 emit된 배열만 들어간다.

## 3. 캐릭터 램프 — 3색의 배분

공용 어둠·공용 백색 + 캐릭터 강조색 1개. 명도차가 커서 색약·저자극에서도 자동으로 구분된다.

| 캐릭터 | 1 어둠 | 2 강조 | 3 광 | 코드 오버레이 |
|---|---|---|---|---|
| 에코 일사사 | `1a1626` | 청록 `4ddbc8` | `f2f0e6` | 빨간 LIVE 핀 1px (`e55b57`) |
| 시크 웜 | `1a1626` | 호박 `e5a84b` | `f2f0e6` | — |
| 포맷 제로 | `1a1626` | 자홍 `ed4f9a` | `f2f0e6` | 베일 진행 막대(게이지 연동) |

- 외곽선: 전면 윤곽선 금지. **배경과 닿는 밝은 면에만 선택적 어둠 1px**(셀렉티브 아웃라인). 어두운 배경(`100d18`) 위이므로 어둠(1)이 실루엣 역할을 겸한다.
- 16×16에서 강조색은 면적의 30~60%를 가져야 한다 — 멀리서 색만으로 캐릭터가 구분되게.

## 4. 자산 목록과 바이트 예산

| 자산 | 크기 | 프레임 | raw 바이트 |
|---|---|---:|---:|
| echo_16 (대기2·피격1·LIVE1) | 16×16 | 4 | 256 |
| seek_16 (엘리트, 등장·피격) | 16×16 | 2 | 128 |
| format_16 (전환·결과 연출) | 16×16 | 2 | 128 |
| 초상 echo/seek/format_48 | 48×48 | 각1 | 1,728 |
| 합계 | | | **2,240** (팔레트 테이블 제외, 목표 4KB 이하 여유) |

일반 적 8×8은 현행 도형(원+색)이 이미 기능적으로 읽히므로 P0 유지 — 캐릭터 3인과의 대비(도형=시스템, 스프라이트=인물)가 오히려 서사에 맞는다. 여유 시에만 재검토.

애니메이션은 40 §1 모션 문법(각 4프레임 상한, 반전·1px 오프셋·팔레트 교환)을 따른다. 에코 대기 2프레임 = 링이 반 박자 늦게 따라오는 2픽셀 차이.

## 5. 제작 공정 — 5단계 루프

1. **실루엣**: 단색(어둠)만으로 블랙필 형태를 잡는다. 렌더 → 검정 채움 상태로 캐릭터가 구분되면 통과.
2. **램프 배분**: 강조/광을 클러스터 단위로 채운다. 픽셀 1개짜리 고아 픽셀 금지(눈·하이라이트 제외).
3. **렌더 검수**: 14× 렌더를 Claude가 Read로 직접 보고 형태·가독성·매력을 판정. 불통과면 그리드 수정 후 반복.
4. **실크기 검증**: 3× 렌더(게임 창 배율)와 1×로 뭉개짐 확인. 게임 배경색 위 시뮬레이션.
5. **emit-c**: 통과분만 C 배열로 변환해 `src/echo144.c` 데이터 구획에 삽입, `draw_sprite_2bpp()` 경로로 교체.

## 6. 수용 기준

- 블랙필 실루엣만으로 3캐릭터 구분(자기 판정 + G2 테스터 3/5 확인 문항 재사용).
- 16×16을 1×로 봐도 머리/몸/눈 위치가 읽힌다.
- 저자극·게임 배경 위에서 캐릭터 강조색 구분 유지.
- 각 스프라이트에 `비대칭 1곳 + 강조색 1개 + 반복 도형 1개`(40 §1)가 실제로 존재 — 16×16에서 사라졌으면 실패.
- 프레임 4개 이내, 자산 합계 4KB 이내.
