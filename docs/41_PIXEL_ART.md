# 41 — 픽셀 제작 규격·파이프라인 (V2)

[40_ART_AUDIO_TEXT.md](40_ART_AUDIO_TEXT.md)의 방향을 실제 픽셀로 만드는 도구·규격·작화 매뉴얼·검수 자동화·제작 단계의 정본. **V1 제작 규격·자산 이력(.px 정본 공정, 자산 18종 제작 기록)은 [archive/v1-last-live/41_PIXEL_ART.md](archive/v1-last-live/41_PIXEL_ART.md)에 동결** — 파이프라인 전환의 결정 이력은 [adr/0008-art-pipeline-v2.md](adr/0008-art-pipeline-v2.md).

## 1. 자산 정책 — 이름을 바꾸는 것이 아니라 다시 설계한다

V1 자산은 `포맷 제로`·`LAST LIVE`·`시청자 1`·자동 발동 이펙트에 맞춰 만들어졌다. **부분 수정·재라벨로는 부족하다.**

1. 기존 V1 자산은 `assets/archive_v1/`(자산)과 archive 문서(규격)로 동결한다. V2 코드가 V1 자산을 직접 참조하지 않는다.
2. **브랜드 DNA만 계승한다**: 청록·호박·자홍 삼분, 끊긴 링, 케이블, 수직 실루엣, 흰 장갑, 국소 오류, 네거티브 스페이스, 인물↔시스템 오브젝트의 조형 차이.
3. 캐릭터 전신·초상·키아트·카드 아이콘·적·HUD·공격 이펙트는 **V2 기준으로 재설계**한다.
4. V1의 진단(재설계가 필요한 이유): 세 초상이 같은 얼굴 베이스 공유 / 차이가 머리색·장식에 집중 / 어깨·목·손·소품의 물리 연결 약함 / 정면 대칭이라 감정·관계 부재 / 시크 링·케이블의 시작점 불명 / 카드 발동 대부분이 탄환·범위로 수렴. **원인은 해상도가 아니라, 인물별 골격·자세·행동 규칙 없이 공통 지오메트리에서 출발한 것이다.**
5. 재사용 가치가 있는 V1 자산(잘 읽히는 카드 아이콘 일부, 적 글리프의 개념, 팔레트 감각)은 **참고 자료**로 쓰되 V2 규격으로 다시 그린다.

### 왜 24×24인가

16×16은 적·아이콘·마스코트에 충분하지만, V2 에코는 CUE 선택 / 수동 발동 / LIVE 핀을 붙잡는 피격 / OPEN CHANNEL 자세 변화 / 개입 반응을 **행동으로** 보여야 한다. 24×24는 손·소매·헤드셋·링의 상대 위치를 읽게 하면서 화면을 과점하지 않는다. 히트박스는 스프라이트보다 작게(6×7, [45](45_UI_UX.md) §7).

### 원시 데이터 감각

24×24 4bpp 1프레임 288B → 에코 12프레임 ≈3.4KB, 네임드 3명 36프레임 ≈10.4KB / 64×64 초상 2KB×3 = 6KB / 카드 아이콘 24종 1.5KB / 적·프로필·파티클 5~12KB / 글리프 500개 ≈6KB / 320×180 키아트 28.8KB. **델타·RLE 없이도 핵심 아트는 100KB 안팎이다.** 카테고리 예산은 [30](30_TECH.md) §9.

### 앵커 규칙 — 아트와 코드의 계약

모든 전장 스프라이트는 메타데이터를 가진다 (코드 enum과 1:1, `[본 개정 구체화]`):

```text
pivot_x / pivot_y     발밑 또는 몸 중심 — 프레임 간 흔들림 금지
hitbox / hurtbox      별도 사각형
hand_socket           기술 기점        head_socket   링·프로필 환 기점
cable_socket          시크 케이블 시작점
fx_under / fx_over    이펙트 레이어 기준
```

액세서리의 흔들림은 피벗 이동이 아니라 픽셀 애니메이션으로 표현한다.

## 3. 도구와 소스 포맷

원칙: **런타임 제약과 제작 도구 제약을 분리한다.** 최종 게임은 C11+내장 비트맵이지만 제작 환경은 자유다 — 도구 용량은 EXE에 들어가지 않는다. 1.44MB를 이유로 원본을 텍스트 그리드로 편집하면 레이어·프레임·피벗·검수가 어려워져 품질이 떨어진다.

- **1순위 Aseprite**: 레이어·프레임 태그·타임라인·팔레트·슬라이스·CLI 배치 Export. 흐름: `.aseprite(원본) → indexed PNG + JSON → assetc.py → generated/*.inc`. Aseprite 파일은 EXE에 넣지 않는다.
- 2순위 Pixelorama(오픈소스 공용 환경), 3순위 LibreSprite. 채택 전 작은 자산으로 CLI·JSON 안정성을 먼저 검증.
- 고해상 일러스트·모델 시트: Krita / CSP / Photoshop / Affinity, 워드마크는 벡터 도구. 중요한 것은 도구가 아니라 레이어 명명 규칙·팔레트 스와치·안전영역 가이드·버전 관리 가능한 내보내기.
- **`.px`의 새 역할** (원본에서 강등): 코드 리뷰용 사람이 읽는 덤프 / 작은 1bpp 아이콘의 빠른 수정 / 생성 결과 diff / 테스트 fixture / 도구 없는 긴급 수정. 캐릭터·초상·애니메이션의 원본으로는 쓰지 않는다.
- **레벨·배경 편집기**: 한 화면 아레나 + 절차 배경인 현재는 LDtk·Tiled를 도입하지 않는다. 확장판에서 다중 방·충돌 타일·이벤트 트리거·NPC 배치가 생기면 검토(LDtk = JSON·엔티티 정의 명확 / Tiled = 넓은 생태계). 어느 쪽이든 **런타임 파서는 넣지 않고 빌드 시 C 배열로 컴파일**한다.

### 원본 레이어 규격 (예: `art/src/characters/echo_v2.aseprite`)

```text
GUIDE(grid/pivots/hitbox/effect_anchor) / FX_OVER(ring_front/live_pin_glow/cast_fx)
BODY_FRONT(hand_front/hair_front/face/jacket_front) / BODY(torso/legs/head)
BODY_BACK(hair_back/jacket_back/hand_back) / FX_UNDER(ring_back/shadow)
```

과분화 금지 — 비대칭 소품·앞뒤 관계·팔레트 교체가 필요한 요소만 분리한다.

### 애니메이션 태그 (ASCII 소문자·언더스코어, 코드 ID와 1:1)

### Git 관리·파일명

추적: `.aseprite`·`.kra`·팔레트·JSON·스크립트 / 선택 추적: preview PNG·contact sheet / 자동 생성: `generated/*.inc`·리포트 / 릴리스: EXE. 파일명은 `chr_echo_cast_short_00`, `por_echo_hear_reply`, `boss_noa_trend_firewall_00`, `bg_1997_board_tile_00` 형식 — **`final`, `new`, `fix` 금지**, 버전은 Git이 담당.

## 4. 작화 매뉴얼

**픽셀 아트는 저해상도 그림이 아니다.** 고해상 그림을 축소해 계단을 남기지 않는다 — 캔버스 크기에서 직접 픽셀 군집을 설계한다: `실루엣 → 큰 명암 덩어리 → 얼굴·소품 기준점 → 내부 재질 분리 → 선택적 외곽선 → 1픽셀 표정·강조 → 실제 게임 화면 검수`.

- **클러스터 우선**: 픽셀 1개보다 2×2·2×3·L자 덩어리 먼저. 고립 픽셀은 눈동자·LIVE 핀·메아리·금속 반사처럼 의미가 있을 때만. 넓은 면에 소금·후추 노이즈 금지.
- **외곽선**: 전부 검은 1px로 두르면 굳는다. 위험 배경과 접하는 면만 BROADCAST BLACK, 밝은 배경 접면은 캐릭터의 어두운 고유색, 내부 분리는 명암 면으로. 에코 링·시크 케이블·NØA 베일은 본체와 다른 선 굵기 문법.
- **계단선**: 곡선 계단은 일정한 리듬(`1-1-2-2-3` 좋음 / `1-3-1-4-1` 나쁨). 단, **NØA의 완전 기하 vs 에코·시크의 유기적 비대칭**을 구분 — 에코 링은 구획이 자연스럽게 어긋나고, NØA 프로필 환은 지나치게 정확하다(그것이 캐릭터다).
- **밴딩 방지**: 같은 길이의 평행 픽셀선 연속 금지 — 얼굴 윤곽과 머리카락 내부 선, 라펠과 팔 외곽이 평행하게 붙지 않게. 프로필 환의 반복은 의도적 기계성일 때만.
- **명암**: 24×24 = 3단계(어둠/기본/광), 얼굴은 기본색+눈·입만, **디더 금지**. 64×64 초상 = 4단계 이내, 재질은 색면으로 구분, 투명도 AA 금지. 대형 키아트 = 4bpp, 넓은 배경·광원에만 제한적 디더.
- **디더 규율**: 디더는 "레트로 패턴"이 아니다. 허용 — 넓은 어둠의 두 색 전이 / NØA 그림자의 빈 관객석 질감 / 2097 원경 / 키아트 대형 광원. 금지 — 16×16 아이콘 / 24×24 피부 / UI 패널 / 카드명 주변 / 모든 그림자 면.
- **서브픽셀 모션**: 블러·반투명 보간 대신 프레임 간 픽셀 배치 변경 — 머리카락 끝 1px 하강+몸 정지 / 링이 한 틱 늦게 이동 / 케이블 굽은 부분만 이동 / NØA 베일은 본체와 다른 스크롤 속도.
- **홀드**: 균등 재생 금지 — `대기 8-8-6-10틱 / 걷기 4-4-4-4 / CUE 준비4·점등2·홀드4 / 피격 충돌1·눌림2·복귀3 / NØA 미소 기본30·이상1·기본45`. **NØA의 공포 프레임은 자주 재생할수록 약해진다** — 조건·긴 간격.
- **좌우 반전**: 단순 미러 불가 요소 — LIVE 핀·한쪽 헤드셋·재킷 여밈·시크 케이블 포트·NØA 장갑과 베일. 기준 프레임 + 비대칭 델타 또는 소품 오버레이로 처리(전체 프레임 2배 저장 금지).
- **캐릭터별 작화 차이**: 에코 = 둥근 클러스터·한쪽으로 열린 곡선·약간 어긋난 표정·움직임이 관객 쪽으로 열림 / 시크 = 낮고 감기는 곡선·케이블이 본체보다 먼저 움직임·얼굴 일부 항상 가림·태그가 후행 / NØA = 수직선·완전 대칭·본체는 적게 움직이고 주변이 움직임·이상 상태에도 얼굴은 안정.
- **1×·3×·8× 동시 검수**: 확대 화면만 보지 않는다. 1×에서 안 읽히는 디테일은 핵심이 아니고, 8×에서 예쁘지만 1×에서 노이즈면 삭제.
- **흑백 실루엣 테스트**: 완전 검정으로 채워도 — 에코(링·긴 한쪽 머리·열린 자세) / 시크(낮은 몸·케이블 릴·감기는 꼬리) / NØA(수직 베일·프로필 환·장갑 포즈) / BOT.CHAT(말풍선) / POP.AD(창) / MOD.MASK(봉인 도장) / SPON.GIFT(선물+프로필)가 구분되어야 한다.

승인 체크: 고립 픽셀 의도성 / 계단 일정성 / 밴딩 없음 / 얼굴 상호 구분 / 손·소품 물리 연결 / 외곽선 무게 / 디더의 기능 정보 비침범 / 1× 실루엣 / 혼잡 배경 위 우선순위 / 반전 시 설정 오류 없음 / 발 피벗·발사점 프레임 안정.

## 5. 자산 컴파일·검수 자동화

목표: 편집기는 편하게, EXE에는 필요한 픽셀·메타데이터만, 오류는 빌드 전에, 수동 복사로 인한 코드-자산 불일치 제거.

```text
Aseprite/Pixelorama 원본 → export → indexed PNG + JSON
  → assetc.py (팔레트 검증 → 프레임 크롭 → 2/4bpp 패킹 → RLE·델타 후보 비교 → 메타데이터)
  → generated/assets.inc + assets_meta.inc + art_report.md
  → MSVC unity build → size report + screenshot tests
```

스크립트 구성: `art_export.py`(변경 파일만 CLI Export) / `assetc.py` / `art_lint.py` / `contact_sheet.py` / `render_reference.py`(게임 렌더러와 같은 규칙의 미리보기) / `screenshot_diff.py` / `glyph_subset.py` / `content_report.py`.

### art_lint 검수 항목

- 공통: 허용 캔버스·허용 팔레트만 / 반투명 금지 / 빈 프레임·프레임 밖 픽셀·중복 프레임 / 누락 태그 / 잘못된 파일명.
- 캐릭터: 발 피벗·hitbox·cast anchor 존재 / 좌우 비대칭 보정 / LIVE 핀·장갑·케이블 포트 기준 픽셀.
- 카드: 16×16 / 실루엣 면적 범위 / 타입 탭과 아이콘 비충돌 / 배경 투명 / 경계 비침범.
- UI: 글리프 누락 0 / 텍스트 최대 폭 / 320×240 안전영역 / 대비 기준.

### 팔레트 검증 정책

허용 색과 근소하게 다른 색을 **가장 가까운 색으로 조용히 매핑하지 않는다** — 실수 색을 통과시키면 원본과 게임이 달라진다. `정확 일치=통과 / 허용 오차 모드=미리보기만 / 릴리스 빌드=불일치 즉시 실패`.

### 크롭·압축·리포트

- 투명 여백을 크롭하되 원본 피벗을 메타데이터로 보존 (`SpriteFrame { offset, packed_size, w, h, pivot_x, pivot_y, duration, encoding, palette_map, flags }`).
- 자산·애니메이션별로 `RAW packed / RLE / base+delta` 세 방식을 자동 비교, **해제 코드 비용을 포함한 전체 EXE 크기**로 최소를 선택.
- contact sheet 자동 생성: 전 프레임 1×·4× / 표정 초상 / 아이콘 무명판 / 적 흑백 실루엣판 / 색각 변환판 / 좌우 반전 오류판 / **95퍼센타일 혼잡 화면**. 리뷰는 개별 PNG가 아니라 시트 중심.
- 스크린샷 회귀: 결정론 시드+입력 리플레이로 `title / edit_first_turn / air_firewall / break_first_purchase / shuffle_card_return / open_channel_16 / open_channel_48 / trend_mirror / ending_cyan / ending_amber / ending_magenta` 자동 캡처, 픽셀 일치 기본(무관 정보 마스킹), 의도된 변경은 기준 갱신+이유 기록.
- 빌드마다 카테고리별 raw/packed/frames 용량 보고서 출력 — 특정 자산의 비대화를 조기 발견.
- 결정론: 파일 목록 정렬·JSON 키 순서 고정·생성 시간 제외 — 같은 입력이면 같은 `.inc`와 해시(`ECHO_ASSET_BUILD_HASH`). `generated/` 첫 줄에 `/* GENERATED FILE. DO NOT EDIT. */`.

## 6. AI 사용 규정 — slop은 프롬프트가 아니라 공정으로 막는다

이 프로젝트의 AI slop은 손가락 오류만이 아니다 — 절차 생성 픽셀에서도 나타난다: 같은 얼굴에 색만 다름 / 기호가 몸과 물리적으로 연결 안 됨 / 설명할 수 없는 디테일 / 프레임마다 액세서리가 변함 / 정면만 예쁘고 전신·측면 불가 / 의미 없는 문자 배경 / 가짜 픽셀 크기 혼합 / 모든 모서리 발광.

- **허용**: 콘셉트 키워드 확장 / 구도 썸네일 다수 생성 / 조명 비교 / 의상 카테고리 발산 / 소품 목록 / 관계 장면 아이데이션 / 무드보드 / 클리셰·중복 점검.
