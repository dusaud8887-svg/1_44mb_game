## B-공식 — 신호 예상 모델

```text
순환 틱 = 30×덱장수 + 15×ceil(덱장수/5)          (60Hz)
A:\ SIG 예상 = 지침 선송출 + floor(3600/순환 틱) × 덱 SIGNAL 합
```

MULTI 단축·PREFETCH +1은 제외한 보수치 — 실제는 같거나 높다. 검산 기준점: 시작 덱 10장 → 30 / 시작 덱+VOICE 1장(11장) → 54. 이 두 값이 깨지면 공식이나 카드 값이 바뀐 것이다.

## 알려진 밸런스 결함과 수정안

### 결함-1 · MIRROR 경로가 실전에서 도달 불가 — P0 수정 필요

구매 기회는 최대 9회이므로 실전 최대 덱은 19장, MIRROR 보너스는 최대 +9다(문서상 상한 12는 도달 불가). 검산: 19장 덱 순환 630틱(10.5초) → LIVE 5순환. `64 = 보너스 + 5×SIGNAL합`에서 현행(+9)은 SIGNAL합 11이 필요해 9구매 중 6~7구매를 조각에 써야 하고, 그 덱은 4:30까지 생존하지 못한다. 현행 selftest의 MIRROR 스모크는 12장 추가(불가능한 경제)로 통과하므로 증명력이 없다.

**수정(2026-07-14 적용)**: `+2/초과 장, 최대 16`. 19장 덱 → +16, 필요 SIGNAL합 = (64−16)/5 = 9.6 → VOICE 2 + CHAT 4(6구매, 잔여 3구매를 경제·전투에). 코드·selftest(9구매 제약 덱 `10+VOICE2+CHAT4+14K3`)에 반영 완료. 실플레이 성립 여부는 SIM 게이트와 G3에서 최종 확인한다.

### 결함-2 · SEEK 효용 미측정

기대 효용이 작아(5장 중 순서 1회 조정) 장식으로 전락할 위험. DEV 로그의 `seek_used`와 G2 질문("SEEK를 왜 썼나")으로 판정하고, 실패 시 레버는 버튼 추가가 아니라 **SEEK 후 다음 카드 대기 +0.2초(읽기 여유)** 한 가지만 검토한다.

## SIM — 헤드리스 밸런스 시뮬레이터 (P0 도구, W-BAL)

"봇 AI"가 아니라 **스크립트된 구매 정책 4개의 몬테카를로**다. SELF_TEST 하니스를 확장해 전투를 무적 더미로 두고 덱·경제·LIVE만 시뮬레이션한다(회피 실력 변수 제거).

- 정책: ① 경제→CLIP ② 유틸 LINK(MULTI/PREFETCH+조각) ③ CLEAN 압축 ④ MIRROR 증원. 각 정책은 "B로 살 수 있는 우선순위 목록" 한 줄이다.
- 각 정책 × 100 seed, 9 NODE 규칙 준수, GO LIVE는 4:30/6:00 두 변형.
- 산출: 정책별 64 도달률, 도달 중앙 시각, 지침별 편차 → `simtest.csv`.
- **수용 기준**: 4정책 모두 도달률 >0이고 최고 정책이 전체 승리의 70%를 독점하지 않는다. 미달 시 카드 추가가 아니라 B-지침·가격·목표 64를 조정한다.

## 튜닝 절차

1. 수치 변경은 이 파일 → 코드 → selftest 검산 기준점(30/54) 순으로 한 커밋.
2. 사람 테스트 전 SIM으로 후보 값을 거른다. 사람은 재미·가독성 판정에만 쓴다.
3. 지배 전략 발견 시 순서: 가격 → 수치 → 지침 → (최후) 목표 64. 카드·버튼 추가는 레버가 아니다.
