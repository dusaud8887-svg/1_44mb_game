# PART A. 조사 — 도미니언: 재미의 해부

## A-1. 전략 생태계 (커뮤니티 정설 기준)

도미니언의 전략은 5개 원형으로 정리된다. **모든 전략의 출발점은 "빅머니를 이기는 것"**이며, 게임 시작 시 공개되는 왕국 카드 10종을 보고 이길 전략을 구상할 수 있느냐가 중수와 초보를 가른다 — 이것이 도미니언 두뇌싸움의 제1막이다.

| 전략 | 본질 | 핵심 긴장 |
|---|---|---|
| **빅머니** | 재화만 사서 속주 직행. 단순·강력한 베이스라인 | 초보도 강함 → 모든 덱의 가상 적수 |
| **엔진** | 액션추가(마을) + 드로워(대장간) + **페이로드**의 3요소. 덱 전체를 드로우해 폭발적 구매력 | 완성 전까지 약함·패말림. 감내와 타이밍의 게임 |
| **슬로그** | 정원 등 "덱이 불어날수록 점수" 카드로 게임을 질질 끌며 승점 비대화 | 압축이 정설인 게임에서의 역발상 |
| **러시** | 공급처 더미를 빠르게 비워 게임을 조기 종료, 점수 우위 시점에 끝냄 | 종료 타이밍 자체가 무기 |
| **콤보** | 특정 카드 상호작용으로 판을 접수 (예: 예배당 극한 압축 후 옥좌-마녀) | 킹덤 읽기 능력의 정점 |

## A-2. 두뇌싸움의 실체 — 무엇이 "머리를 쓰게" 하는가

1. **킹덤 읽기 (판 시작 30초)**: 10종 조합에서 성립 가능한 아키타입과 그 속도를 추정. 매 판 다른 퍼즐.
2. **그리닝 타이밍**: 승점 전환이 빠르면 덱이 죽고, 늦으면 속주가 동난다. 상대의 전환 신호를 읽고 내 전환점을 정하는 심리전 — **도미니언 재미의 심장**.
3. **압축의 카타르시스**: 예배당은 2코스트임에도 커뮤니티 공인 최강급. 숙련자는 첫 구매로 주저 없이 예배당을 집는다. "버림으로써 강해진다"는 직관 역행의 쾌감.
4. **오염 전쟁**: 마녀의 저주 살포는 상대 덱을 물리적으로 망가뜨린다. 저주·폐허 같은 더미 카드가 굴러들어오면 엔진덱은 꼬여서 돌지 않는다.
5. **파일 컨트롤**: 더미 고갈이 곧 게임 시계. 러시는 시계를 앞당기고 슬로그는 늦춘다.

# PART B. 조사 — 뱀서류: 유저는 실제로 어떻게 노는가

## B-1. 유저 반응에서 추출한 성공 인자 (VS·홀로큐어 커뮤니티 관찰)

VS가 홀로라이브 전체에 유행하고 그 관심이 홀로큐어로 그대로 이동한 과정은 뱀서류 수용사의 좋은 표본이다. 커뮤니티가 반복적으로 꼽는 인자:

1. **단순·직관 구조로 익히기 쉬움** — 조작 진입장벽 제로. 스트리머가 방송하며 떠들 수 있는 인지 여유.
2. **성장과 조합의 재미가 확실함** — 캐릭터 성장 + 무기 조합(진화)이 한 판 안에서 완결.
3. **한 판 30분 내외 + 로그라이트** — 매 판 다른 결과, 반복해도 질리지 않음.
4. **빠른 업데이트/피드백 반영** — 수명 연장 (공모전 스코프 외, 참고만).
5. **관전성** — 옆에서 봐도 뭐가 일어나는지 보임. 홀로큐어가 "부술 수 있는 오브젝트" 같은 유저 기대(뱀서 문법)를 그대로 수용한 것처럼, **장르 문법 준수 자체가 UX**다.
6. **캐릭터 개성** — 홀로큐어의 차별점은 캐릭터별 고유 무기·스킬. 유저는 티어표를 만들고, 약캐로 클리어에 도전하고, 자신에게 맞는 플레이 스타일의 캐릭터를 찾는다.

## B-2. 플레이 행동 패턴 (설계 입력값)

- **초반 3분**: 약한 화력으로 카이팅하며 첫 파워스파이크를 조립 — 여기가 가장 죽기 쉽고 가장 집중함.
- **중반**: 빌드 방향 확정. 레벨업 선택은 사실상 "내 빌드에 맞는 카드 드래프트".
- **후반**: 화면 절멸 파워 판타지 + 방치성. 긴장은 보스 웨이브가 담당.
- **메타 인지**: 유저는 조합 시너지(진화 레시피)를 외우고 커뮤니티에서 공유. **조합 지식 자체가 콘텐츠**.

## C-2. 승부 구조 — 유령 라이벌과 속주 레이스 (v1.0 신규 확정)

도미니언 두뇌싸움의 심장(그리닝 타이밍·파일 레이스)은 상대가 있어야 성립한다. 싱글 게임에서 이를 복원하는 장치:

- **유령 상인 (라이벌 AI)**: 화면 우상단에 초상+속주 카운터로 상존. **빅머니 페이스**로 공유 속주 더미(8장)에서 75초마다 1장 구매 [가정 — 튜닝 변수]. 도미니언 격언 "모든 전략은 빅머니를 이기는 것에서 출발한다"를 문자 그대로 게임 구조로 만든 것.
- **종료 조건**: 속주 더미 고갈 즉시 정산 → **내 VP vs 라이벌 VP**로 승패. 시간제한이 아니라 도미니언식 파일 고갈 종료.
- **파생되는 결정들** (전부 도미니언에서 계승):
  - 그리닝 타이밍: 언제부터 불발탄(VP)을 사기 시작할 것인가
  - 러시: 내가 속주를 사면 게임 시계가 빨라진다 — 화력이 부족해도 시계를 조여 이길 수 있다
  - 슬로그: 정원 뚱덱으로 속주 없이 VP 우위 노리기
  - 보스 처치 보상: 라이벌 다음 구매 15초 지연 — 전투 성과가 레이스에 환류
- **사망 = 즉시 패배** (라이벌 승리 연출). 뱀서의 생존 긴장 유지.

## C-3. 코어 루프 명세

```
[전투 상태 — 상시]
  0.7초 간격으로 덱 상단 1장 자동 발동 (틱)
    재화 → 코인 적립 + 등급별 탄 발사
    액션 → 효과 (버스트/버프/소각/즉발)
    승점·저주 → 불발 (틱 1회 소모, '철컥' 사운드)
  덱 소진 → 리셔플: 0.8초 발사 정지 (재장전 연출, 덱 크기 무관 고정)
  적 처치 → 코인 젬 (자동 흡수 반경)

[상점 상태 — 30초 주기 자동 개점, 8초간]
  시간 배속 10%로 감속 (완전 정지 아님 — 포위 상황 압박 유지)
  킹덤 10종 + 기본 재화/승점 더미 표시, 기본 구매권 1회
  구매 카드는 버림더미로 → 다음 리셔플부터 등장 (도미니언의 지연 보상 보존)

[정산 상태]
  속주 고갈 or 사망 → VP 비교 → 승/패 + 덱 리플레이(내 덱 전체 공개) 화면
```

**입력 명세**: 이동(WASD/스틱) / 상점 커서·구매(마우스 or 방향+확인) / **긴급 재장전(스페이스, 쿨 10초)**: 남은 덱을 즉시 버리고 리셔플 — 유일한 능동 전투 입력. 불발탄 구간을 스킵할지 재장전 무방비를 감수할지의 실시간 판단으로, 폐기된 "손패 플레이 결정"의 보상 장치. [가정 — W2 게이트에서 존치 결정]

# PART D. 조사 — 용량 절감의 계보와 적용

## D-1. 선례에서 추출한 원칙

**① 슈퍼 마리오 브라더스 (NES, 40KB = PRG 32KB + CHR 8KB)**
- 덤불 = 구름의 팔레트 스왑. 8×8 타일 재사용·반전으로 모든 야외 레벨이 한 줌의 타일에서 나옴 — "Reduce, reuse, recycle".
- 레벨은 픽셀도 RLE도 아닌 **커맨드 스트림**("여기 파이프", "여기 계단")으로 저장. 후계작 Micro Mages는 화면당 60바이트 수준.
- → **교훈: 데이터를 저장하지 말고 '생성 명령'을 저장하라. 팔레트는 공짜 콘텐츠다.**

**② .kkrieger (2004, 96KB FPS)**
- 텍스처를 픽셀이 아니라 **창작 히스토리(연산 순서)**로 저장, 실행 시 재생성. 음악·효과음은 V2 신시사이저로 실시간 합성 — WAV/MP3 저장 자체가 없음. 통상 저장 시 200~300MB 상당을 96KB로.
- 코드 모듈화·미사용 제거·kkrunchy 압축(120KB→96KB).
- → **교훈: 에셋은 절차로, 사운드는 신스로. 저장이 아니라 연산으로 콘텐츠를 만든다.**

**③ MUD 제작 전통**
- 그래픽 제로. 방·아이템·몬스터가 전부 **테이블 데이터**, 경험은 시스템(전투식·상호작용 동사)이 생성. 수백 시간 분량 콘텐츠가 수백 KB 텍스트.
- → **교훈: 시스템 × 데이터 = 콘텐츠. 우리 게임의 카드 27종이 정확히 이 구조 — 카드 1장 추가 비용은 코드 수십 바이트.**

**④ 초소형 잼 생태계 (검증된 상한선)**
- js13k(13KB zip)에서 로그라이크·전략 게임이 매년 완성됨. WASM-4 판타지 콘솔은 카트리지 64KB. PICO-8은 32KB 카트로 상업적 히트(Celeste 원형) 배출. [추정 — 세부 수치는 통념 수준]
- → **교훈: 1.44MB는 이 계보에서 보면 '풍족한' 예산이다. 우리의 병목은 바이트가 아니라 개발 시간이다.**

# PART E. 구현 설계서 (기술 명세)

## E-1. 스택 확정

- **언어**: C (C11), MSVC `/O1 /GS- /GL`, CRT 정적 최소화. [대안: Odin — 팀 선호 시]
- **플랫폼 레이어**: Win32 API 직접. 창 생성 + `StretchDIBits` 블릿(기본) / D3D9 텍스처 블릿(수직동기 옵션). 외부 DLL 의존 0.
- **렌더**: 320×240×8bit 인덱스드 프레임버퍼, 소프트웨어 블리터. 근거: 76,800px에 엔티티 1천 개 블릿은 단일 코어로 충분하며, 16색 제약이 곧 아트 디렉션.
- **오디오**: waveOut(호환 최우선) 링버퍼 + 자체 4채널 칩신스.
- **패커 불사용**: 예산 3배 여유이므로 UPX 등 규정 리스크 원천 배제 (kkrunchy의 교훈은 '필요할 때만').
- **엔티티**: 고정 배열 풀 (적 400 / 투사체 600 / 이펙트 256), 32px 그리드 스페이셜 해시 충돌.
- **루프**: 고정 60Hz 시뮬레이션, 프레임 스킵 허용.

## E-2. 모듈 구조

```
main.c        플랫폼(창/입력/타이머/사운드 출력)      ~600 LoC
gfx.c         블리터, 팔레트, 절차 이펙트               ~500
synth.c       4ch 칩신스 + 패턴 시퀀서 + sfxr식 SFX     ~400
font.c        ASCII 8×8 + 한글 자소 조합 렌더           ~300
game.c        상태머신(타이틀/전투/상점/정산)           ~800
deck.c        덱/버림/소각, 틱, 리셔플                  ~300
cards.c       카드 27종 효과 테이블 + 디스패치          ~400
enemies.c     적 5종 AI, 웨이브 스트림, 보스            ~500
rival.c       유령 상인 페이스 로직                     ~100
합계                                                  ~3,900 LoC [추정]
```

## E-3. 사운드 설계

- 채널: 사각파×2(멜로디/베이스) + 삼각파(패드) + 노이즈(드럼·SFX). NES 구성의 오마주.
- 음악: 패턴 시퀀서 — 곡 = (패턴 인덱스 배열 + 패턴당 노트 레코드). 곡당 1~2KB [추정].
- SFX: sfxr 계열 파라메트릭 합성(발사, 불발 '철컥', 코인, 리셔플 '차르륵', 저주). 에셋 0B.
- 발사음은 카드 등급별 음고 차등 → **귀로 덱 상태를 읽게** 한다 (§C-3 가독성 전략의 청각 축).

## E-4. 한글 렌더링

- 자소 조합 방식: 초성 19 + 중성 21 + 종성 27 자소 비트맵(8×16 기준 벌 변형 포함)을 조합 — 데이터 약 10~15KB [추정], 완성형(2,350자 ≈ 75KB) 대비 1/5 이하.
- 국산 DOS 게임·PC통신 시대의 실제 기법 → 공모전(하이텔 오마주) 정서와 이중 부합.
- 리스크 폴백: 구현 지연 시 UI 영문 + 타이틀만 한글 이미지.
