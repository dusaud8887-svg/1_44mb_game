## 1. 원작 핵심 재미 분해

### 1-1. 도미니언 (main) — 무엇이 재미인가

| 재미 요소 | 본질 |
|---|---|
| **엔진 빌딩** | 카드가 카드를 부르는 연쇄(+카드/+액션)를 설계하는 쾌감 |
| **덱 속도(velocity)** | 덱이 얇고 순환이 빠를수록 강함. 정화(Chapel)의 카타르시스 |
| **기회비용** | 턴당 구매 1회. 모든 구매가 다른 구매의 포기 |
| **승점 오염** | 이기려면 사야 하는 승점 카드가 덱을 망가뜨리는 **핵심 딜레마** |
| **킹덤 랜덤** | 매 판 25종 중 10종 공급 → 조합적 다양성, 콘텐츠가 아니라 조합이 리플레이성 |

### 1-2. 뱀파이어 서바이버 (sub) — 무엇이 재미인가

| 재미 요소 | 본질 |
|---|---|
| **파워 판타지 곡선** | 콩알탄 → 화면 절멸까지의 지수적 성장을 15분에 압축 |
| **저입력 고자극** | 이동만 하면 됨. 뇌는 빌드 판단에만 씀 |
| **레벨업 드래프트** | 3택1 — 사실상 **초경량 덱빌딩이 이미 내장**되어 있음 |
| **군중 압박** | 포위→돌파의 공간 긴장 |
| **한 판 더** | 짧은 런 + 언락 메타 |

### 1-3. 결합 논리 — 왜 이 둘인가

뱀서의 레벨업 3택1은 "선택지만 있는 퇴화된 덱빌딩"이다. 여기에 도미니언을 이식하면 뱀서에 **없던 것**이 생긴다:

1. **덱 순환이 실시간 발사 리듬이 된다** — 빌드가 스탯 목록이 아니라 *돌아가는 기계*가 됨
2. **승점 오염이 DPS 저하로 체감된다** — "언제 그린으로 전환하나"라는 도미니언 최고의 질문이 실시간 생존 도박이 됨
3. **정화 = 연사속도** — 덱 슬림화가 즉각적 화력 상승으로 손에 느껴짐
4. **적이 내 덱을 오염시킨다** — 도미니언의 어택 카드(저주 주입)를 적 몹의 역할로 전치
5. **킹덤 랜덤 10종** — 에셋 추가 없이 런 다양성 확보 (1.44MB에 최적: **다양성이 바이트가 아니라 조합에서 나옴**)

**선행 사례** (설계 참조): One Step From Eden(실시간 액션+덱빌딩 — 순환 덱의 실시간화 검증됨), Loop Hero(자동전투+빌드 배치), Peglin(이종 매커니즘에 덱빌딩 이식), 20 Minutes Till Dawn(뱀서 라이트 변주). "뱀서×정통 덱 순환(리셔플·오염·정화)" 조합은 검증된 인접 사례들 사이의 빈 자리다. [추정 — 출시작 전수조사는 아님, 스팀 검색으로 직접적 동일 컨셉 미발견]

## 2. 게임 컨셉

### 2-1. 개요

- **장르**: 실시간 덱빌딩 서바이버 (탑다운, 싱글, 1런 10~12분)
- **조작**: 이동(WASD/패드) + 상점에서 구매 선택. 발사는 전자동
- **비주얼**: 320×240 소프트웨어 렌더 업스케일, 16색 팔레트, DOS 시절 한국 PC게임 미감 — **하이텔 게제동 오마주라는 공모전 정서에 정면으로 부합**
- **가제**: RESHUFFLE (국문 부제: 재장전 서바이버) [가정 — 네이밍 후보 추가 필요]

### 2-2. 코어 루프

```
[전투(실시간)]                          [상점(시간 90% 감속, 8초)]
덱 상단 카드가 0.7초마다 자동 발동  ←──  30초 주기 or 웨이브 클리어 시
  재화 카드 → 코인 적립 + 약한 탄          공급처 10더미 중 구매 1회(기본)
  액션 카드 → 무기/버프 발동               구매 카드는 버림더미로
  승점/저주 → 불발 (딜레이만 소모)         → 다음 리셔플부터 등장 (도미니언의 지연 보상)
덱 소진 → 리셔플(재장전 0.8초 무방비)
적 처치 → 코인 젬 드랍
```

- **덱 = 탄창 UI**: 화면 하단에 벨트로 다음 5장 노출 → 예측 가능성·가독성 확보
- **시작 덱**: 콩알탄(구리) ×7 + 고철(사유지, 1VP 불발탄) ×3 — 도미니언 그대로
- **종료**: 12분 생존 시 클리어, 점수 = 덱 내 총 VP. 사망 시 VP 50%만 인정
- **조기 승리**: 속주(6코인, 8장 한정) 전량 매입 시 즉시 승리 + 보너스 — 그리드 러시 빌드 허용

### 2-3. 핵심 딜레마 (이 게임의 존재 이유)

> **"승점을 사는 순간 내 총이 약해진다."**

VP 카드는 순환 시 불발탄. 점수 욕심 = 실시간 DPS 손실 = 죽음 리스크. 도미니언에서 턴으로 추상화됐던 긴장이 몸으로 느껴지는 것이 이 게임의 유니크 셀링 포인트.

## 3. 재미 관점 리스크 — 스스로에 대한 비판

기획 단계에서 이 컨셉이 죽을 수 있는 지점들:

1. **결정 밀도 손실 (최대 리스크)**. 도미니언 재미의 절반은 "손패를 어떤 순서로 낼까"인데 자동 발사가 이를 제거한다. 남는 결정은 구매뿐. → 완화: 구매를 도미니언처럼 희소하게(기본 1회) 유지해 결정 하나하나의 무게를 키움 + 지하실/예배당 등 "순환에 개입하는" 카드로 미시 결정 일부 복원. **그래도 부족하면**: 스페이스바 = 덱 상단 1장 홀드/스킵 (쿨다운 3초) 같은 단일 능동 입력 추가 검토. [가정 — 프로토타입 검증 필수]
2. **인지 과부하**. 탄막 피하면서 상점을 읽을 수 없다. → 상점 중 시간 90% 감속은 타협이 아니라 필수. 뱀서도 레벨업 시 완전 정지였음.
3. **순환이 안 느껴질 위험**. 덱이 내부 수치로만 돌면 그냥 랜덤 총. → 하단 탄창 벨트 UI + 불발 시 "철컥" 사운드 + 리셔플 슬로모션 연출. **덱을 보이게 만드는 것이 이 게임 UX의 전부다.**
4. **재장전 무방비가 재미인가 스트레스인가**. → 0.8초는 초기값, 덱 크기 무관 고정. 뚱덱 페널티는 불발탄 비율로만. [가정]
5. **12분 안에 도미니언 경제가 돌아가는가**. 상점 주기 30초면 런당 구매 ~24회 — 도미니언 1판 구매 횟수(15~20)와 유사해 성립 가능. [추정]

**검증 게이트**: 2주차 종료 시점, 회색 박스 + 기본카드 7종만으로 "불발탄 사고 싶어지는가/정화가 짜릿한가"를 플레이테스트. 아니라고 판단되면 이 컨셉을 버리고 뱀서 순정 라이트로 피벗한다. 매몰비용 상한 2주.

## 4. 프로덕트 관점

1. **심사 적합도**: 완성(스코프 최소화된 단일 스테이지·5적·16카드) → 용량(§5에서 3배 여유 확보) → 재미(장르 결합의 신선함 + 뱀서 검증 루프). 3개 기준 모두 정면 대응.
2. **행사 정서 적합도**: 주최가 하이텔 게제동을 오마주 → DOS 팔레트·조합형 한글 비트맵 폰트·삑삑이 사운드는 장식이 아니라 **심사자·관객 정서 공략**. 오프라인 아케이드 전시 이력 고려 시 "옆에서 봐도 뭔지 아는" 화면 밀도 중요 — 뱀서류는 관전성이 검증됨.
3. **차별화**: 1.44MB 잼 출품작 대부분은 아케이드 단일 매커니즘으로 수렴할 것 [추정]. 시스템 결합형 출품은 "재미" 항목에서 변별력.
4. **IP 리스크**: 매커니즘은 저작권 보호 대상 아님. 단 카드명·아트·"Dominion" 명칭 직접 사용 금지, 트레이드 드레스(카드 프레임 디자인) 모방 회피. 뱀서 쪽도 캐슬바니아풍 스프라이트 회피 — 어차피 절차 생성 도형 위주라 자연 회피됨.
5. **자산화**: 공모전 후 이 프로토타입은 확장 가능한 컨셉 검증물(스팀 데모급 씨앗). 단 공모전 기간 중엔 고려 자체를 스코프에서 제외.

## 5. 1.44MB 구현 관점

### 5-1. 엔진/스택 선정

| 선택지 | 판정 | 근거 |
|---|---|---|
| Unity / Godot / Unreal | ❌ | 런타임 수십 MB, 규정상 런타임 포함 |
| C# (MonoGame 등) | ❌ | .NET 런타임 포함 시 초과. self-contained 최소도 수십 MB |
| Love2D | ❌ | 런타임 ~4MB+ [추정] |
| SDL2 동적 링크 | ❌ | SDL2.dll 단독 ~1.5–2MB [추정] |
| raylib 정적 링크 | ⚠️ | -Os·strip 시 700KB–1.2MB [추정] — 가능하나 예산 절반 이상 소모 |
| **C/C++/Odin/Zig + WinAPI + 소프트웨어 렌더** | ✅ **채택** | 실행파일 100–300KB [추정]. 320×240 8bit 프레임버퍼를 GDI StretchDIBits 또는 D3D9 텍스처 블릿 |
| Rust + minifb | ✅ 대안 | 유사 크기, 팀 숙련도에 따라 |

**소프트웨어 렌더가 약점이 아닌 이유**: 320×240 = 76,800픽셀. 뱀서식 엔티티 500개 스프라이트 블릿은 현대 CPU 단일 코어로도 압도적 여유. 팔레트 렌더는 곧 미감(16색)과 직결 — 제약이 스타일이 된다.

### 5-3. 기술 리스크

1. **한글 조합형 렌더링 공수**: 벌 체계 구현 1–2일 [추정]. 리스크 시 폴백 = 영문 UI + 한글은 타이틀 이미지만.
2. **UPX 규정 해석**: §0 확인필요. 어차피 예산 3배 여유라 **패커 불사용을 기본안**으로 — 규정 리스크 원천 차단.
3. **크로스 PC 호환**: GDI 폴백 유지 시 Win7~11 전 범위 안전. 전시장 구형 PC 가능성 대비.
4. **저장(메타 진행)**: 스코프 아웃. 단일 런 완결 구조 — 완성이 1순위 심사기준이므로.
