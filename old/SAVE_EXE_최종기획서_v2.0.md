## 0-2. 심사기준 역산 전략

**완성이 1순위, 재미는 3순위.** 즉 "야심찬 미완성"이 최악이다. 본 기획의 모든 스코프 결정은 이 순서를 따른다:
- 스코프는 완성 가능 최소치 (단일 스테이지, 적 5종, 카드 27종, 메타 진행 없음)
- 재미는 콘텐츠 물량이 아니라 **시스템 결합(덱빌딩×서바이버)과 조합 다양성**에서 조달
- 용량은 3배 이상 여유를 확보해 규정 리스크 원천 차단 (제9장)
- 행사 정서(하이텔·플로피·PC통신 노스탤지어)를 컨셉의 뼈대로 삼아 심사자 공략 (제3장)

## 0-3. 주최측 확인 필요 사항 [확인필요]

1. UPX 등 실행파일 자체 압축의 "압축 해제 후" 해석 → **본 기획은 패커 불사용이 기본안이므로 무관하나 확인 권장**
2. OS 기본 탑재 시스템 DLL(kernel32, user32, gdi32, winmm 등)의 용량 포함 여부 → 상식적으로 미포함 [가정]
3. 대상 플랫폼 명시 여부 → Windows x64 단일 exe [가정]

# 제1장. 조사 — 도미니언: 재미의 해부

## 1-1. 전략 생태계 (커뮤니티 정설)

도미니언의 전략은 5개 원형으로 정리되며, **모든 전략의 출발점은 "빅머니를 이기는 것"**이다. 게임 시작 시 공개되는 왕국 카드 10종을 보고 이길 전략을 구상할 수 있느냐가 중수와 초보를 가른다.

| 전략 | 본질 | 핵심 긴장 |
|---|---|---|
| **빅머니** | 재화만 사서 속주 직행. 단순·강력한 베이스라인 | 초보도 강함 → 모든 덱의 가상 적수 |
| **엔진** | 액션추가(마을) + 드로워(대장간) + **페이로드**의 3요소. 덱 전체를 드로우해 폭발적 구매력 | 완성 전까지 약하고 패말림 심함. 감내와 타이밍의 게임 |
| **슬로그** | 정원 등 "덱이 불어날수록 점수" 카드로 게임을 끌며 승점 비대화 | 압축이 정설인 게임에서의 역발상 |
| **러시** | 공급처 더미를 빠르게 비워 조기 종료, 점수 우위 시점에 게임을 끝냄 | 종료 타이밍 자체가 무기 |
| **콤보** | 특정 카드 상호작용으로 판을 접수 (예: 예배당 극한 압축 후 옥좌-마녀) | 킹덤 읽기 능력의 정점 |

## 1-2. 두뇌싸움의 실체

1. **킹덤 읽기 (판 시작 30초)**: 10종 조합에서 성립 가능한 아키타입과 속도를 추정하는, 매 판 다른 퍼즐.
2. **그리닝 타이밍**: 승점 전환이 빠르면 덱이 죽고 늦으면 기회가 사라진다. 전환점 판단이 도미니언 재미의 심장.
3. **압축의 카타르시스**: 예배당(2코스트)은 커뮤니티 공인 최강급 — 숙련자는 첫 구매로 주저 없이 집는다. "버림으로써 강해진다"는 직관 역행의 쾌감.
4. **오염 전쟁**: 마녀의 저주 살포는 상대 덱을 물리적으로 망가뜨린다. 저주·폐허가 굴러들어오면 엔진덱은 꼬여서 돌지 않는다.
5. **파일 컨트롤**: 더미 고갈이 곧 게임 시계. 러시는 시계를 당기고 슬로그는 늦춘다.

## 1-3. 이식 판정표

| 도미니언 요소 | 이식 | 본 게임에서의 방식 |
|---|---|---|
| 덱 순환·리셔플 | ✅ 원형 유지 | 실시간 자동 발사 벨트 (덱=탄창) |
| 승점 오염 | ✅ 원형 유지 | VP(추억 파일) = 불발탄 → DPS 손실로 체감 |
| 압축(폐기) | ✅ 원형 유지 | 조각모음 = 순환 밀도 = 화력 |
| 킹덤 랜덤 10종 | ✅ 원형 유지 | "오늘의 자료실" 10종 공개 → 킹덤 읽기 재현 |
| 그리닝 타이밍 | ✅ 재발명 | 포맷의 시간 역산 딜레마 (제4장) |
| 러시(파일 고갈) | ✅ 재발명 | 앨범.ZIP 전량 백업 시 조기 개전 |
| 마녀(저주 살포) | ✅ 역전 이식 | 적 랜섬웨어가 **나에게** 배드 섹터 주입 |
| 손패 플레이 순서 결정 | ❌ 폐기 | 실시간 자동화와 양립 불가 → 긴급 재장전·버퍼정렬·조각모음이 능동 결정을 부분 보상 |
| 대인 심리전 | △ 대체 | 포맷 시계 + 랜섬웨어 압박으로 치환. (v1.0의 '유령 라이벌 AI'는 보이지도 싸울 수도 없어 체감 실패로 폐기) |

# 제2장. 조사 — 뱀서류: 유저는 실제로 어떻게 노는가

## 2-1. 성공 인자 (VS·홀로큐어 커뮤니티 관찰)

VS가 스트리머·시청자 생태계 전체에 유행하고 그 관심이 홀로큐어로 그대로 이동한 과정에서 커뮤니티가 반복적으로 꼽는 인자:

1. **단순·직관 구조로 익히기 쉬움** — 조작 진입장벽 제로, 플레이하며 떠들 인지 여유
2. **성장 + 조합의 재미가 확실** — 캐릭터 성장과 무기 조합(진화)이 한 판 안에서 완결
3. **적절한 런 길이 + 로그라이트** — 매 판 다른 결과, 반복해도 안 질림
4. **관전성** — 옆에서 봐도 뭐가 일어나는지 보임. 장르 문법 준수 자체가 UX (홀로큐어가 "부술 수 있는 오브젝트" 기대를 수용한 사례)
5. **캐릭터 개성** — 홀로큐어의 차별점. 유저는 티어표를 만들고 자기 스타일의 캐릭터를 찾는다
6. **조합 지식의 콘텐츠화** — 진화 레시피·시너지를 외우고 공유하는 메타 활동

## 2-2. 플레이 행동 패턴 (설계 입력값)

- **초반 3분**: 약한 화력으로 카이팅하며 첫 파워스파이크 조립 — 가장 죽기 쉽고 가장 집중하는 구간
- **중반**: 빌드 방향 확정, 선택은 사실상 빌드 맞춤 드래프트
- **후반**: 화면 절멸 파워 판타지 + 방치성, 긴장은 보스가 담당
- **장르의 심장은 파워 판타지 곡선** — 콩알탄에서 화면 절멸까지의 지수 성장을 짧은 런에 압축

## 2-3. 이식 판정표

| 뱀서 요소 | 이식 | 방식 |
|---|---|---|

# 제3장. 컨셉

## 3-1. 로그라인과 본질적 경험

**로그라인**: 자정에 포맷이 예약된 1997년의 486 PC. 상주 프로그램 '지킴이.EXE'가 되어, 바이러스 물결을 뚫고 주인이 남긴 추억 파일들을 A드라이브 디스켓에 백업한다. 백업한 파일은 실행 큐를 막는 짐 — 그러나 포맷이 시작되는 순간, 부팅 디스크가 발화하며 저장된 추억 하나하나가 빛의 탄환이 되어 터진다.

**본질적 경험** (The Art of Game Design, '본질적 경험' 렌즈): 이 게임이 주려는 단 하나의 경험은 **"짐이 보물로 반전되는 순간"**이다. 8분간 '철컥'거리던 불발탄이 최후의 90초에 화면을 불태우는 반전. 모든 설계 결정은 이 경험 기준으로 판정한다.

**테마 통일** ('통일성' 렌즈): 테마 = **저장(SAVE)**. 특히 **기술 제약(1.44MB)이 픽션 그 자체** — "추억을 1.44MB에 담아라"는 이 게임의 이야기이자 이 게임 파일의 물리적 현실이다. 하이텔 오마주 공모전에서 심사자가 이 재귀를 발견하는 순간까지 설계에 포함한다.

## 3-2. 아이덴티티

- **제목**: SAVE.EXE (후보: A:\, 마지막 디스켓)
- **장르**: 실시간 덱빌딩 서바이버 / 싱글 / 1런 약 9.5분
- **플랫폼**: Windows x64 단일 exe [가정] / 320×240 내부 렌더, 16색 팔레트, 정수배 업스케일
- **비주얼 톤**: DOS 시절 국산 PC게임·PC통신 미감 (조합형 한글, 회로 기판 맵, 게시판 양식 UI)
- **한 줄 경험 목표**: "8분간 참아온 불발탄이 90초의 불꽃놀이가 되는 반전을 몸으로 느끼게 한다"

# 제4장. 게임 디자인 명세 — 승리 구조와 코어 루프

## 4-1. 승리 구조: 포맷의 시간

**주 조건 — 8:00 포맷 개시 → 90초 생존**
- 8:00에 시스템 포맷 시작. **덱의 모든 추억 파일(VP)이 성광탄으로 반전**된다:
  - 메모.TXT(1VP) = 소폭발 (20dmg, 반경 16px)
  - 사진.JPG(3VP) = 중폭발 (45dmg, 반경 32px)
  - 앨범.ZIP(6VP) = 화면 절멸탄 (전 화면 60dmg + 1초 정지 연출)

8:00 등장하는 집행자. 악의 없는, 직무에 슬픈 관료 (동방식 보스 원형). 등장 3줄: "예약된 작업입니다. 원망은 예약한 분께." / "1분 30초만. 그거면 돼." / "…카운트는 시작됐습니다." 클리어 시 1줄: "…빈 디스크는, 처음이네요." — 그녀가 포맷을 완수하지 못한 최초의 밤, 승리의 서사화.
*여백: 누가 포맷을 예약했는가.*

**④ 씨크.WORM — 랜섬웨어 네임드 (6:00 보스)**
추억을 암호화해 "자기 안에 보존"하려는 바이러스 소녀 — **지킴이와 동일한 동기의 뒤틀린 거울상.** "지워질 바엔 내가 전부 삼킬 거야." 격파 시 "…네 방식으로, 지켜봐" + 배드 섹터 전체 소각(그녀가 암호화를 푼다 — 보상과 대사의 정합).
*여백: 그녀의 기원. 악성코드인가, 실패한 백업 프로그램인가.*

**⑤ 주인 — 등장하지 않는 주인공 (부재로 설계)**
메모.TXT 백업마다 실제 내용 1줄 표시 (풀 30줄, 시간순 셔플): "3.15 오락실에서 100원 잃음", "기말 망함. 컴퓨터 압수", "걔한테 편지 썼다. 못 보냈다", "996번째 접속. 등업!" — **여러 런을 돌아야 주인의 10년이 퍼즐로 맞춰진다. 반복 플레이 = 스토리 수집** (최소 바이트, 최대 변주). 사진.JPG는 해석 불가능한 8×8 썸네일 12종. 엔딩의 수신인은 깨진 텍스트: "소중한 ▒▒에게" — 여백에 박는 마지막 못.

## 6-2. 2차 창작 여백 최종 점검 (동방 공식 대조)

# 제9장. 구현 설계서

## 9-1. 용량 절감의 계보 — 조사와 적용

**① 슈퍼 마리오 브라더스 (NES, 40KB = PRG 32KB + CHR 8KB)**: 덤불 = 구름의 팔레트 스왑. 8×8 타일 재사용·반전으로 전 야외 레벨 구성. 레벨은 픽셀도 RLE도 아닌 **커맨드 스트림**("여기 파이프, 여기 계단") — 후계작 Micro Mages는 화면당 약 60바이트. → **데이터가 아니라 생성 명령을 저장하라. 팔레트는 공짜 콘텐츠다.**

**② .kkrieger (2004, 96KB FPS)**: 텍스처를 픽셀이 아닌 **창작 히스토리(연산 순서)**로 저장해 실행 시 재생성, 음악·효과음은 V2 신시사이저 실시간 합성(오디오 에셋 0), kkrunchy 자체 압축. 통상 저장 시 200~300MB 상당을 96KB로. → **에셋은 절차로, 사운드는 신스로.**

**③ MUD 제작 전통**: 그래픽 0, 콘텐츠 전부가 테이블 데이터, 경험은 시스템이 생성. → **시스템 × 데이터 = 콘텐츠. 본작의 카드 27종·대사 풀이 정확히 이 구조 — 콘텐츠 추가 한계비용 ≈ 0.**

**④ 초소형 잼 생태계**: js13k(13KB), WASM-4(64KB 카트리지), PICO-8(32KB) 등에서 전략·로그라이크가 매년 완성된다 [추정 — 통념 수준]. → **1.44MB는 이 계보에서 풍족한 예산. 병목은 바이트가 아니라 개발 시간이다.**

**적용 매핑**: 적 5종 × 팔레트 4벌 = 시각 20종 / 스프라이트 좌우 반전 런타임 처리 / 웨이브 = 4바이트 레코드 스트림 / 오디오 에셋 0 (칩신스) / 바닥·이펙트 절차 생성 / 카드·적·대사 전부 상수 테이블 / 조합형 한글(국산 DOS 게임 전통 = 시대 고증 그 자체).
